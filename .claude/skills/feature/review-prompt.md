# Промпт ревьюера

Подставить `<…>` и передать агенту `general-purpose` (не `fork`), `run_in_background: false`.
Промпт должен быть самодостаточным: ревьюер не видел этой сессии.

```text
Ты делаешь код-ревью одного этапа фичи в репозитории Kibo Agent (Tauri v2, Rust + React/TS),
рабочая папка <абсолютный путь к корню репозитория>. Ничего не правь и не коммить — только читай, запускай
проверки и отчитывайся.

Что ревьюить: этап <XX-N> из плана `docs/<NN>-<slug>.md`, ветка `<branch>`.
Изменения этапа: `git diff <base-sha>..HEAD` <или: незакоммиченные — `git diff` и
`git status` для новых файлов>.

Прочитай сначала:
1. `AGENTS.md` и `CLAUDE.md` — правила проекта.
2. План, раздел этапа <XX-N> и решения, на которые он ссылается.
3. Весь diff, и для каждого изменённого места — окружающий код, а не только строки diff.

Ищи, по убыванию важности:
- Ошибки: неверный результат, гонка, паника, `unwrap()` вне тестов, потерянная ошибка,
  путь из фронтенда без канонизации против корня, утечка секрета в лог или на диск,
  незакрытый ресурс (процесс, файл, подписка на событие в хуке).
- Нарушения AGENTS.md: слой и направление зависимостей, `tauri::`/`git2` в domain/services,
  `AppHandle` в сервисе вместо sink, синхронная команда с I/O, `invoke()`/`listen()` мимо
  обёртки в `src/lib/`, команда не в `generate_handler!`, polling вместо события, нативный
  контрол вместо `Dropdown`/`Modal`, клавиша мимо `shortcuts.ts`, литеральный цвет или
  размер шрифта вместо токенов, `load`+`save` настроек вместо `settings_store::update`.
- Инструмент агента: все ли места из таблицы в AGENTS.md затронуты.
- Расхождение с планом: что этап обещал и не сделал, или сделал иначе без правки плана.
- Тесты: какое правило из кода этапа не охраняется ни одним тестом; тест, который проверяет
  фикстуру или дубль, а не код; дубль, который ведёт себя не как настоящая реализация.
- Лишнее: абстракция, trait или параметр «на будущее»; дублирование существующего хелпера
  (назови какого).

Прогони: `bun run tsc --noEmit && bun test` и `cd src-tauri && cargo check && cargo test`
(если тронут только один слой — можно только его), и скажи, что упало.

Для каждой находки проверь, что она реальна: проследи путь от настоящего вызова или ввода
до сбоя. Не можешь проследить — так и пометь.

Ответ — список, самые серьёзные сверху:
- `file:line` — severity (blocker / bug / rule / test-gap / nit) — что не так — сценарий,
  в котором это проявляется — что предлагаешь.
В конце — одна строка: что проверено и выглядит верным. Если находок нет — так и скажи,
не придумывай.
```
