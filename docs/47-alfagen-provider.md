# AlfaGen: провайдер Альфа-Банка из коробки, с сертификатом в сборке

Статус: **план, предложен 2026-11-01** — вопросы закрыты пользователем 2026-11-01.
AG-1 и AG-2 сделаны 2026-11-01, следующий — AG-3 (живая проверка на шлюзе, нужен ключ).

В форму провайдеров добавляется готовый провайдер **AlfaGen** (внутренний шлюз
`https://alfagen.moscow.alfaintra.net/continue-dev/v1`) — его адрес и протокол
подставляются одним кликом, корневой сертификат Альфа-Банка приходит **вместе со сборкой**
и сразу попадает в доверенные этому провайдеру, а каждый запрос несёт
`User-Agent: Kibo-Agent/{version}`. Пользователю остаётся ввести личный ключ.

Почти вся работа фронтовая: путь «сертификат провайдера → доверенные» в бэкенде уже есть и
проверен ([`infra/http_agent.rs`](../src-tauri/src/infra/http_agent.rs),
[`commands/settings.rs`](../src-tauri/src/commands/settings.rs)). Бэкенд трогается ровно в
одном месте — подстановка версии в заголовок (решение 9).

Кода в документе нет — только решения.

## Что уже есть

- `domain::settings::ProviderConfig` — `id`, `kind` (`openAiCompatible` | `anthropic`),
  `base_url`, `models_url`, `model`, `trusted_cert_pem`, `request_headers`, сэмплинг,
  `context_limit`, `reasoning_effort`, `supports_images`. `trusted_cert_pem` — «CA, которой
  доверять **вместо** публичных корней, для шлюза за корпоративной CA».
- `infra::llm_providers::provider_for` собирает агент через
  `http_agent::build_agent(config.trusted_cert_pem.as_deref())`; `build_agent` ставит свой
  верификатор `Pinned`, который (а) принимает сервер, чей сертификат побайтово равен
  вставленному, (б) иначе проверяет цепочку обычным webpki против вставленных корней.
  `parse_trusted_certs` разбирает **всю** цепочку в PEM, текст вокруг игнорирует.
- `commands::settings::llm_provider_save` разбирает PEM на сохранении: битый сертификат —
  ошибка в форме, а не «провайдер не отвечает» через ход.
- `request_headers` провайдера уже применяются к запросам чата и к списку моделей
  (`openai_compatible::extra_headers`), а значение-заглушка `$uuid` разворачивается в новый
  идентификатор на каждом запросе (`REQUEST_HEADER_VALUE_UUID`, `header_value`).
- `src/components/ProviderSettings.tsx`: вкладка на провайдера, блок «Known providers» из
  `src/lib/providerCatalog.json` (заполняет имя, протокол, base URL), карточка
  «Certificate» (загрузить файл / вставить / снять, показывает число сертификатов).
  `src/lib/providerForm.ts` — чистые помощники (`certificateCount`, `pemFromBytes`,
  `freeName`, `filterBy`). Полей для `requestHeaders` в форме **нет**: они переживают
  сохранение (приходят из `...chosen`), но увидеть и править их нельзя.
- `src/__tests__/ProviderSettings.test.tsx` и `src/__tests__/providerForm.test.ts` — стиль
  тестов формы уже есть.
- **Чего нет.** Пресетов сборка не несёт: `docs/06-port-plan.md` (F-1.12c) — каждый
  провайдер это полное определение из настроек, `base_url` всегда `String`.
  `providerCatalog.json` — не пресеты, а заполнялка формы: он генерируется
  `scripts/update-provider-catalog.py` из models.dev и перезаписывается целиком. Первого
  провайдера ничто не создаёт: `LlmSettings.providers` начинается пустым, `active()` без
  закреплённого — первый в списке.

## Проба (сделана при исследовании, 2026-11-01)

Проверено с этой машины (в корпоративной сети), результаты — основа решений ниже:

| Что | Ответ |
|---|---|
| DNS | `alfagen.moscow.alfaintra.net` → `10.229.72.203` (внутренний адрес) |
| Цепочка TLS | leaf `CN=alfagen.moscow.alfaintra.net`, 2026-06-15…**2028-06-14** ← `Alfa-Bank ST CA Sub1` (CA:TRUE, pathlen:2, 2025-08-07…2035-08-05) ← `Alfa-Bank ST CA Root` (самоподписанный, CA:TRUE, pathlen:3, 2025-08-07…**2045-08-02**). Сервер отдаёт все три |
| Что в файле пользователя (`~/Desktop/files/alfagen-sert.pem`) | ровно корневой, один сертификат; SHA-256 `4211dba6d2c39459…` — тот же, что в цепочке с сервера |
| `curl --cacert <этот корень>` | `verify=0`, TLS проходит — **одного корня достаточно**, промежуточный сервер присылает сам |
| Протокол | `POST /continue-dev/v1/chat/completions` и `GET /continue-dev/v1/models` доходят до приложения и отвечают `{"error":{"message":"Ключ не найден. Пожалуйста, получите новый ключ.","type":"authentication_error"}}` при `Authorization: Bearer …`; без заголовка шлюз отдаёт пустой 401 |
| Что не маршрутизируется | `/continue-dev/v1/messages`, `/embeddings`, `/responses`, `/config`, `/info`, `/health` — пустой 401 даже с Bearer. То есть Anthropic-провода там нет, и эмбеддинги приложение и так считает локально |
| Ключ | личный, в `Authorization: Bearer`; список моделей — `/models` (без ключа не отдаётся) |
| `User-Agent` | по исходникам `ureq` 3.4.2 в локальном кэше: свой `User-Agent` ureq ставит, только если запрос его не несёт (`run.rs`: `if !has_header_ua`), так что заголовок провайдера доедет один, без дубля |

## Решения

### 1. AlfaGen — обычный провайдер на существующем проводе, а не новый `ProviderKind`

Шлюз отвечает OpenAI-совместимо и с Bearer-ключом (проба выше), значит новый вариант
`ProviderKind`, новая ветка в `provider_for` и новый модуль в `infra/llm_providers/` не
нужны: хватает строки `kind: openAiCompatible`. Отвергнуто: отдельный `ProviderKind::AlfaGen`
— он бы ничего не решал, а таблицу мест в `AGENTS.md` (протокол провайдера) раздувал.

### 2. Сертификат — в доверенных **у этого провайдера**, а не глобально

`build_agent` уже настраивает TLS на агент, а не глобально: «a provider that needs its own
certificate trusted gets it without changing what any other provider trusts». Так и
оставляем: `trustedCertPem` провайдера `alfagen` заменяет публичные корни только для него.
Это строже, чем добавить корень Альфа-Банка в общий набор: чужой провайдер с сертификатом
банка не пройдёт проверку случайно.

### 3. В сборку идёт только корневой сертификат

Промежуточный `Sub1` не нужен: сервер присылает его в рукопожатии, и webpki строит цепочку
leaf → Sub1 → root. Отвергнуто: положить в сборку всю цепочку, как её отдаёт
`openssl s_client` (то есть вместе с листовым) — тогда верификатор `Pinned` запомнит и
листовой сертификат, а он умирает **первым** (2028-06-14) и его плановая замена сломала бы
все сборки без обновления приложения. Отвергнуто и «только Sub1»: он сменится (2035) раньше
корня (2045), и корень его всё равно покрывает.

### 4. Сертификат попадает в настройки провайдера текстом, а не по идентификатору сборки

Клик по встроенной строке подставляет в форму и адрес, и PEM; при сохранении он, как и
вставленный руками, ложится в `settings.json` провайдера полем `trustedCertPem` (около 1.9 КБ,
сертификат публичный — не секрет). Почему так: путь сертификата в бэкенде уже сквозной
(форма → `llm_provider_save` → `provider_for` → `build_agent`, и те же три места берут
`trusted_cert_pem` для баланса, веб-поиска и DeepSeek), поэтому новых полей, новой ветки
разрешения и новых отказов не требуется вовсе.

Отвергнуто: поле `builtinCa: Option<String>` в `ProviderConfig`, которое бэкенд разрешает в
`include_str!`-файл сборки `infra/builtin_certs.rs`. Оно надёжнее в одном: пользователь не
может случайно снять сертификат, а ротация корня приезжает обновлением приложения. Цена —
новое поле в домене, разрешение в четырёх местах, отказ на неизвестный id, тесты на двух
слоях ради одного сертификата. Потолок выбранного решения (`ponytail:`-комментарий у
списка встроенных): смена корня Альфа-Банка требует, чтобы пользователь заново выбрал
строку AlfaGen или вставил новый PEM; путь дальше — та самая `builtinCa`-индирекция.
Вернуться к ней стоит, если появится второй внутренний провайдер или сменится CA.

### 5. Встроенные провайдеры — свой файл рядом с генерируемым каталогом

`src/lib/builtinProviders.ts` — рукописный список (сейчас одна строка: `alfagen`, «AlfaGen»,
`openAiCompatible`, адрес выше, PEM из `src/lib/certs/alfa-bank-st-ca-root.pem`,
импортированный через `?raw` — так уже делают промпты в `App.tsx`, и `bun test` этот импорт
понимает). Рядом, а не внутри `providerCatalog.json`: тот перезаписывается скриптом из
models.dev целиком, рукописная строка в нём исчезла бы на первой пересборке.

### 6. Ключ и модели — обычным путём, модель не прошиваем

Ключ AlfaGen личный: пользователь вставляет его в поле API key, оно запечатывается в
хранилище ключей под id `alfagen` (`llm_api_key_save`), как у любого провайдера. Список
моделей появляется кнопкой «Load list» (`/models` с ключом). Модель — **первая из тех, что
отдаёт API** (пустой `model` = «первая из списка», это уже поведение
`llm_session::effective_model`): имена знает только шлюз, а прошитое имя устареет молча и
уведёт пользователя на снятую модель. По той же причине не прошиваем и `contextLimit` —
остаётся умолчание приложения.

### 7. Картинки — «Text only» по умолчанию

Про vision шлюза данных нет (проба не проверяла; `/chat/completions` — да, но поддержку
`image_url` это не доказывает). Пока не проверено — выключено, как у любого нового
провайдера: вместо картинки уходит строка, что она пропущена.

### 8. Первого провайдера сборка не создаёт (решено пользователем)

Строка AlfaGen — предложение в списке «Add», а не запись в `settings.json` при первом
запуске: провайдер без ключа, оказавшись первым, становится активным (`active()` → первый в
списке), и первый же ход падает с «no API key is stored». Пользователь сам выбирает его
при добавлении.

### 9. `User-Agent: Kibo-Agent/{version}` — заглушкой `$appVersion`, а не прошитой версией

Шлюз хочет видеть клиента строкой `Kibo-Agent/{version}`. Заголовок кладём во встроенную
строку — `requestHeaders: { "User-Agent": "Kibo-Agent/$appVersion" }`, — а `$appVersion`
разворачивается в версию сборки на каждом запросе, рядом с уже работающим `$uuid`
(`openai_compatible::header_value`). Версия — `env!("CARGO_PKG_VERSION")`
(`src-tauri/Cargo.toml`, сейчас `0.10.0`; совпадает с `package.json` и `tauri.conf.json`);
так уже делает MCP-клиент (`infra/mcp_rmcp.rs`).

Почему заглушка, а не готовое значение: в настройках лежит `Kibo-Agent/$appVersion`, и
после обновления приложения заголовок сам говорит новую версию. Прошитое при клике
`Kibo-Agent/0.10.0` осталось бы в `settings.json` навсегда и врало бы шлюзу — а по версии
он, судя по формату, и различает клиентов. Отвергнуто и «свой `User-Agent` всем провайдерам
сразу»: это меняет то, что видит каждый внешний провайдер, — отдельное решение, не часть
этой фичи.

Замена — подстрокой (`Kibo-Agent/$appVersion`), а не целым значением, как у `$uuid`: префикс
`Kibo-Agent/` осмысленно держать в настройках, а не в коде. `header_value` общий с
Anthropic-проводом (`anthropic.rs` его импортирует), так что заглушка работает на обоих.

## Слои

- `src/lib/certs/alfa-bank-st-ca-root.pem` — тот самый корневой сертификат, как его дал
  пользователь (один блок `BEGIN CERTIFICATE`).
- `src/lib/builtinProviders.ts` — чистые данные: тип строки (`CatalogEntry` + `certPem` +
  `requestHeaders` + признак «встроенный») и список; помощник «встроенные + каталог» для формы.
- `src/components/ProviderSettings.tsx` — блок «Known providers» показывает встроенные
  строки, `onPick` заполняет ещё и `cert` и заголовки; карточка «Certificate» объясняет, что
  сертификат пришёл со сборкой. Заголовки проходят через черновик формы
  (`Draft`/`fromConfig`/`config()`): полей для них нет, а `config()` собирает объект заново —
  без этого сохранение любой другой правки стёрло бы `User-Agent`.
- `src-tauri/src/infra/llm_providers/openai_compatible.rs` — `header_value` и константа
  заглушки версии; тесты рядом, в `mod tests` модуля.
- `src/__tests__/ProviderSettings.test.tsx`, `src/__tests__/providerForm.test.ts`.

Ни `domain/`, ни `services/`, ни `commands/`, ни capability: новых команд, событий и полей
настроек нет.

## Нарезка

Каждый этап — отдельный коммит с тестами и мутационной проверкой
([11-mutation-testing.md](11-mutation-testing.md)).

**AG-1. AlfaGen в форме, сертификат из сборки — сделано** (2026-11-01). Файл сертификата
`src/lib/certs/alfa-bank-st-ca-root.pem`, `src/lib/builtinProviders.ts` (строка AlfaGen +
`KNOWN_PROVIDERS` + `builtinSourceOf`), встроенные строки в «Known providers» над каталогом
с пометкой «built in», заполнение `baseUrl`/`kind`/`trustedCertPem` по клику (сертификат
принадлежит выбранной строке, а не остаётся от прошлой), число в заголовке считает
встроенные, карточка Certificate говорит «the one AlfaGen comes with, trusted instead of the
public roots». Тесты: адрес и протокол по клику, ровно один сертификат в сохранённом
`trustedCertPem`, строка видна без поиска и находится по «alfa», сертификат не едет за
следующей строкой каталога, PEM в сборке — один блок `BEGIN CERTIFICATE`, встроенные идут
перед каталогом. Проверки: `bun run tsc --noEmit` — чисто, `bun test` — 1245 тестов, все
зелёные.

Мутационная проверка: 10 мутантов, все пойманы. Выкинутый из `onPick` сертификат,
`kind: "anthropic"`, адрес без `/continue-dev/v1`, число без встроенных, «свой сертификат
не узнан» (`!==` вместо `===`), строка без PEM, `KNOWN_PROVIDERS` без встроенных,
выключенная ветка `source` — все уронили ожидаемые тесты. Мутант «сертификат остаётся от
предыдущей строки» в форме `cert: draft.cert` поймал не тот тест (он заодно не приносит
сертификат новой строке, это ловит первый тест), поэтому он переделан в
`cert: entry.trustedCertPem ?? draft.cert` — и тогда его ловит ровно «a certificate does
not follow the next pick». Не проверено руками в окне.

**AG-2. `User-Agent: Kibo-Agent/{version}` — сделано** (2026-11-01). Заглушка
`$appVersion` (`REQUEST_HEADER_VALUE_VERSION`) в `header_value`: версия подставляется
**подстрокой**, потому что значение — `Kibo-Agent/$appVersion` с именем клиента впереди; а
`$uuid` оставлен как был — целым значением, и старый тест на него не тронут. Версия —
`env!("CARGO_PKG_VERSION")` сборки. `requestHeaders` добавлены встроенной строке AlfaGen,
черновик формы (`BLANK`/`fromConfig`/`config()`) проносит их в сохранение и отдаёт их той
строке, которую выбрали.

Тесты: `header_value("Kibo-Agent/$appVersion")` даёт `Kibo-Agent/{CARGO_PKG_VERSION}` и не
равен литералу; запрос несёт `user-agent: Kibo-Agent/0.10.0` и в чате, и в `/models` (через
`serve_capturing`); `$uuid` по-прежнему разворачивается в новый id, а `"static"` не
меняется; при сохранении формы заголовки встроенной строки доезжают в `requestHeaders`,
следующая строка каталога их не наследует, а правка другого поля у сохранённого провайдера
их не стирает. Проверки: `bun run tsc --noEmit` чисто, `bun test` — 1248 тестов, `cargo test`
— 2268, все зелёные.

Мутационная проверка: 9 мутантов, все пойманы. Rust: заглушка не разворачивается; остаётся
только номер без `Kibo-Agent/`; `$uuid` не разворачивается (`if false`); заголовки не едут
в запрос списка моделей. Фронт: `requestHeaders` не сохраняются; `fromConfig` не читает
сохранённые; строка каталога не приносит свои; заголовки остаются от предыдущей строки;
версия застыла в настройках (`Kibo-Agent/0.10.0` в самой строке) — этот поймал тест на
placeholder. Не проверено: живой шлюз (AG-3) и окно.

**Ревью AG-1 и AG-2** (субагент с чистым контекстом, 2026-11-01): две дыры в тестах и четыре
замечания, все приняты и исправлены. Что добавлено: счёт вхождений `user-agent:` в
захваченном запросе — не только наличие, иначе дубль (свой заголовок плюс `ureq`-шный после
обновления зависимости) прошёл бы молча; Rust-тест `the_bundled_certificate_is_the_banks_root`
— встроенный PEM разбирается тем же `parse_trusted_certs`, что и вставленный руками, и
закреплён хешем (проверено подменой файла на другой валидный CA: тест падает); доккомментарий
`request_headers` в `domain/settings.rs` — оба placeholder'а и разные правила (`$uuid` целым
значением, `$appVersion` — подстрокой); комментарий в `builtinProviders.ts` о том, что
написание placeholder'а — контракт с бэкендом, и неизвестный placeholder уходит буквально;
метка «built in» — нейтральный `.model-note` вместо акцентной пилюли, которая читалась как
«выбрано»; AG-4 больше не добавляет строку в `docs/README.md` второй раз. Отклонённых
находок нет. Проверки после исправлений: `tsc` чисто, `bun test` — 1248, `cargo test` — 2269.

**AG-3. Живая проверка на шлюзе — если есть ключ.** `Load list` на реальном AlfaGen с
личным ключом: список моделей приходит, первый ход в чате проходит, модель — первая из
списка, ошибка без ключа показывается текстом шлюза, `User-Agent` доезжает в том виде,
какого ждёт шлюз (и проверяется, не отвечает ли он иначе без него). Если ключа нет — этап
помечается «не проверено» и остаётся в плане; заодно проверяется, видит ли модель картинки
(тогда решение 7 можно перевернуть).

**AG-4. Документы.** Строка в `CHANGELOG.md` (что пользователь теперь может) и абзац в
`docs/08-data-policy.md` (AlfaGen — внутренний шлюз банка: строку, корневой сертификат и
`User-Agent: Kibo-Agent/{версия}` несёт сборка, сертификат публичный, ключ личный и
печатается пользователем, данные не покидают контур банка). Строка в `docs/README.md` уже
есть — она ведётся с AG-1.

## Вне плана

- `builtinCa`-индирекция в домене — до смены корня или второго внутреннего провайдера
  (решение 4).
- `User-Agent: Kibo-Agent/{version}` для **всех** провайдеров — меняет то, что видит каждый
  внешний провайдер; отдельное решение (решение 9).
- UI для `requestHeaders` — в форме их нет и по-прежнему не будет: встроенной строке хватает
  черновика. Появится, если понадобится править трассировочные заголовки руками.
- Автосоздание провайдера при первом запуске — решено «нет» (решение 8).
- Общий механизм пресетов провайдеров — им пришлось бы нести и сертификаты; пока одна
  строка, механизм был бы больше строки.
