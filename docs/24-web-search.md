# Поиск в интернете: инструмент `webSearch`

План, W-1 сделан. Решение принято пользователем 2026-09-30: один встроенный
инструмент `webSearch` на Tavily для режима Chat; в папке поиск остаётся за MCP (уточнено
2026-09-30: не тратить кредиты Tavily на агента). Документ описывает, что
уже есть, какие решения предлагаются и почему, что из данных уходит наружу, нарезку
W-1…W-4 и открытые вопросы.

## Зачем

Модель знает мир на дату своего обучения. Версия библиотеки, changelog, текст ошибки из
свежего релиза, известная проблема чарта — ничего этого она не найдёт ни в папке, ни в
кластере. Сейчас у неё два пути, и оба плохие:

- **Агент** может запустить `curl` через `runCommand`. Сетевая команда спрашивает
  каждый раз, даже при Always allow (`domain::command_risk`), а в ответ приходит сырой
  HTML поисковика.
- **Чат** не может ничего. У роли Assistant инструментов нет вообще (`ChatRole::tools()`
  → `&[]`), у Kubernetes только `kube*`. MCP чату не передаётся:
  `services/plain_chat.rs` отдаёт ходу `McpTools::default()`.

## Почему не MCP

Tavily и Brave публикуют свои MCP-серверы, и в режиме Agent они подключаются уже сейчас
через `mcp.json`, без единой строки кода. Для чата этот путь не подходит:

- Серверы запускаются для одного рабочего каталога (`services/mcp_servers.rs`,
  `for_turn(config, cwd, …)`), и смена каталога останавливает их все. У чата папки нет.
  Если запускать их, например, в `~`, каждое переключение между агентом и чатом
  перезапускало бы серверы агента.
- В чат попали бы все серверы пользователя, включая файловые, а это ломает саму идею
  чата без папки.
- Каждый вызов MCP-инструмента спрашивает (`ToolName::Mcp` считается изменяющим), и
  одобрять каждый поиск утомительно.
- Нужен Node (`npx`), а с Dock он запускается не всегда (`infra/login_path.rs`).

Встроенный инструмент решает всё это для чата. В папке остаётся MCP: там он уже
работает, пользователь сам выбирает сервер (Tavily, Brave или другой) и платит за него,
а агент, который ищет по пять раз за ход, не расходует кредиты встроенного ключа.

## Почему Tavily

| | Tavily | Brave Search API |
|---|---|---|
| Что возвращает | Для каждого результата до 3 фрагментов страницы по ~500 символов, отобранных под запрос | Поисковую выдачу: заголовок, ссылку, сниппет |
| Нужен ли второй инструмент, чтобы прочитать страницу | Обычно нет: фрагменты и есть содержание | Да, `webFetch`, а его нет |
| Индекс | Свой поверх нескольких источников | Собственный независимый |
| Цена | `basic` стоит 1 кредит, `advanced` 2; есть бесплатный месячный лимит | Дешевле на объёме; бесплатный тариф урезан, условия нужно смотреть на сайте |

Для агента важнее всего первая строка: одним вызовом он получает текст, который можно
цитировать, а не список ссылок. Brave вторым бэкендом добавим, если Tavily не устроит по
цене или качеству (см. «Вне плана»).

API (сверено по docs.tavily.com, 2026-09-30): `POST https://api.tavily.com/search`,
`Authorization: Bearer tvly-…`, тело — JSON с полями `query`, `search_depth`
(`basic` | `fast` | `advanced` | `ultra-fast`), `max_results` (0…20), `time_range`
(`day` | `week` | `month` | `year`), `topic`, `chunks_per_source`, `include_answer`,
`include_raw_content` и др. Ответ: `results[]` с полями `title`, `url`, `content`, `score`.

## Что уже есть и переиспользуется

| Что | Где | Зачем здесь |
|---|---|---|
| Контракт инструмента: вариант в `ToolName`/`ToolCall`/`ToolResult`, модуль, ветка `match`, строка в `DEFINITIONS` | `domain/tools.rs`, `services/ai_tools/tools/mod.rs`, `parse.rs` | Новый инструмент добавляется так же, как любой другой |
| Инструмент, работающий без папки | `dispatch(scope: None, …)` | `webSearch` не вызывает `folder()?`, поэтому работает и в чате |
| Необязательная зависимость в `ToolDeps` | `search: Option<CodeSearchFn>` | Так же передаётся `web: Option<WebSearchFn>` |
| Фильтр по режиму и по роли | `conversation_mode::tools`, `ChatRole::tools()` | Решают, где инструмент предлагается |
| HTTP-агент с TLS | `infra/http_agent.rs::build_agent` | Через него идёт запрос к Tavily, без нового HTTP-клиента |
| Запечатанное хранилище ключей | `infra/llm_credentials_store.rs` (`SecretPurpose::ProviderApiKey`) | Там же хранится ключ Tavily |
| Проверка, откуда код ходит в сеть | `data_policy.rs` (`NETWORK_ALLOWED`) | Новый модуль добавляется в этот список, иначе тест упадёт |
| Описание вызова в логе чата | `src/lib/describeTool.ts` | Строка и развёрнутый вид `webSearch` |

## Решения

### 1. Порт в `domain/`, Tavily в `infra/`

- `domain/web_search.rs`: `WebQuery { query, max_results, time_range }`,
  `WebHit { title, url, content }`, `WebSearchError` (thiserror: нет ключа, ключ отвергнут,
  исчерпан лимит, провайдер недоступен, неразборчивый ответ) и
  `pub type WebSearchFn = Arc<dyn Fn(&WebQuery) -> Result<Vec<WebHit>, WebSearchError> + Send + Sync>`
  по образцу `CodeSearchFn`. Вторая реализация настоящая — это тестовый двойник, поэтому
  трейт-граница здесь оправдана.
- **Без SDK.** Официальный SDK у Tavily есть только для Python и JS. Неофициальный крейт
  `tavily` (2.1.0) асинхронный и тянет `reqwest` и `tokio`. Здесь HTTP идёт через `ureq` с
  TLS из `infra/http_agent.rs`, а `reqwest` разрешён только под SDK MCP
  (`data_policy::no_dependency_exists_to_send_data_elsewhere`). Сам вызов — это один
  `POST` и две структуры `serde`, десятки строк; крейт ради них не нужен.
- `infra/tavily.rs`: сборка тела запроса, разбор ответа, перевод HTTP-кодов в
  `WebSearchError`. Разбор и сборка — чистые функции, тестируются без сети. Параметры
  фиксированы: `search_depth: "basic"`, `include_answer: false` (отвечает модель, а не
  Tavily), `include_raw_content: false`, `include_images: false`. Таймаут 20 с.
- Ключ хранится в `llm_credentials_store` под зарезервированным id `web-search:tavily`, в
  том же запечатанном файле. Отдельное хранилище ради одного ключа не нужно.

### 2. Инструмент `webSearch`

- Аргументы: `query` (обязательный), `maxResults` (1…10, по умолчанию 5), `timeRange`
  (`day` | `week` | `month` | `year`, необязательный). `topic`, `include_domains` и глубину
  не открываем, пока не понадобятся.
- Результат модели: для каждой находки заголовок, адрес и фрагменты. Перед ними стоит
  строка о том, что это текст из интернета — данные, а не инструкции. Это защита от
  prompt injection со страниц: пусть слабая, но дешёвая.
- Общий размер ограничен, как у вывода команды: при `maxResults` = 10 и трёх фрагментах по
  500 символов получается до ~15 000 символов.
- `loop_weight` = 2: один сетевой запрос длиной около секунды, как `gitDiff`.
- `is_mutating` = false: на машине и в кластере поиск ничего не меняет. Что он выносит
  наружу — см. решение 4.

### 3. Где инструмент предлагается

| Где | Предлагается | Почему |
|---|---|---|
| Chat → Assistant | да | Ради этого всё и затевается |
| Chat → Kubernetes | да | Ошибки операторов, известные проблемы чартов, заметки к релизам |
| Папка: Agent | нет | Поиск через MCP-сервер из `mcp.json`, кредиты не тратятся |
| Папка: Plan, Ask, Explore, Review | нет | MCP есть только в Agent, так что поиска здесь нет вовсе. Принято: вопрос, которому нужен интернет, задают в чате или в Agent |

`conversation_mode::tools` не меняется ни для одного режима, поэтому `webSearch` в папке
отказывается тем же путём, что и любой инструмент, не предложенный режимом.

Пока ключа нет, инструмент **не предлагается и в чате**: для `Place::Chat` `offered()`
отфильтровывает `webSearch`, если `turn.web` равен `None`. Если его показать, модель потратит раунд на
вызов, который гарантированно упадёт, а схема будет занимать токены в каждом запросе.
Если модель вызовет его по памяти, `dispatch` вернёт `WebSearchError::NoKey` с
подсказкой «добавьте ключ в Settings → Web search».

Описание роли Assistant («no files, commands or tools») и её промпт («You cannot…»)
придётся поправить: инструмент у неё теперь есть. Промпт при этом остаётся
статическим, и кэш провайдера не страдает. Наличие ключа видно только по списку
инструментов, а он меняется лишь при добавлении или удалении ключа.

### 4. Что уходит наружу, и почему без карточки

Tavily получает строку `query`. Её составляет модель, поэтому туда может попасть что
угодно из разговора: имя внутреннего сервиса, кусок кода, текст ошибки с путём.

Правило из `08-data-policy.md` гласит: всё, что выносит данные, кроме провайдера модели,
«либо настраивает сам пользователь, либо спрашивает перед каждым разом». Здесь работает
первая половина: инструмент появляется только после того, как пользователь сам ввёл ключ.
Экран Settings → Web search прямо говорит, что запросы, составленные моделью, уходят в
Tavily. Каждый запрос виден в логе вызовов чата.

Карточку на каждый поиск не показываем: ход, в котором модель ищет трижды, с ней
превращается в три одобрения подряд. В лог вызовов пишется запрос и адреса результатов; текст
фрагментов вырезается так же, как `text` у `kube*`.

### 5. Settings → Web search

Новая секция в `Settings.tsx` (иконка `Globe`) — «поиск в интернете для чата» — содержит
поле ключа, строку о том, что в папке поиск подключается через MCP, ссылку «получить ключ»
(открывается в системном браузере, как любая ссылка), строку о том, что уходит наружу, и
кнопку «Удалить ключ». Ключ пишется в хранилище и больше не возвращается: наружу отдаётся
только `hasKey`, как у провайдеров модели. Отдельного переключателя нет — наличие ключа и
есть включение.

Команды `web_search_key_status`, `web_search_key_save`, `web_search_key_delete` живут в
`commands/settings.rs`, у каждой есть обёртка в `src/lib/`. Новых capability не нужно:
это обычные команды, а не плагин.

варианты в `ToolName`, `ToolCall`, `ToolResult`, разбор в `parse.rs`, строка в
`DEFINITIONS`, вес, `ChatRole::tools()`, поле `web` в `Turn`, `ToolDeps` и `ChatTurn`,

нет в запросе», «вызов по памяти без ключа → понятная ошибка», «ни один режим папки его не
предлагает», предложение по ролям, ход чата Assistant с двойником поиска через `plain_chat`.
Проверки: `cargo check && cargo test` и мутационный прогон по
[11-mutation-testing.md](11-mutation-testing.md).

*Сделано 2026-09-30.* Инструмент работает, когда ключ лежит в хранилище под
`web-search:tavily` (`infra::tavily::saved`); ввести его из окна можно будет после W-2.
**Мутации: девятнадцать, все пойманы** — тело запроса, коды ответа, разбор ошибки,
проверки запроса и обрезка, фильтр без ключа, путь до инструмента, пометка «не

## Вне плана

- **Brave вторым бэкендом.** Когда понадобится, это ещё одна реализация `WebSearchFn` и
  выбор в Settings. Порт уже есть, так что правка останется в `infra/` и в Settings.
- **`webFetch`** — прочитать страницу по адресу. Tavily уже возвращает фрагменты, а
  `extract` добавим, когда модель начнёт упираться в них. Это отдельный выход данных со
  своими вопросами: закрытые адреса, редиректы, localhost.
- **Нативный серверный поиск провайдера** (у Anthropic и OpenAI есть свои). Зависит от
  провайдера и не работает у OpenAI-совместимых. Встроенный инструмент одинаков у всех.

## Открытые вопросы

1. **Карточка на первый поиск в чате?** Предлагается «нет» (решение 4). Альтернатива —
   Always allow per chat, как у MCP, но это возвращает ту самую усталость от одобрений.
2. **Язык запроса.** Модель ищет на языке пользователя или на английском? Предлагается не
   вмешиваться: пусть решает модель.
