# Несколько папок одновременно (F-8)

Рабочий документ фичи. Сайдбар уже рисует чаты группой под папкой, но бэкенд держит
**одну** открытую папку на всё приложение, а смена папки гасит всё, что к ней относилось.
Цель: открыть в сайдбаре несколько папок и работать, переключаясь между их чатами, не теряя
ни индекса, ни фоновых процессов, ни разрешений.

Документ живёт до конца фичи: опись, решения, нарезка, инварианты, журнал. Каждый подшаг
отмечается здесь и одной строкой в [06-port-plan.md](06-port-plan.md).

## Решения (приняты пользователем 2026-09-19)

| Вопрос | Решение | Что это значит |
|---|---|---|
| Ходы | **Один ход за раз; смотреть другие чаты можно** | Пока агент идёт в чате X, можно открыть и читать любой чат любой папки; отправить можно только в X (или остановить его). Сайдбар показывает, какой чат работает. Параллельные ходы — отдельная фича потом |
| Индекс | **Все открытые папки держат свой индекс** | Свой `RepoIndexer` и наблюдатель на каждую папку в сайдбаре; модель эмбеддингов одна на всех. Переключение мгновенное |
| Процессы и MCP | **Живут до закрытия папки** | Dev-сервер папки A не умирает при переходе в B. Останавливаются, когда папку убрали из сайдбара или закрыли приложение. MCP — свой набор серверов на папку, запускается первым ходом в ней |
| «Always allow» | **На папку** | Разрешение, данное в своём проекте, не действует в чужом репозитории, открытом рядом. Как и сейчас, не сохраняется между запусками |

**Предлагаемое, требует подтверждения** (не было в вопросах):

- **Auto остаётся одним на приложение.** Это видимая кнопка композера, а не ответ на
  карточку; разнести её по папкам — значит показывать разное состояние одной и той же
  кнопки в зависимости от выбранного чата.
- **Режим разговора (Agent/Plan/Ask) — тоже один**, как сейчас.

## Нарезка

Каждый шаг — компилируется, тесты зелёные, мутации прогнаны, коммит `stage f-8.N — …`.
Бэкенд сначала: пока фронтенд не переписан, он работает с **одной** папкой через новые
команды, и приложение на каждом шаге рабочее.

| Шаг | Что | Готово, когда |
|---|---|---|
| **F-8.1** | Реестр открытых папок в бэкенде: `workspace_add` / `workspace_close` / `workspace_list`, `workspaces.json`; `AgentState.workspace` уходит, все команды получают папку аргументом и проверяют её по реестру | Тест: команда с папкой не из реестра отказывает; с путём в обход канонизации (`..`, симлинк) — тоже |
| **F-8.2** | Индекс на папку: `WorkspaceIndex` — карта; `close` снимает наблюдателя; поиск хода — индекс его папки | Тест: две папки проиндексированы, поиск в A не находит B; закрытие A останавливает её синк, B продолжает |
| **F-8.3** | Процессы по папке: `ProcessInfo.workspace`, закрытие папки останавливает её процессы, агент видит и трогает только свои | Тест: `stopProcess` из хода в B по id процесса A — отказ; закрытие A не трогает процессы B |
| **F-8.4** | MCP-пул на папку, остановка при закрытии | Тест: ход в B не останавливает серверы A |
| **F-8.5** | «Always allow» на папку, Auto — общий | Тест: разрешение в A не снимает карточку в B |
| **F-8.6** | Фронтенд: сайдбар из нескольких групп, добавить/убрать папку, «+» в группе, активная папка = папка просматриваемого чата; правая панель — по активной папке | Тест компонентов; живая проверка пользователем |
| **F-8.7** | Фронтенд: идущий ход отделён от просматриваемого чата — события не теряются, сохранение идёт в чат хода, отправка из другого чата недоступна с объяснением | Тест хука: открыть другой чат посреди хода, дождаться конца — сохранён чат хода с полным транскриптом |
| **F-8.8** | Запуск: открываются все папки из `workspaces.json`, последний просмотренный чат | Тест хука; живая проверка |

## Инварианты — проверяются тестами, не дисциплиной

1. **Папка из окна — не доверенная.** Любая команда, получившая путь, канонизирует его и
   принимает только папку из реестра открытых (AGENTS.md: «validate/canonicalize any path
   coming from the frontend»). Реестр — единственное место, где это решается.
2. **Ход не выходит из своей папки.** Scope, поиск, правила, алиасы git, MCP, процессы — всё
   от папки, с которой ход начался; `chat_resume` с другой папкой — ошибка.
3. **Чат не переезжает.** `chat_save` существующего чата под другой папкой — ошибка, а не
   перезапись поля.
4. **Закрытие папки убирает всё её**: наблюдатель индекса, процессы, MCP-серверы,
   разрешения. И ничего чужого.
5. **Закрыть папку, в которой идёт ход, нельзя** — сначала остановить.
6. **Событие без папки не применяется к чужой.** Индекс уже шлёт `root`; всё новое, что
   шлёт события по папке, — тоже.
7. **Один ход за раз** — как сейчас: второй `chat_start` при идущем ходе отказывает.

## Проверка

- После каждого шага: `cargo check && cargo test`, `bun run tsc --noEmit && bun test`,
  мутации по изменённому, выжившие — закрыть тестом.
- В конце — сквозной прогон по инвариантам выше: для каждого назвать тест, который его
  держит; инвариант без теста — не закрыт.
- Живая проверка пользователем (`bun run tauri dev`), чеклист:
  1. Открыть две папки; в каждой по чату; переключаться — индекс и список чатов свои.
  2. Запустить в A dev-сервер (`background`), перейти в B — процесс жив, во вкладке
     Terminal B его нет.
  3. «Always allow runCommand» в A — в B карточка всё равно появляется.
  4. Пустить длинный ход в A, открыть чат в B, вернуться — ход дошёл, транскрипт полный,
     чат A сохранён; в B отправить нельзя, пока A идёт.
  5. Убрать A из сайдбара — её процессы остановлены, B не тронута.
  6. Перезапустить приложение — обе папки на месте.

## Потолки

- Память: каждая открытая папка держит свой SQLite-индекс и наблюдателя. Десяток папок —
  нормально; если станет много — закрывать индекс давно не открывавшейся папки (LRU),
  оставляя её в сайдбаре.
- Эмбеддинг изменений в фоновых папках идёт через ту же модель — `git checkout` в соседнем
  репозитории займёт её, пока ход ждёт поиска.
