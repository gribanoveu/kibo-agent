# Несколько папок одновременно (F-8)

Рабочий документ фичи. Сайдбар уже рисует чаты группой под папкой, но бэкенд держит
**одну** открытую папку на всё приложение, а смена папки гасит всё, что к ней относилось.
Цель: открыть в сайдбаре несколько папок и работать, переключаясь между их чатами, не теряя
ни индекса, ни фоновых процессов, ни разрешений.

Документ живёт до конца фичи: опись, решения, нарезка, инварианты, журнал. Каждый подшаг
отмечается здесь и одной строкой в [06-port-plan.md](06-port-plan.md).

## Решения

Приняты пользователем 2026-09-19 (ходы, индекс, процессы/MCP, «always allow») и
дополнены 2026-11-16 (изоляция, единица — папка):

| Вопрос | Решение | Что это значит |
|---|---|---|
| Ходы | **Параллельные, как сейчас** | Реестр сессий по `chat_id` уже сделан в PS ([45-parallel-sessions.md](45-parallel-sessions.md)). Ход чата идёт в своей папке; окно может смотреть любой чат любой папки. Отдельного «одного хода на окно» нет и не возвращаем |
| Индекс | **Все открытые папки держат свой индекс** | Свой `RepoIndexer` и наблюдатель на каждую папку в сайдбаре; модель эмбеддингов одна на всех. Переключение мгновенное |
| Процессы и MCP | **Живут до закрытия папки** | Dev-сервер папки A не умирает при переходе в B. Останавливаются, когда папку убрали из сайдбара или закрыли приложение. MCP — свой набор серверов на папку, запускается первым ходом в ней |
| «Always allow» | **На папку** | Разрешение, данное в своём проекте, не действует в чужом репозитории, открытом рядом. Как и сейчас, не сохраняется между запусками |
| **Изоляция (2026-11-16, смягчена в тот же день)** | **Папка = проект; чат живёт внутри неё** | Чат принадлежит ровно одной папке и никогда её не покидает. Рабочий набор хода — своя папка: scope, поиск, правила, git, MCP, процессы; соседние папки не индексируются и не ищутся. Это не глухая стена: чтение файла вне папки по явному пути не запрещено — `runCommand` умеет это уже сегодня (через карточку approval); path-инструменты заперты в корне (CA-3.9, `resolve.rs`). **Дополнительных ограничений для модели F-8 не строит** — остаётся всё как сейчас. Дополнительных корней пока нет: `/add-dir` как в Kimi Code — **отложенная фича**, возможна позже. Вопросы про другой репозиторий — чатом в нём |

Дополнено 2026-11-16 (что не меняется):

- **IDE layout открывает и отображает только папку проекта** — ничего там не меняется.
  Вкладка Files и редактор в IDE-раскладке показывают активную папку, не все открытые.
- **Открытие терминала — аналогично**: шелл открывается в папке проекта (активной),
  поведение как сейчас. F-8.3 придаёт шеллам папку для закрытия и списка, но не меняет,
  где они открываются.

**Предлагаемое, требует подтверждения** (не было в вопросах):

- **Auto остаётся одним на приложение.** Это видимая кнопка композера, а не ответ на
  карточку; разнести её по папкам — значит показывать разное состояние одной и той же
  кнопки в зависимости от выбранного чата.
- **Режим разговора (Agent/Plan/Ask) — тоже один**, как сейчас.

## Опись: что сейчас привязано к одной папке

Проверено чтением кода на коммите `dede1694` (2026-11-16). Прошлая опись — `a438abb`
(2026-09-19); с тех пор фича PS сделала за F-8 значительную часть ходовой работы —
она вынесена в «уже готово».

### Уже готово (PS и доработки сентября–ноября)

- **Ход знает свою папку.** `chat_start`/`chat_resume`/`chat_preview` берут checkout из
  чата — `AgentState::chat_workspace(chat_id)` (`commands/chat.rs`) — а не из открытой
  папки. Scope, поиск (`searcher_of` берёт индекс папки чата — `WorkspaceIndex::searcher(root)`, F-8.2), правила,
  MCP и процессы хода собираются от неё.
- **Реестр сессий по `chat_id`** с `running_root` на ход: `parallel_chats`,
  `root_is_idle`, лимит параллельных ходов (`commands/agent_state.rs`).
- **Чаты хранятся под папкой**: `chat_store::list/save` ключированы по `workspace`,
  колонка `workspace` уже в схеме `chats` — миграция не нужна. Пины и группы чатов
  тоже под папкой.
- **События несут папку**: `workspace-index:event` — `root`, `workspace-git:changed` —
  тоже; фронтенд уже фильтрует по ней (`useIndexStatus`, `onFolderChanged`).
- **Доверие папки и approval-auto персистентно по пути папки**
  (`folder_trust`, `settings.approval.set_auto(chat_id, folder)`).
- **Фронтенд ходов**: `useAgentTurn` — реестр сессий `Map<chatId, Session>`; фоновый
  ход живёт и сохраняется, пока смотришь другой чат.
- **Паттерн «аргумент вместо state» уже есть**: `chat_group_*` шлют
  `workspace: Option<String>` и бэкенд сверяет его со state (`group_workspace`,
  `commands/chat_history.rs`). F-8 обобщает этот паттерн на все UI-команды и заменяет
  сверку со state на сверку с реестром открытых.

## Инварианты — проверяются тестами, не дисциплиной

1. **Папка из окна — не доверенная.** Любая команда, получившая путь, канонизирует его и
   принимает только папку из реестра открытых (AGENTS.md: «validate/canonicalize any path
   coming from the frontend»). Реестр — единственное место, где это решается.
2. **Ход работает в своей папке — как уже сейчас.** Scope, поиск, правила, git, MCP,
   процессы — всё от папки, с которой ход начался (сделано в PS). Новых ограничений
   для модели F-8 не добавляет; чтение по явному пути вне папки не запрещается
   (`runCommand`, через approval) — см. решение об изоляции.
3. **Чат не переезжает.** `chat_save` существующего чата под другой папкой — ошибка, а не
   перезапись поля. (Колонка `workspace` уже в схеме.)
4. **Закрытие папки убирает всё её**: наблюдатель индекса, процессы, терминалы,
   MCP-серверы, разрешения. И ничего чужого.
5. **Закрыть папку, в которой идёт хоть один ход (в любом чате), нельзя** — сначала
   остановить.
6. **Событие без папки не применяется к чужой.** События уже несут `root`; всё новое,
   что шлёт события по папке, — тоже.

~~7. Один ход за раз~~ — снят PS-1 ([45-parallel-sessions.md](45-parallel-sessions.md)):
ходы разных чатов идут параллельно в пределах лимита; внутри одного чата — по-прежнему
один.

- Живая проверка пользователем (`bun run tauri dev`), чеклист:
  1. Открыть две папки; в каждой по чату; переключаться — индекс и список чатов свои.
  2. Запустить в A dev-сервер (`background`), перейти в B — процесс жив, во вкладке
     Terminal B его нет.
  3. «Always allow runCommand» в A — в B карточка всё равно появляется.
  4. Пустить длинный ход в A, открыть чат в B, писать в B (ход B идёт параллельно в
     пределах лимита), вернуться в A — ход дошёл, транскрипт полный, чат A сохранён.
  5. Чат в A не ищет в B: спросить про репозиторий соседней папки — модель не находит
     его файлы поиском и индексом, предлагает открыть чат там. Прочитать файл B по
     явному пути, названному пользователем, — можно (`runCommand`, через approval).
  6. Убрать A из сайдбара — её процессы и терминалы остановлены, B не тронута.
  7. Перезапустить приложение — обе папки на месте, активна папка последнего чата.

## Потолки

- Память: каждая открытая папка держит свой SQLite-индекс и наблюдателя. Десяток папок —
  нормально; если станет много — закрывать индекс давно не открывавшейся папки (LRU),
  оставляя её в сайдбаре.
- Эмбеддинг изменений в фоновых папках идёт через ту же модель — `git checkout` в соседнем
  репозитории займёт её, пока ход ждёт поиска.
