# Ручной порядок папок в сайдбаре: поставить одну папку выше другой

План, предложен 2026-11-20. В режиме Agent сайдбар рисует секцию на каждую открытую папку;
сегодня их порядок задан историей открытия и заморожен фронтом, а поменять его нельзя.
Фича даёт пользователю расставить папки вручную — пунктами «Move up»/«Move down» в меню
«⋮» заголовка секции, — и порядок переживает перезапуск. Строится на реестре открытых
папок (F-8, [10-multi-workspace.md](10-multi-workspace.md)).

Кода в документе нет — только решения.

## Что уже есть

- Порядок секций — порядок массива `workspace.folders`: `src/App.tsx:952-959` строит
  `sections` из него. Хук `src/hooks/useWorkspace.ts` владеет массивом; `keepOrder`
  (`useWorkspace.ts:14-24`) держит уже показанные папки на местах, новые добавляет в
  конец — список не двигается под курсором при переключении чатов.
- Бэкенд-источник: реестр открытых в памяти `open: Mutex<Vec<PathBuf>>`
  (`src-tauri/src/commands/agent_state.rs:116`), `register_open` вставляет в начало
  (:266-270); файл `workspaces.json` — «последняя добавленная первой»
  (`src-tauri/src/infra/open_folders.rs`). `workspaces_list`
  (`src-tauri/src/commands/workspace.rs:197-205`) отдаёт порядок реестра как есть;
  `workspaces_restore` (:26-50) регистрирует сохранённые папки в обратном порядке, так
  что после запуска реестр повторяет порядок файла. Экранный порядок — обратный к
  файловому (это делает `keepOrder` при первом чтении).
- Команды переупорядочивания нет: API файла — только `remember/record/remove`, у чатовых
  папок (`ChatGroup.position`) — только create/rename/delete.
- Заголовок секции (`.chat-workspace-head`) уже несёт меню «⋮» (`ChatMenu`) с пунктами
  «New chat» и «Close folder» — новые пункты встают туда же. Drag-and-drop в сайдбаре
  нет; в доске есть (`@dnd-kit`, `BoardPage.tsx`), но для меню он не нужен.

## Решения

### 1. Порядок хранит бэкенд, а не localStorage

Новая команда `workspaces_reorder` принимает желаемый экранный порядок путей, проверяет,
что множество совпадает с открытым (ни одна не потеряна и не добавлена), и переписывает
реестр и `workspaces.json`. Отвергнуто: порядок в localStorage поверх бэкендного списка —
два источника правды, `workspaces_restore` после перезапуска дал бы другой порядок, и
заморозка `keepOrder` начала бы спорить с сохранённой. Файл уже персистит порядок —
команда лишь даёт его задать.

Конвенция «файл — обратный к экранному» сохраняется: команда принимает экранный порядок
и пишет файл в его конвенции. Тест обязан закрепить круг «reorder → restore → тот же
экранный порядок», иначе порядок молча перевернётся при перезапуске.

### 2. Фронт применяет порядок оптимистично, `keepOrder` не трогается

`useWorkspace` получает `reorder(next: string[])`: сразу `setFolders(next)` и вызов
команды; при отказе — перечитать. `keepOrder` остаётся как есть: последующие `reread`
(открытие/закрытие папки) сохраняют уже показанный порядок, включая ручной. Событие не
нужно: перестановку делает это окно, других окон с сайдбаром нет; существующие сигналы
перечитывания порядок не ломают.

### 3. Пункты «Move up»/«Move down» в меню «⋮» секции

Выбор пользователя (2026-11-20). В меню заголовка секции, выше «Close folder», два
пункта со стрелками (lucide `ArrowUp`/`ArrowDown`); у первой папки «Move up» недоступен
(`disabled` с `hint`), у последней — «Move down». Пункт меняет папку с соседом и зовёт
`reorder`. Отвергнуто перетаскивание заголовка (@dnd-kit, паттерн доски): больше кода
(сенсоры, клавиатурный жест, записи в реестре шорткатов), а меню даёт клавиатурный
доступ даром. Новых клавиш нет — записи в `shortcuts.ts` не нужны.

### 4. Только папки-рабочие-области; чатовые папки не трогаем

Речь о секциях открытых папок в Agent-режиме (то, что обсуждали). У чатовых папок
(`ChatGroup`) есть `position`, но нет ни команды смены порядка, ни UI — это отдельная
фича, если понадобится.

## Слои

- `src-tauri/src/commands/agent_state.rs` — метод реестра `reorder` рядом с
  `register_open`/`close` (реестр уже живёт здесь, standing exception); проверка
  множества — там же, отказ типизированной ошибкой.
- `src-tauri/src/infra/open_folders.rs` — перезапись файла в существующей конвенции
  (`save` уже есть).
- `src-tauri/src/commands/workspace.rs` — тонкая `workspaces_reorder`, `async` через
  `commands::blocking` (файл + мьютекс); регистрация в `generate_handler![]`.
- Фронт: обёртка `reorderWorkspaces` в `src/lib/chat.ts`; `reorder` в
  `src/hooks/useWorkspace.ts`; пункты меню в `src/components/Sidebar.tsx` (проп
  `onMoveFolder` из `App.tsx`).
- Нового канала событий, инструмента агента, фичи в Catalog, записей в `shortcuts.ts`
  нет.

## Нарезка

Каждый этап — отдельный коммит с тестами и мутационной проверкой
([11-mutation-testing.md](11-mutation-testing.md)).

**FO-1. Бэкенд: команда порядка.** `workspaces_reorder` + метод реестра + перезапись
файла + обёртка. Тесты (Rust): перестановка меняет порядок `workspaces_list`; чужой или
недостающий путь — отказ, порядок не тронут; круг «reorder → restore» даёт тот же
экранный порядок; файл перезаписан. Мутации: снятая проверка множества, перевёрнутая
конвенция записи, порядок не сохранён.

**FO-2. Пункты меню в сайдбаре.** `useWorkspace.reorder` (оптимистично), «Move
up»/«Move down» в меню «⋮» секции, проп `onMoveFolder` через `App.tsx`. Тесты (фронт):
пункт меняет папку с соседом и зовёт обёртку с полным порядком; у первой папки «Move
up» недоступен, у последней — «Move down»; `reread` после перестановки порядок
сохраняет; новая папка по-прежнему встаёт в конец; отказ команды возвращает прежний
порядок. Мутации на логику `reorder`/`keepOrder`.

**FO-3. Документы.** Строка в `CHANGELOG.md`, статусы в `docs/README.md` и этом плане.

## Вне плана

- Порядок чатовых папок (`ChatGroup.position`) — вернёмся, если попросят: нужна своя
  команда смены position и тот же жест.
- Порядок чатов внутри папки — им владеет стор («последний тронутый первый»), ручной
  порядок противоречит этому правилу.
- Перенос чата в другую папку перетаскиванием — есть «To folder» в меню строки.
