# Ручной порядок папок в сайдбаре: поставить одну папку выше другой

Сделано FO-1…FO-2 (2026-11-20, без ручной проверки в запущенном приложении). В режиме Agent сайдбар рисует секцию на каждую открытую папку;
сегодня их порядок задан историей открытия и заморожен фронтом, а поменять его нельзя.
Фича даёт пользователю расставить папки вручную — пунктами «Move up»/«Move down» в меню
«⋮» заголовка секции, — и порядок переживает перезапуск. Порядок — состояние вида в
window storage; реестр открытых папок (F-8, [10-multi-workspace.md](10-multi-workspace.md))
не тронут.

Кода в документе нет — только решения.

## Что уже есть

- Порядок секций — порядок массива `workspace.folders`: `src/App.tsx:952-959` строит
  `sections` из него. Хук `src/hooks/useWorkspace.ts` владеет массивом; `keepOrder`
  (`useWorkspace.ts:14-24`) держит уже показанные папки на местах, новые добавляет в
  конец — список не двигается под курсором при переключении чатов.
- Бэкенд-источник: реестр открытых в памяти `open: Mutex<Vec<PathBuf>>`
  (`src-tauri/src/commands/agent_state.rs:116`), `register_open` вставляет в начало
  (:266-270); файл `workspaces.json` — «последняя добавленная первой»
  (`src-tauri/src/infra/open_folders.rs`). `workspaces_list`
  (`src-tauri/src/commands/workspace.rs:197-205`) отдаёт порядок реестра как есть;
  `workspaces_restore` (:26-50) регистрирует сохранённые папки в обратном порядке, так
  что после запуска реестр повторяет порядок файла. Экранный порядок — обратный к
  файловому (это делает `keepOrder` при первом чтении).
- Команды переупорядочивания нет: API файла — только `remember/record/remove`, у чатовых
  папок (`ChatGroup.position`) — только create/rename/delete.
- Заголовок секции (`.chat-workspace-head`) уже несёт меню «⋮» (`ChatMenu`) с пунктами
  «New chat» и «Close folder» — новые пункты встают туда же. Drag-and-drop в сайдбаре
  нет; в доске есть (`@dnd-kit`, `BoardPage.tsx`), но для меню он не нужен.

## Решения

### 1. Порядок — состояние вида в window storage; бэкенд не трогаем

Ручной порядок живёт в localStorage (`kibo-folder-order`, массив путей), как свёрнутость
секций (`kibo-folder-folded-…`) — это правило AGENTS.md: «collapse is about the view… it
lives in window storage». Бэкенд-файл `workspaces.json` продолжает хранить своё.

Почему не бэкенд (разворот первоначального решения): выяснилось, что порядок и активация в
`workspaces.json` — один список. Голова файла = «последняя активированная» = какую папку
`workspaces_restore` откроет при запуске (F-8.8). Переключение чата другой папки зовёт
`workspace.open` → `workspace_add` → `register_open`/`record`, двигающие папку в голову
(`App.tsx:394`, `agent_state.rs:266`, `open_folders.rs:record`). Если писать ручной порядок
тем же файлом, ближайшее переключение чата снова переставит голову — порядок молча
ломается. Хранить оба факта в одном списке нельзя без нового формата и миграции; это
дороже самой фичи. Window storage разводит два факта даром: бэкенд помнит активацию,
вид — порядок. Порядок переживает перезапуск (localStorage на диске профиля), F-8.8 не
тронут. Отвергнуто и перетаскивание, и SQL (см. «Вне плана»).

### 2. `useWorkspace.move` меняет соседей и пишет storage; `keepOrder` сеется порядком

`useWorkspace` получает `move(folder, dir: -1 | 1)`: меняет папку с соседом в `folders`,
пишет новый порядок в storage; на краях — ничего. Первый `reread` сеет `keepOrder`
сохранённым порядком (`keepOrder(shown.length ? shown : storedOrder(), open)`), дальше
`keepOrder` держит уже показанный порядок, включая ручной; новые папки — в конец,
закрытые выпадают. Storage зеркалит экран: `reread` тоже пишет вычисленный порядок —
открытие/закрытие двигают секции без `move`, и без этого рестарт сеял бы устаревшую
расстановку (находка ревью FO-1). Бэкенд-вызова нет, отказа нет, событие не нужно:
перестановку делает это окно, других окон с сайдбаром нет.

### 3. Пункты «Move up»/«Move down» в меню «⋮» секции

Выбор пользователя (2026-11-20). В меню заголовка секции, выше «Close folder», два
пункта со стрелками (lucide `ArrowUp`/`ArrowDown`); у первой папки «Move up» недоступен
(`disabled` с `hint`), у последней — «Move down». Пункт меняет папку с соседом и зовёт
`reorder`. Отвергнуто перетаскивание заголовка (@dnd-kit, паттерн доски): больше кода
(сенсоры, клавиатурный жест, записи в реестре шорткатов), а меню даёт клавиатурный
доступ даром. Новых клавиш нет — записи в `shortcuts.ts` не нужны.

### 4. Только папки-рабочие-области; чатовые папки не трогаем

Речь о секциях открытых папок в Agent-режиме (то, что обсуждали). У чатовых папок
(`ChatGroup`) есть `position`, но нет ни команды смены порядка, ни UI — это отдельная
фича, если понадобится.

## Слои

- Только фронт. `src/hooks/useWorkspace.ts` — `move(folder, dir)` + чтение/запись
  `kibo-folder-order` и посев `keepOrder`. `src/components/Sidebar.tsx` — пункты меню и
  проп `onMoveFolder`; `src/App.tsx` — проп из `workspace.move` (только Agent-режим).
- Бэкенд не меняется. Начатый прошлой сессией `reorder_open` (+ тест) в
  `agent_state.rs` и `record_all` в `open_folders.rs` удаляются как неиспользуемые.
- Нового канала событий, команды, обёртки в `src/lib/`, инструмента агента, фичи в
  Catalog, записей в `shortcuts.ts` нет.

## Нарезка

Каждый этап — отдельный коммит с тестами и мутационной проверкой
([11-mutation-testing.md](11-mutation-testing.md)).

**FO-1. Порядок и пункты меню (фронт) — сделано.** `useWorkspace.move` + storage + посев
`keepOrder`; «Move up»/«Move down» в меню «⋮» секции, проп `onMoveFolder` через
`App.tsx`; удаление неиспользуемого бэкенд-наброска. Тесты (фронт): `move` меняет
соседей и пишет storage, на краях ничего; первый `reread` сеется сохранённым порядком;
новая папка встаёт в конец, закрытая выпадает; пункт меню зовёт `onMoveFolder` с
направлением, у первой «Move up» недоступен, у последней — «Move down».

Мутационная проверка: 10 мутантов, все пойманы. Один выжил в первом прогоне — «первое
чтение не сеется сохранённым порядком»: тест брал сохранённый порядок равным умолчанию
(reverse файла), посев ничего не менял; фикстура взята отличной от умолчания, мутация
поймана. Ревью сабагентом нашло один баг: storage писался только в `move`, а
открытие/закрытие двигают секции без него — после close→reopen рестарт сеял устаревший
порядок. Исправлено: `reread` зеркалит вычисленный порядок в storage; регрессионный тест
и мутант на это правило добавлены. Проверки: `bun run tsc --noEmit` чисто, `bun test`
1605 pass, `cargo check` чисто (бэкенд без изменений). В запущенном приложении не
проверено руками.

**FO-2. Документы — сделано.** Строка в `CHANGELOG.md`, статусы в `docs/README.md` и этом плане.

## Вне плана

- Перенос `workspaces.json` в SQLite (вопрос пользователя 2026-11-20) — нет: один
  маленький список, один писатель под мьютексом, всегда перезаписывается целиком;
  строк, запросов и частичных обновлений, ради которых SQL, здесь нет. SQL у доски и
  чатов — потому что там реляционные строки; мелкие настройки живут файлом
  (`settings.json`). Вернёмся, если у папок появятся свои часто меняемые атрибуты.
- Порядок чатовых папок (`ChatGroup.position`) — вернёмся, если попросят: нужна своя
  команда смены position и тот же жест.
- Порядок чатов внутри папки — им владеет стор («последний тронутый первый»), ручной
  порядок противоречит этому правилу.
- Перенос чата в другую папку перетаскиванием — есть «To folder» в меню строки.
