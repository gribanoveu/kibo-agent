# Папки чатов: темы в сайдбаре

Сделано CG-1…CG-3 (2026-11-12), в окне руками не проверялось. План был предложен 2026-11-12. Папка — тема работы («индексация», «релиз 0.13», «клиентский баг»),
в которую чат кладут руками; в списке она идёт своим заголовком, и её чаты больше не разложены
по дням. Закрепление ([53-pinned-chats.md](53-pinned-chats.md)) — ось времени, папка — ось темы;
они независимы и складываются в один порядок: **закреплённые → папки → остальные по дням**.

Кода в документе нет — только решения.

## Что уже есть

- `src-tauri/src/infra/chat_store.rs` — один файл SQLite с несколькими таблицами в `SCHEMA`
  (строки 49–80: `chats`, `suggestions`, `runs`), миграции — `add_column` для колонок и
  `CREATE TABLE IF NOT EXISTS` для таблиц; всё под одним `WRITE`-замком (`write_lock`, 46).
  Записи чатов — целый JSON в `body`, а рядом колонки не из тела (`archived`, `role`,
  `generated_title`).
- `src-tauri/src/domain/chat_record.rs` — `ChatSummary` (110) — то, что видит сайдбар;
  `NO_FOLDER` (31) — «папка» разговоров Chat-режима, по которой их и листают.
- `src-tauri/src/commands/chat_history.rs` и `commands/plain_chat.rs` — по паре команд на
  каждый список: `chat_list` (23) / `plain_chat_list` (270), обе — `chat_store::list(workspace)`.
- `src/components/Sidebar.tsx` — список секциями: `byDay` (70) даёт `Today`/`Earlier`, каждая
  секция `<section>` с заголовком `.chat-day` (274), строка — `chatRow` (148) с `ChatMenu`.
  Фильтр `active | archived | all` (52) и поиск по названию. `Modal` (293) для удаления,
  `Dropdown` (261) для фильтра.
- Образцы диалогов переименования: `ArtifactsPage` (поле `.artifacts-rename` в `Modal`,
  `artifact_rename`) и `KnowledgePage` (меню `Actions for <name>` → `Rename` → `Modal` с полем
  `Name` и `Save`). Свой такой диалог писать не нужно — берётся форма одного из них.
- `useStoredState` (`src/hooks/useStoredState.ts`) — состояние вида, которое переживает
  перезапуск; так хранится свёрнутость сайдбара и выбранная панель.

Чего нет: ни одного понятия «папка» у чатов. Группировка — только по дате, порядок задаёт
`updated_at`, и в `ChatSummary` нет ничего, что говорило бы, куда чат положили.

## Решения

### 1. Папка одна на чат

«Папки на темы» — это файловая привычка: вещь лежит в одном месте. Одна колонка `group_id` на
чат закрывает вопрос и не требует таблицы связей. Отвергнуто: теги (много на чат) — в списке
пришлось бы либо повторять строку в каждой теме, либо рисовать теги под названием, и ни то ни
другое не дешевле; вложенность папок — темы не вкладываются, а глубина в сайдбаре шириной
180px кончается на втором уровне.

### 2. Папка — строка в своей таблице, а не имя в колонке чата

`chat_groups(id, workspace, name, position)`, у чата — `group_id`, ссылающийся на неё.
Почему не `folder TEXT` на чате: переименование стало бы `UPDATE` по всем чатам папки (и
разъехалось бы с чатом, который в этот момент сохраняется), а пустой папки не существовало бы
вовсе — её нельзя ни создать заранее, ни оставить после переноса последнего чата. `position`
хранится явно: порядок тем — решение пользователя, а не алфавит.

### 3. Папки принадлежат папке проекта

`workspace` в `chat_groups` тот же, что в `chats`: у каждого открытого каталога свои темы, а
разговоры Chat-режима (у них `workspace = NO_FOLDER`) получают свой, общий набор. Это следствие
существующего правила «список ограничен открытым каталогом», а не второй код: обе команды
листают по тому же ключу, что и `chat_list` / `plain_chat_list`.

### 4. Удаление папки не удаляет чаты

`DELETE` папки и `UPDATE chats SET group_id = NULL` для её чатов — в одной транзакции под тем
же `WRITE`-замком. Чат, который исчез вместе с темой, — это удаление переписки через действие,
которое читается как «убрать ярлык». Отвергнуто: спрашивать в диалоге «удалить и чаты?» —
развилка, которую нельзя выбрать случайно и нельзя отменить.

### 5. Порядок списка: закреплённые → папки → дни

Закреплённые (53) стоят выше всего: это то, что нужно сейчас. Ниже — папки в их `position`,
внутри папки чаты идут по времени **без заголовков дней**: тема не про даты, и «Today /
Earlier» внутри неё — шум. Остальные чаты продолжают жить по дням внизу. Закреплённый чат не
повторяется в своей папке: строка, показанная дважды, читается как два чата (то же правило,
что в 53).

### 6. Пустая папка видна

Папка без чатов рисуется заголовком с «Empty» в теле. Иначе созданная впрок тема исчезает, и
её нельзя ни переименовать, ни удалить — то есть фича запирает сама себя. Место пустой папки
— её `position`, как у непустой.

### 7. Создание и перенос — из строки чата и из заголовка списка

- В меню строки — пункт `Move to folder…` над `Pin` и `Archive`: он открывает `Modal` со
  списком существующих папок, пунктом `No folder` и `New folder…`, который превращает диалог в
  поле имени. Один диалог на оба действия — перенос и создание, — потому что создают папку
  всегда ради переноса.
- В заголовке списка, рядом с фильтром, — `New folder…` для темы, которую заводят впрок.
- Переименование и удаление — с заголовка папки: меню `Actions for <name>` → `Rename…` /
  `Delete…`, форма — как у доменов Knowledge (52), с полем `Name` и ошибкой в самом диалоге.

### 8. Имя: обрезается, не пустое, не повторяется в пределах каталога

Сравнение без учёта регистра и лишних пробелов по краям. Отказ объясняется в диалоге, который
остаётся открытым (`ArtifactsPage` уже так делает с ошибкой отказа). Отвергнуто: молча
переименовать в `idea 2` — пользователь не поймёт, куда делась его папка.

### 9. Свёрнутость папки — состояние окна, не данные

`useStoredState` с ключом из каталога и id папки: свёрнутость — про взгляд, а не про чаты, и
синхронизировать её через хранилище значило бы гонять записи на каждый клик. Отвергнуто: поле
`collapsed` в `chat_groups` — то же решение, но с записью в SQLite на каждое сворачивание.

### 10. Новых событий нет

Список чатов в этом приложении не приходит событием: `useChatHistory` перечитывает его после
записи хода, архивации и смены каталога. Папки читаются тем же триггером (`useChatGroups`,
рядом с `refresh`), поэтому канал не нужен — `AGENTS.md` требует переиспользовать сигнал,
прежде чем заводить новый.

### 11. В ChatSwitcher папок нет

Переключатель в заголовке IDE-раскладки — быстрый поиск по названию, а не место, где живут
темы: шесть строк в меню папку только запутают. Порядок там — как отдал бэкенд.

## Слои

- `infra/chat_store.rs` — `chat_groups` в `SCHEMA` (`CREATE TABLE IF NOT EXISTS`, индекс
  `(workspace, position)`), `group_id` в `chats` через `add_column`, `groups(workspace)`,
  `create_group`, `rename_group`, `delete_group` (с обнулением `group_id`), `set_group`;
  `list` читает `group_id` и сортирует `pinned DESC, group_id IS NULL, updated_at DESC, id`.
  Заголовок модуля называет `chat_groups` рядом с остальными таблицами.
- `domain/chat_record.rs` — `group: Option<String>` в `ChatSummary`; `ChatError` получает
  вариант для занятого имени (или `AlreadyThere`, если такой уже есть) — сообщение в `commands/`.
- `commands/chat_history.rs` — `chat_group_list(workspace: Option<String>)` (`None` — Chat-режим,
  как `NO_FOLDER`), `chat_group_create`, `chat_group_rename`, `chat_group_delete`,
  `chat_set_group`; все — `async` через `commands::blocking`; `workspace` сверяется с открытым
  корнем, а не берётся на веру. Регистрация в `lib.rs`.
- `src/lib/savedChats.ts` — `ChatGroup`, обёртки пяти команд; `ChatSummary.group`.
- `src/hooks/useChatGroups.ts` (новый) или пара полей в `useChatHistory` и `usePlainChat` —
  читать папки там же, где список, и перечитывать вместе с ним.
- `src/components/Sidebar.tsx` + `Sidebar.css` — секции папок, заголовок папки с меню, пункт
  `Move to folder…`, диалог переноса/создания; свёрнутость через `useStoredState`.
- Тесты: `chat_store.rs` (создание, перенос, переименование, удаление с обнулением, пустая
  папка в списке, порядок «закреплённые → папки → прочие», занятое имя), `Sidebar.test.tsx`
  (секции, пустая папка, меню строки, диалог, свёрнутость), `docs/README.md`.

## Нарезка

Каждый этап — отдельный коммит с тестами и мутационной проверкой
([11-mutation-testing.md](11-mutation-testing.md)).

**CG-1. Хранилище.** — сделано. Таблица `chat_groups`, `group_id`, `groups`, `create_group`,
`rename_group`, `delete_group`, `set_group`, порядок `list`, `group` в `ChatSummary`. Тесты:
чат переносится и возвращается в «без папки»; удаление папки оставляет чаты и обнуляет
`group_id`; пустая папка есть в `groups`; имя-дубль отвергается, а в другом каталоге — нет;
список идёт закреплённые → папки (по `position`) → остальные; `delete_group` чужой папки —
`NotFound`; база без таблицы открывается и получает её. Мутации: `DELETE` без обнуления
`group_id`, порядок без `group_id IS NULL`, `position` из имени вместо колонки.

**CG-2. Команды и окно.** — сделано. Пять команд с регистрацией, обёртки в `src/lib/savedChats.ts`,
чтение папок вместе со списком в обоих режимах, `onGroupChat`/`onCreateGroup`/… в `App.tsx`.
Тесты: обёртки шлют то, что им дали (`chat.test.ts`-стиль), и `ChatSummary.group` доезжает.

**CG-3. Сайдбар.** — сделано. Секции папок с заголовком, счётчиком и меню (`Rename…`, `Delete…`), пустая
папка, свёрнутость, `Move to folder…` и диалог переноса/создания, `New folder…` в заголовке
списка. Тесты в `Sidebar.test.tsx`: чат перенесён — он под заголовком темы и не в днях;
пустая папка нарисована; свёрнутая не рисует строки; `Move to folder…` → `No folder` зовёт
перенос с `null`; занятое имя оставляет диалог открытым с ошибкой. Мутации: папка, чьи чаты
одновременно попали в дни; пустая папка не нарисована; диалог, закрывающийся при отказе.

**CG-4. Документы.** `CHANGELOG.md` — строка; `docs/README.md` — статус; этот файл — отчёты
мутаций и то, что не проверено руками.

## Отчёт

**Мутации: шесть, одна выжила и закрыта тестом.** CG-1: `DELETE` папки без обнуления
`group_id`; порядок `list` без `group_id IS NULL`; порядок папок из имени вместо `position`
(выжила — не было теста на порядок `groups()`; закрыт тестом
`folders_keep_the_order_they_were_made_in`, повторный прогон поймал). CG-3: чаты папки
одновременно в днях; пустая папка без «Empty»; диалог имени, закрывающийся при отказе.

## Вне плана

- **Теги и несколько папок на чат.** Возвращаемся, если тем станет больше, чем строк в списке.
- **Вложенные папки.** Плоскость — сознательная цена за ширину сайдбара.
- **Ручной порядок чатов внутри папки перетаскиванием.** Порядок — по времени; перетаскивание
  нужно там, где есть `position` у чата, а это отдельная колонка и отдельный жест.
- **Папки для артефактов и заметок Knowledge.** У них свои коллекции и домены.

## Открытые вопросы

список по дням; пустая папка видна всегда; свёрнутость запоминается (`localStorage`, на
приложение).

2. ~~Нужен ли **All** с папками вовсе..~~ — All остаётся плоским списком по дням.
3. ~~Пустая папка видна всегда..~~ — видна всегда.
4. ~~Свёрнутость папок запоминается..~~ — запоминается, ключ из каталога.
