# Функции, которые пользователь включает сам: доска и следующие

План, F-0…F-4 сделаны. До него доска Assistant'а (инструмент `board` и страница Board) была
включена у всех и всегда. Нужен общий механизм: функция, собранная в приложение, по умолчанию может быть
выключена, а пользователь включает её на странице Catalog. Тогда модель получает её
инструменты, а окно — её страницу. Следующая такая функция подключается к тому же
механизму, а не изобретает свой переключатель.

Кода в документе нет — только решения.

## Исходная точка

**До плана доска была встроена в три места, и ни одно не знало о выключении:**

| Где | Что | Файл |
|---|---|---|
| Инструменты роли | `ToolName::Board` в `ChatRole::Assistant.tools()` | `domain/chat_role.rs` |
| Промпт роли | Фраза «что просят напомнить — на доску» в `ChatRole::Assistant.prompt()` | `domain/chat_role.rs` |
| Окно | Запись `board` в `PAGES`, пункт в боковой панели | `components/pages.tsx` |

Ещё есть хранилище (`infra/board_store.rs`, `~/.kibo/board.json`) и событие `board:changed`.
Их выключать не нужно: без инструмента и страницы к ним никто не обращается.

**Чем это отличается от того, что ставит Catalog (`32-catalog.md`).** Catalog доставляет
*файлы* из удалённого репозитория: skill, команду, ранбук, запись MCP или хука. Код доски
скачать нельзя, он уже в бинарнике. Значит, для функции Catalog ничего не ставит, а только
переключает. Удалённый индекс функцию не описывает и включить её не может (ниже).

**Чем это отличается от `16-extensions.md`.** Там решается, *где живёт код* расширения:
отдельный крейт в workspace, трейт `Extension`, свой API для UI. Здесь — *как пользователь
включает* то, что уже собрано. Это слой, общий для обоих случаев:

- встроенная функция (доска) живёт в ядре и описывается манифестом в `domain/`;
- будущее расширение из `16` — это функция, чьи инструменты и страницы приходят через
  трейт. Флаг, хранение, карточка в Catalog и фильтры у них те же.

То есть этот план — облегчённый E-2 из `16`, сделанный раньше E-1. Workspace и крейт API
ради одной доски были бы непропорциональны (правило AGENTS.md про абстракции по
необходимости). Когда `16` начнётся, его E-2 сведётся к подключению расширений к
готовому механизму.

## Что такое функция

Манифест — строка в `domain/features.rs` (`Feature::manifest`), по одной на функцию:

| Поле | Что это | У доски |
|---|---|---|
| `id` | `[a-z0-9-]`, ключ в `settings.json` и в окне | `board` |
| `name`, `description` | Для карточки в Catalog | «Board», «Cards for later…» |
| `enabled_by_default` | Что действует, пока пользователь не выбрал | `false` |
| `tools` | Какие `ToolName` ей принадлежат. *Где* они предлагаются, решают, как и раньше, роли (`ChatRole::tools`) и режимы (`conversation_mode::tools`); манифест только снимает их, пока функция выключена | `Board` — роль Assistant и режимы Agent, Plan, Ask |
| `data` | Её файл в папке приложения, для «Delete data» и для карточки | `board.json` |

Страницы функции не в манифесте, а в окне: запись в `PAGES` с `feature: "<id>"`.

Манифест описывает только то, что функция *добавляет*. Код доски не меняется: она не знает,
что её можно выключить.

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Где хранится выбор | `settings.json` → `features: { "board": true }`. Хранится только явный выбор пользователя; без ключа действует `enabled_by_default` | `OptOut` хранит только выключенное и не выразит «включить то, что по умолчанию выключено». Такая же форма предложена в `16` для `extensions` — когда дойдёт до них, это будет одна карта или две одинаковые |
| Незнакомый id в настройках | Пропускается молча, но при записи не удаляется | Функцию могли убрать в новой версии или добавить в более новой. Откат версии не должен терять выбор |
| Кто фильтрует инструменты | Бэкенд, по снимку на ход: включённые функции читаются один раз за ход рядом с остальными настройками | Модель должна не видеть инструмент, а не только окно — его кнопку. Снимок на ход — тот же приём, что у skills и MCP (`commands/chat.rs`): переключение посреди хода действует со следующего |
| Где фильтр | `Turn.features` — снимок на ход. `tool_definitions_for_role` и `tool_definitions_for` отбрасывают инструменты выключенных функций (и счётчик контекста считает так же). `preflight` в `llm_chat` — одно место для папки и чата — отказывает вызову такого инструмента ошибкой `ToolError::FeatureOff`: «…turned off — tell the user they can turn it on on the Catalog page». `ToolDeps.board` — `None`, когда функция выключена | Три рубежа, как у остального: список для модели, отказ до карточки подтверждения, отказ в самом инструменте. Модель может позвать инструмент по памяти из прошлого хода, и ответ должен ей подсказать, что делать |
| Промпт | Своей фразы у функции нет: фраза про доску ушла из `ChatRole::Assistant.prompt()`, а то же самое говорит описание инструмента `board` | Описание приходит вместе с инструментом и уходит вместе с ним. Фраза в промпте при выключенной функции заставляла бы модель обещать «записал на доску», а её отдельное включение — это ещё одно место, которое можно забыть |
| Дата в промпте | Остаётся всегда | Она нужна не только доске |
| Окно: страницы | У записи в `PAGES` появляется необязательное поле `feature`. Боковая панель показывает такую страницу, только пока функция включена. `App` при поиске открытой страницы пропускает выключенные — открытая страница выключенной функции закрывается | `PAGES` — единственное место, где названа страница (`pages.tsx`). Фильтр в одном месте, а не в каждой странице |
| Откуда окно знает | `useFeatures` в `App`: команда `features_list` при монтировании и событие `features:changed` — сигнал перечитать. Wrapper'ы в `src/lib/features.ts` | Переключают на странице Catalog, а показывает боковая панель — это два разных места. По правилам AGENTS.md изменение состояния бэкенда — это событие, а не таймер и не проброс колбэка через `PageContext` |
| Где в Catalog | Отдельный блок «Features» и вкладка Features рядом со Skills, Commands…; на карточке «Built into the app». Без сети, `rev` и Update. Только в Catalog — в Settings переключателя нет | Пользователь ищет «что можно добавить» в одном месте. Но функции не из удалённого источника, и смешивать их с его записями — значит врать о происхождении |
| Кнопки | Turn on / Turn off вместо Install / Remove | Ничего не скачивается и не удаляется: слово должно говорить, что происходит |
| Панель функции | Справа, как у позиций каталога: что добавляет (инструменты с описанием и где доступны, страница, фраза промпта), где её данные, что будет при выключении | Включение — решение пользователя, и он должен видеть, что именно получит модель |
| Выключение | Со следующего хода модель не видит инструментов, страница пропадает, данные остаются. Старые чаты рисуются как раньше: `describeTool` от функции не зависит | Выключить и включить обратно — не должно ничего терять. Отрисовка истории ничего не запускает |
| Удаление данных | Отдельная кнопка «Delete data» в панели, только у выключенной функции и только когда файл есть, через `Modal` с путём файла. Бэкенд (`features_delete_data`) тоже отказывает включённой | Необратимо, поэтому не совмещается с выключением и спрашивает. Включённую модель может как раз сейчас записывать |
| Удалённый индекс | Запись `kind: "feature"` из каталога остаётся строкой в «пропущено», как любой незнакомый вид | Иначе чужой репозиторий сможет включать код в приложении |
| Одобрение | Инструменты функции идут через тот же гейт: `is_mutating` по `ToolName`, как у встроенных | Функция — это код ядра, ей доверяют так же, как остальным инструментам. `board` не мутирующий, карточки нет |

## Как добавить следующую функцию

Контракт, который проверяют тесты:

1. Инструменты — как любой встроенный: варианты в `ToolName` и `ToolCall`, модуль в
   `services/ai_tools/tools/`, ветка в `match` (AGENTS.md). Роль или режим их перечисляют, как
   сейчас.
2. Вариант в `Feature` и строка манифеста в `domain/features.rs`: какие инструменты её и где
   её данные. Id — ещё и в тесте `the_ids_are_the_ones_the_window_knows`.
3. Страница — запись в `PAGES` с `feature: "<id>"`.

Ни в фильтре, ни в Catalog, ни в боковой панели ничего не правится: они читают манифест.

**Общие тесты** — по всем функциям сразу, а не по каждой:

- инструмент выключенной функции не предлагается ни в одной роли и ни в одном режиме, а
  включённой — предлагается там, где её манифест говорит;
- вызов инструмента выключенной функции отказывает до карточки подтверждения;
- инструмент принадлежит не больше чем одной функции;
- id функций в Rust закреплены тестом, как имена событий: окно называет их строкой.

## Что нельзя потерять

- **Выключенная функция не видна модели**, а не только окну. Скрытая страница при
  предложенном инструменте — это ровно то, чего просили избежать.
- **Ход на паузе.** Функцию выключили, пока висела карточка подтверждения: после ответа
  вызов получает отказ «функция выключена». Нужен тест.
- **Данные не удаляются молча:** ни выключением, ни обновлением версии, где функции больше
  нет.
- **Выбор пользователя переживает версию,** которая о функции не знает.
- **Мутационная проверка** (`docs/11-mutation-testing.md`): фильтр списка, отказ в preflight,
  фраза промпта, значение по умолчанию, пропуск незнакомого id.

## Отвергнутые варианты

| Вариант | Почему нет |
|---|---|
| Прятать только в окне | Модель всё равно видит инструмент и пишет на доску, которую пользователь выключил |
| Функция как позиция удалённого индекса | Код не скачивается. А включать код из чужого репозитория — та же дыра, от которой каталог защищается для хуков и MCP |
| `OptOut` | Хранит только выключенное: «включить по умолчанию выключенное» в нём не выразить |
| Cargo features | Решают, что попадёт в сборку, а просили переключать во время работы |
| Сначала весь `16-extensions.md` | Workspace, крейт API и реестр ради одной встроенной функции — абстракция под гипотетический случай. Этот механизм ему не мешает: `16` подключится к нему же |

## Решено по открытым вопросам

- **Доска по умолчанию выключена.** Assistant остаётся простым чатом, пока пользователь сам не
  добавит доску. Функция до этого не выпускалась, так что ни у кого ничего не пропало.
- **Доска — и в режимах агента** Agent, Plan и Ask (не в Review и не у helper'а `explore`):
  «напомни» говорят и там. Схема инструмента — около 1,7 тыс. символов, порядка 400 токенов на
  запрос; платит только тот, кто доску включил.
- **Только в Catalog,** в Settings переключателя нет: одно место.
