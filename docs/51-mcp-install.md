# Экран установки MCP-сервера: вставка JSON заполняет поля, три шага поперёк

План, предложен 2026-11-04. Сейчас сервер добавляют формой в узком окне на 420 px в один
столбец (`ConfigEntryForm.tsx`) либо вставкой сниппета в редактор всего файла, где он молча
ложится в текст. Фича даёт добавлению свой экран: первый шаг принимает JSON из README и
заполняет поля, второй показывает те же поля в две колонки, третий — запись ровно в том
виде, в каком она уйдёт в `mcp.json`. Правка существующего сервера идёт тем же экраном со
второго шага. Бэкенд не меняется: экран производит тот же текст, что и форма.

## Что уже есть

- `src/lib/configEntries.ts` — `McpServerFields` и всё чтение и письмо одной записи:
  `readMcpServer(text, name)` раскладывает её в поля, `writeMcpServer(text, previous, fields)`
  пишет обратно (сохраняет ключи, для которых у формы нет поля, разбирает командную строку на
  `command` и `args`, даёт серверу по URL `type: "http"`, отказывает на занятое имя),
  `removeMcpServer`. Чистый модуль, покрыт `src/__tests__/configEntries.test.tsx`.
- `src/lib/configSnippets.ts` — `parseLoose` (сниппет как его печатает README: целый объект,
  голая карта серверов или кусок `"name": {…},` без скобок), `parseFile`, `mergeMcp` (вставка
  в редактор добавляет серверы в файл и говорит, какие заменила), `jsonError` с позицией
  поломки. Тоже чистый и покрыт.
- `src/components/ConfigEntryForm.tsx` — `McpServerForm`: Name, Runs (`Dropdown`), Command +
  Arguments + Environment или URL + Headers, Weight, Timeout, Its tools, Its results — всё в
  один столбец; ссылка «Edit as JSON» переключает то же окно на редактор файла. `HookForm`
  делит с ним обёртку `Field` и классы `.entry-*`.
- `src/App.tsx` — `mcpDialog: EntryDialog<string>` (`"json" | { entry: string | null } | null`),
  модалка на 1021–1035; добавление — `setMcpDialog({ entry: null })` из `McpList`
  (`src/components/panes.tsx`, кнопка `ItemList` «Add MCP server»), правка — по имени строки.
- `src/hooks/useMcp.ts` — `view`, `save(text)` (через `mcp_config_save`, отказ приходит в
  `error`), `connect(name)`, `setEnabled`, `setToolShown`.
- `src/components/Modal.tsx` — 420 px, `wide` 880 px, шапка, тело и подвал; тело
  прокручивается.
- Окно установки из каталога (`CatalogPage.tsx`, `InstallDialog`) — ближайший образец
  «показать запись перед тем, как её записать»: целая запись, поля `${NAME}`, строка о том,
  что файл перепишется в раскладке приложения.
- Чего нет: ни одного пошагового экрана. Полоса стадий в `MeetingsPage` («Step 3 of 4») —
  это индикатор хода работы, а не навигация, и переиспользовать её нечего.
- Бэкенд для фичи не нужен: `mcp_config_save` уже проверяет и перезаписывает файл,
  `mcp_server_connect` уже запускает сервер.

## Решения

### 1. Экран — отдельный компонент `McpInstall` в широком `Modal` (880 px), а не страница

Задача возвращает пользователя туда же, откуда он пришёл, — в панель MCP; страница (как
Catalog) отнимает панель и прячет уже настроенные серверы. Широкая модалка — то, что вообще
позволяет две колонки. Отвергнуто: страница в `pages.tsx`; отвергнуто: оставить узкое окно и
добавить в него одно поле вставки — тогда ни колонок, ни шагов.

### 2. Вставка разбирается теми же правилами, что вставка в редактор файла, и результат — поля, а не текст

`parseLoose` и тот же признак «это сервер» (`mcpServers`, голая карта записей с `command` или
`url`, либо одна запись), что в `mergeMcp`: один и тот же сниппет ведёт себя одинаково, куда
бы его ни вставили. Дальше запись раскладывается в поля тем же кодом, что читает файл:
отображение внутри `readMcpServer` выносится в `serverFields(name, entry)`, и вставленный
сервер проходит через него же. Отвергнуто: свой разбор у экрана — два набора правил на один
формат расходятся на первой правке.

Одна запись без имени (`{"command": "npx", …}`) принимается: имя тогда обязательно на втором
шаге, как и сегодня у новой записи.

### 3. Ключи, для которых у формы нет поля, переживают установку

Сегодня `writeMcpServer` сохраняет незнакомые ключи только у записи, которая уже лежит в
файле. У вставленной их может быть много — `disabled`, `type: "stdio"`, `toolExposure`, ключи
другого клиента, — и установка не должна их терять: вставленный «выключенный» сервер иначе
молча включится. Поэтому остаток JSON едет в полях (`extra`) и ложится в запись поверх того,
что в файле; для правки `extra` и есть то, что в файле, — поведение не меняется. Отвергнуто:
потерять остаток и сказать «поправьте после» — это тихая потеря данных в общем файле.

### 4. Занятое имя — не тупик, а замена, сказанная вслух

Сегодня форма отказывает новой записи на занятое имя, а редактор файла при вставке заменяет
сервер и говорит об этом. Экран ведёт себя как редактор: шаг «обзор» пишет «заменит сервер
`<имя>` в `mcp.json`», и установка идёт с `previous = <имя>`, то есть на место записи. Вставка
сниппета с именем, которое уже настроено, — обычное дело (обновить команду): отказом тут
только заставляли бы удалять сервер руками. Отвергнуто: отказ, как у формы.

### 5. «Обзор» показывает ровно ту запись, которая уйдёт в файл

Запись в том виде, в каком её напечатает `writeMcpServer` (`JSON.stringify` с отступом), путь
файла и уже существующая строка о том, что приложение пишет файл в своей раскладке. Отвергнуто:
ставить прямо со второго шага — файл общий с другими клиентами и перезаписывается целиком,
запись надо увидеть.

### 6. Поля — в две колонки, шаги — полосой сверху

Полоса из трёх шагов («Paste», «Connection», «Review»), текущий отмечен, к пройденным можно
вернуться кликом. Внутри шага — две колонки: слева «как запускается» (имя, транспорт, команда
и аргументы либо URL и заголовки), справа «как им пользуется агент» (окружение, вес и таймаут,
доступ к инструментам, результаты). При узком окне колонки складываются в одну — модалка не
должна ломаться на 880 px и меньше. Отвергнуто: карусель из трёх панелей рядом — каждый шаг
это 400–800 px, три сразу дадут горизонтальную прокрутку внутри окна; отвергнуто: одна
длинная форма с якорями — тогда «шаги» только украшение. Если имелась в виду именно карусель,
это другой экран: открытый вопрос 3.

### 7. Правка существующего сервера — тот же экран со второго шага

Вставлять нечего, поэтому шагов два: «Connection» и «Review». Отвергнуто: две формы для одних
и тех же полей — они разойдутся, а правило «что форма не понимает, то переживает запись»
придётся держать в двух местах.

### 8. Дверь в редактор всего файла остаётся

Ссылка «Edit as JSON» — в подвале каждого шага, переключает окно на редактор, как сегодня.
Отвергнуто: убрать — именно редактор чинит файл, когда тот не разбирается, и на него
ссылается сообщение формы.

  причина отказа), `extra` в `McpServerFields` и его запись в `writeMcpServer`.
- `src/components/EntryField.tsx` + `.css` — обёртка поля, сейчас приватная в

  из двух мест несёт свой CSS, а не берёт у соседа).
- `src/components/McpInstall.tsx` + `McpInstall.css` — шаги, колонки, обзор.
- `src/App.tsx` — вместо `McpServerForm` в модалке `McpInstall`; `EntryDialog` не меняется.
- Тесты — `src/__tests__/configEntries.test.tsx` (разбор и запись) и новый

## Нарезка

**MI-1. Вставка → поля, без экрана.** `serverFields`, `pastedServers`, `extra` и его запись.
Тесты: целый `{"mcpServers": …}`, голая карта, кусок `"name": {…},` без скобок, запись без
имени, несколько записей, объект без `command` и `url` — отказ с причиной, битый JSON —
позиция из `jsonError`, `disabled` и `type` из вставки доезжают до файла, порядок серверов в
файле не меняется.

**MI-2. Экран.** `McpInstall` с тремя шагами и двумя колонками; открывается из панели на
добавление и на правку (со второго шага). Тесты: вставка заполняет поля и показывает запись на
обзоре; занятое имя — «заменит» и установка с `previous`; «Start from scratch» — второй шаг с
пустыми полями; возврат на шаг назад сохраняет набранное; «Edit as JSON» отдаёт окно
редактору; Install зовёт `save` с текстом, в котором есть сервер, и закрывает окно.

**MI-3. Документы.** `docs/README.md`, строка в `CHANGELOG.md`, абзац UI в
`docs/17-mcp-http.md`, статус этого плана.

## Вне плана

- Установка нескольких серверов одной вставкой — открытый вопрос 1.
- Кнопка «проверить соединение» до установки: `mcp_server_connect` запускает процесс, а первый
  `npx` скачивает пакет; это отдельный шаг с ожиданием и своими отказами.
- Каталог внутри экрана — за это отвечает страница Catalog.
- OAuth для HTTP-серверов — `docs/18-mcp-oauth.md`.
- Заглушки `${NAME}` (соглашение каталога): вставка оставляет их как есть — бэкенд их не
  раскрывает.

## Открытые вопросы

1. **Несколько серверов в одной вставке.** Рекомендую: экран ведёт один сервер, а найденные
   несколько показывает списком «какой настроить», с отсылкой к редактору файла для «вставить
   все как есть». Ставить все сразу — следующий шаг, если понадобится.
2. **Запускать ли сервер сразу после установки.** Сегодня добавленный стартует со следующим
   ходом Agent, а строка говорит «откройте её, чтобы запустить». Галочка «Start it now» на
   обзоре — это `connect` и его отказ в строке панели. Рекомендую без неё в первом заходе.
3. **Горизонтальность.** Прочитано так: шаги полосой сверху, внутри шага две колонки полей.
   Если имелась в виду карусель — панели шагов стоят рядом и сдвигаются влево, — это другой
   экран: шире, на узком окне превращается в свайп, и обзор тогда третья панель, а не вид.
4. **Правка существующего сервера** — тем же экраном со второго шага (рекомендую) или оставить
   нынешнюю форму, а экран открывать только на добавление?
