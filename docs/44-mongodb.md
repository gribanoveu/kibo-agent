# MongoDB: страница в духе Compass и инструменты агента

**План, предложен 2026-10-26. Ждёт одобрения** — ниже раздел «Что решить до начала».
Кода в документе нет — только решения и этапы.

## Суть

Новая функция `mongodb`, которую пользователь включает в Catalog, как Meetings или
Knowledge (`docs/33-features.md`). Она добавляет страницу MongoDB: пользователь подключается
к своим серверам и делает то, что в Compass делают каждый день, — смотрит базы и коллекции,
ищет документы фильтром, правит, добавляет и удаляет их, запускает агрегации, смотрит
индексы. Строки подключения хранятся так же, как API-ключи провайдеров.

У функции будет набор инструментов для агента. В этой работе — только их **заготовка**:
имена, аргументы, какие из них пишут, где они работают. Модели они не предлагаются.

## Что входит, а что нет

| Входит | Не входит (пока) |
|---|---|
| Соединения: добавить, переименовать, сменить строку, проверить, удалить | SSH-туннель, сертификат файлом, вход через Kerberos/LDAP/AWS — всё, что не помещается в строку подключения. Опции в самой строке (`tls=true`, `authSource`, `replicaSet`) работают |
| Дерево: базы с размером, коллекции; view и timeseries помечены | Статистика коллекции, размеры индексов |
| Документы: фильтр, проекция, сортировка, страницы по 10/20/50/100, сколько всего совпало | Табличный вид, дерево по полям, правка одного поля прямо в списке |
| Вставка (документ или массив), правка документа целиком, клон, удаление одного документа | Массовые `updateMany`/`deleteMany` со страницы |
| Агрегации: конвейер текстом, первые 200 результатов | Конструктор по стадиям, превью каждой стадии |
| Индексы: список; создание (ключи, имя, unique) и удаление | TTL и partial при создании (в списке видны), `hidden` |
| Создать коллекцию (база появится вместе с ней), удалить коллекцию | Удалить базу целиком, анализ схемы, explain, импорт/экспорт |
| Заготовка инструментов агента | Сами инструменты, роль, бенч — отдельные этапы после |

## Решения (предлагаются)

| Вопрос | Предложение | Почему |
|---|---|---|
| Включение | Функция `mongodb` в Catalog, по умолчанию выключена; страница в `PAGES` с `feature: "mongodb"` | Новый сетевой клиент нужен не всем. Выключение прячет страницу, соединения остаются; «Delete data» удаляет их файл |
| Где хранятся соединения | Один зашифрованный файл `~/.kibo/mongo_connections.enc`: список `{id, name, uri}` под мастер-ключом приложения, своё назначение `SecretPurpose::MongoConnections` | Пароль живёт внутри строки подключения, поэтому шифруется вся строка. Тот же мастер-ключ и формат, что у `llm_credentials.enc`. Своё назначение — чтобы файл ключей нельзя было подложить вместо списка соединений |
| Что видит окно | Только `{id, name, address}`, где в `address` пароль и опции вроде `*password*`, `*token*`, `*secret*`, `authMechanismProperties` заменены на `•••` | Как с API-ключами: окно знает, что соединение есть и куда ведёт, но не пароль. В форме правки поле строки пустое — пустое значит «оставить сохранённую» |
| Файл соединений не открывается | Ошибка с подсказкой (Delete data в Catalog), записывать поверх нельзя | Соединений может быть много — молча потерять их хуже, чем попросить пользователя |
| Драйвер | Официальный крейт `mongodb` 3.x, блокирующий API (`sync`), TLS — rustls на ring, как у `kube` | Каждая команда и так выполняется в `spawn_blocking`. Писать протокол самим несоразмерно; `mongodb+srv://` нуждается в его DNS-резолвере |
| Клиенты | Один клиент на строку подключения, хранится в состоянии приложения; ключ — хеш строки | Клиент — это пул и рукопожатие (TLS, SCRAM); создавать его на каждый запрос дорого. Изменённое соединение само получает новый клиент |
| Таймауты | Поиск сервера и подключение — 6 с; запрос на сервере — `maxTime` 30 с | Неверный хост должен отвечать за секунды, а не за 30 с драйвера; тяжёлый запрос останавливается на сервере |
| Синтаксис запросов | Как в mongosh: ключи без кавычек, строки в любых кавычках, `ObjectId('…')`, `ISODate('…')`, `NumberLong(…)`, `NumberDecimal('…')`, `UUID('…')`, `/regex/i`. Разбирает чистая функция в `domain/`, ошибка — со строкой и столбцом | Так пишут фильтры все, кто работал с Compass и mongosh. Драйвер видит только Extended JSON |
| Как показывается документ | Тем же синтаксисом mongosh, из канонического Extended JSON | Документ, открытый на правку и сохранённый без изменений, сохраняет типы: `Int64` пишется `NumberLong(5)`, `Double` — `5.0`. Обычный JSON это теряет |
| Правка документа | Замена целиком по `_id`; поменять `_id` нельзя; если документа уже нет — понятная ошибка | Самый простой способ, который не теряет данных. Правка одного поля — позже |
| Агрегации | Не больше 200 результатов | Конвейер может вернуть всю коллекцию |
| Канал событий | Не нужен | Меняет показанное только сама страница. Канал `mongo:changed` появится вместе с инструментами, которые пишут |
| Слои | `domain/mongo.rs` (типы, маска, разбор), `infra/mongo_store.rs` (файл), `infra/mongo_client.rs` (драйвер), `services/mongo.rs` (сценарии), `commands/mongo.rs`; в окне `lib/mongo.ts`, `hooks/useMongo.ts`, `components/MongoPage.tsx` | По правилам AGENTS.md. Трейта нет: второй реализации нет, инструменты агента будут звать тот же сервис |
| Политика данных | `infra/mongo_client.rs` — единственный файл, которому разрешена сеть к MongoDB; строка в `08-data-policy.md` | Новый выход данных: сервер, который назвал сам пользователь. Модели ничего не уходит, пока нет инструментов |

## Инструменты агента — заготовка

Форма инструментов описана здесь, в коде её нет: модуль появится вместе с самими
инструментами, по контракту AGENTS.md. Пока ни один не `ToolName`, ни роль, ни режим не
могут их предложить, а манифест функции называет пустой список инструментов.

| Инструмент | Что будет делать | Пишет |
|---|---|---|
| `mongoDatabases` | базы закреплённого соединения с размерами | нет |
| `mongoCollections` | коллекции и view закреплённой базы | нет |
| `mongoFind` | документы по фильтру, с проекцией, сортировкой, `limit` ≤ 50 | нет |
| `mongoCount` | сколько совпало | нет |
| `mongoAggregate` | результаты конвейера; `$out` и `$merge` — отказ | нет |
| `mongoIndexes` | индексы коллекции | нет |
| `mongoSchema` | поля выборки из 100 документов, их типы и частота | нет |
| `mongoInsert` | вставка документа или массива | да |
| `mongoUpdate` | обновление по фильтру; `many: true` — всех совпавших | да |
| `mongoDelete` | удаление по фильтру; `many: true` — всех; пустой фильтр — отказ | да |

Заранее принятые правила для них:

- **Где работают.** Соединение и базу выбирает пользователь у чата, как контекст и
  namespace у роли Kubernetes. Модель называет только коллекцию.
- **Одобрение.** Пишущие идут через карточку подтверждения: коллекция, фильтр и сколько
  документов будет затронуто.
- **Что уходит модели.** До 50 документов, каждый не длиннее 4000 символов; значения полей
  с именами вроде `*password*`, `*token*` заменяются на `<redacted>`.
- **Лог вызовов.** Поля с документами вырезаются, как `manifest` у `kubeApply`.

## M-8: читающий инструмент агента

Решено 2026-10-28, вместо роли с закреплённым соединением из заготовки выше.

| Вопрос | Решение | Почему |
|---|---|---|
| Где предлагается | Во всех режимах папки (Agent, Plan, Ask, Review, помощник `explore`) и у ассистента в Chat, пока функция включена. В режиме Agent ждёт за `toolSearch` — в каждый запрос не попадает | Вопрос о базе чаще всего возникает рядом с кодом, который в неё пишет: «почему заказ не нашёлся» — это и код, и данные. Роль с закреплённой базой отвергнута: она отрезает агента от проекта. Ничего не пишет — значит, годится и для Plan, и для Ask |
| Сколько инструментов | Один, `mongo`, с `op`: `collections`, `schema`, `find`, `count`, `aggregate`, `indexes` — как `board` | Каждый инструмент — дюжина мест по контракту AGENTS.md; шесть читающих стоили бы шесть раз столько, а модель за `toolSearch` находит одно имя. Запись (M-9) — отдельный `mongoWrite`, потому что `is_mutating` — свойство инструмента, а не операции |
| Какие соединения видит модель | Только отмеченные пользователем «доступно агенту» (флажок в форме соединения, по умолчанию снят). Модель видит имя соединения, никогда строку | Боевую базу агент не трогает, пока пользователь сам её не открыл. Флажок дешевле роли и работает в любом режиме |
| Как модель находит коллекцию | `collections` без аргументов — открытые агенту соединения и их базы; с `name` — коллекции, в имени которых есть эта строка, по всем открытым соединениям и базам | Пользователь говорит «посмотри orders», а не «соединение prod, база shop». Сервер, который не ответил, попадает в ответ строкой и поиск не роняет. Найдено больше 50 — сказано, сколько ещё |
| Как называется место | `connection` — имя соединения, `database`, `collection`. Два соединения с одним именем — ошибка с просьбой переименовать | Имя — то, что пользователь видит на странице и пишет в чате; id модели ни о чём не говорит |
| `schema` | `$sample` из 100 документов → поле (с вложенными через точку), его типы BSON и в скольких документах встретилось | Чтобы фильтр был написан по настоящим полям и типам: `ObjectId` против строки — частая ошибка |
| `find` | Фильтр, проекция, сортировка в синтаксисе mongosh — тем же разбором, что у страницы; `limit` ≤ 50, по умолчанию 20. Курсор закрывается сразу | Модели не нужна следующая страница: она уточнит фильтр |
| `aggregate` | До 50 результатов; конвейер с `$out` или `$merge` — отказ (`writing_stage`) | Запись — только через M-9 и карточку |
| Что уходит модели | Документы — mongosh-текстом, каждый не длиннее 4000 символов (длиннее — обрезан с пометкой); значения полей с именами вроде `password`, `token`, `secret`, `apiKey` — `<redacted>`, пароль в URL внутри строки — тоже | Как у инструментов Kubernetes (`kube_view::redact_text`) |
| Лог вызовов | Аргументы пишутся, результат — нет | Фильтр нужен, чтобы понять, что спросили; документы — чужие данные |
| Канал событий | Не нужен | Инструмент ничего не меняет |

Проверяется тестами: инструмент предлагается только при включённой функции; соединение без
флажка не видно ни в списке, ни в поиске, ни по имени; поиск по имени находит коллекцию в
другой базе и переживает сервер, который не ответил; `$out` отказан до сервера; секретное
поле и пароль в URL скрыты; длинный документ обрезан; `limit` больше 50 урезан. Живой тест
`live_server` — против настоящего сервера.

## Этапы

Каждый этап заканчивается зелёными `cargo test`, `bun test`, `bun run tsc --noEmit` и
мутационной проверкой нового кода (`docs/11-mutation-testing.md`).

| | Этап | Что делаем | Готово, когда |
|---|---|---|---|
| | M-0 | Этот план | Одобрен, открытые вопросы закрыты |
| | M-1 | Домен: соединение, вид для окна с маской пароля, проверка строки, разбор и печать синтаксиса mongosh, ошибки | Тесты: маска не пропускает пароль; каждый конструктор (`ObjectId`, `ISODate`, `NumberLong`…) читается; ошибка называет строку и столбец; документ, напечатанный и прочитанный обратно, сохраняет типы |
| | M-2 | Хранилище соединений под мастер-ключом, новое назначение шифрования | Тесты: пароля нет на диске открытым текстом; файл другого назначения не открывается; правка заменяет по id; нечитаемый файл не перезаписывается |
| | M-3 | Драйвер, сервис, команды; политика данных и список медленных команд | `data_policy` и `architecture` зелёные; живой тест против настоящего сервера (`#[ignore]`, запуск руками) проходит |
| | M-4 | Функция в Catalog; страница: соединения (форма, проверка, удаление) и дерево баз и коллекций | Тест страницы: строка уходит в бэкенд один раз и возвращается только маской; при правке без строки она не отправляется |
| | M-5 | Документы: поиск, страницы, вставка, правка, клон, удаление | Тест страницы: фильтр по Enter, следующая страница, ошибка разбора показана как есть, удаление только после вопроса |
| | M-6 | Агрегации и индексы | Тест страницы: индексы читаются при открытии вкладки, `_id_` удалить нельзя |
| | M-7 | Заготовка инструментов агента, CHANGELOG, документы | Тесты заготовки: имена уникальны и не заняты; пишут только три; база в аргументах не принимается |

Позже, отдельными планами после одобрения этого:

| | Этап | Что делаем |
|---|---|---|
| | M-8 | Читающий инструмент `mongo` в любом режиме и у ассистента; флажок «доступно агенту» у соединения (раздел «M-8» ниже) |
| | M-9 | Пишущие инструменты с карточкой подтверждения и подсчётом затронутых документов; канал `mongo:changed` |
| | M-10 | Бенч: коллекция с испорченными данными на локальном сервере, задача, скрытая проверка — как `kube_bench` |

## Что решить до начала

1. **Функция выключена по умолчанию и живёт в Catalog** — как остальные. Согласны?
2. **Объём страницы.** Сейчас в первой версии есть запись: вставка, правка, удаление
   документов, создание и удаление индексов и коллекций. Альтернатива — первая версия
   только для чтения, запись отдельным этапом.
3. **Защита боевых баз.** Добавить ли соединению флажок «только чтение», при котором страница
   (а потом и агент) не пишут в него? Предлагаю добавить в M-2/M-4 — дёшево и полезно.
4. **Синтаксис mongosh** вместо строгого JSON. Строгий JSON проще, но в нём нельзя написать
   `ObjectId('…')` и даты так, как их пишут.
5. **Заготовка инструментов.** Предлагается только описание в этом документе, не
   подключённое к `ToolName` (модуль `domain/mongo_tools.rs` был и удалён на ревью: код без
   вызывающих). Альтернатива — подключить все десять как `ToolName` с
   заглушками, но никому не предлагать: больше кода сейчас, меньше потом.
6. ~~**Где агент получит инструменты (M-8).** Отдельная роль «MongoDB» в режиме Chat с
   закреплённым соединением — или ещё и в режиме Agent, рядом с кодом проекта?~~ — решено
   2026-10-28: в любом режиме и у ассистента в Chat, без роли; соединение модель находит
   сама по имени коллекции, среди отмеченных «доступно агенту» (раздел «M-8» ниже).

## Черновик M-1…M-7: как проверен

Код M-1…M-7 написан до одобрения плана, 2026-10-26, и лежит в ветке как черновик: после
ответов на вопросы выше он правится под них. `cargo test` (кроме пяти тестов, которые в
контейнере падают и без него: веса модели не скачаны из LFS, проверки прав под root, нет
шелла для терминала), `bun test`, `bun run tsc --noEmit`.

**Мутации: двадцать, все пойманы** — маска пароля, хост после последнего `@`, маска
токенов в опциях, строка без хоста, `5.0` как целое, `Double(5)` без `.0`, `Int64` как
`Int32`, `/` в регулярке, `ObjectId` не из hex, столбец ошибки, пустой массив на вставку,
дубль соединения при правке, нечитаемый файл как пустой, файл ключей как список
соединений, запись поверх нечитаемого файла, правка без строки стирает её, пустая строка
как новая, строка без схемы, пустой документ на замену, плохой фильтр как пустой.

Не поймано сразу две: `ObjectId` из 24 символов не-hex (тест знал только короткую строку) и
нечитаемый файл соединений, прочитанный как пустой список (тесты знали только «файла нет»).
Закрыты тестами `a_mistake_says_where_and_what` (строка из `z`) и
`a_file_that_cannot_be_read_says_so` (каталог на месте файла).

`infra::mongo_client::live_server` против настоящего сервера не запускался: в контейнер
сервер не скачать. Запуск:

```bash
cd src-tauri && KIBO_MONGO_URI=mongodb://localhost:27017 cargo test live_server -- --ignored --nocapture
```
