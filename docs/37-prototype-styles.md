# Стили Prototype: дизайн-система на выбор, первая — core-ds

План, предложен 2026-10-21, кода нет. В чате с ролью Prototype рядом с выбором роли —
второй список, **Style**: «Без стиля» по умолчанию и «Альфа-Бизнес (core-ds)». Выбран стиль —
модель получает его промпт (правила вида, цвета, типографика, самопроверка), доступ к
библиотеке компонентов в превью и справку по компонентам по требованию. Не выбран —
всё как сейчас, ни одного лишнего токена.

## Что уже есть

| Что | Где | Как пригодится |
|---|---|---|
| Второй список на вкладке над полем ввода, только для одной роли | `PlainChat.tsx`: Kubeconfig рядом с Role у Kubernetes; `KubePin` идёт с каждым ходом | Тот же приём: Style рядом с Role у Prototype |
| Библиотеки для страниц модели | `scripts/build-prototype-libs.ts` → `src-tauri/prototype-libs/` (3,4 МБ), отдаются по `/lib/`, import map в промпте | Ещё один бандл: `core-ds.js` + `core-ds.css`, React внешний, как у lucide |
| Справка по требованию | runbook'и Kubernetes: строка-каталог в промпте, полный текст — `kubeRunbook { name }` (`domain/runbooks.rs`) | Тот же приём для компонентов: каталог в промпте, пропсы и пример — по вызову |
| Промпт роли | `ChatRole::prompt()`, `PROTOTYPE_PROMPT` в `domain/chat_role.rs` | Стиль — раздел, дописанный к нему, когда выбран |

## Что нашлось у core-ds

- **Библиотека:** `@alfalab/core-components` 50.x, MIT, peer — React 16.9…19 (наш 19
  подходит). Сборка ESM: компонент — JS, который делает `import './x.css'`; CSS обычный,
  классы с хешами, цвета через CSS-переменные (`--color-light-*`), палитра bluetint по
  умолчанию. `Bun.build` такие импорты собирает в один `.css` рядом с `.js` — сборщик
  менять не придётся.
- **Справка для агентов уже есть у самих авторов:** пакет `@alfalab/core-components-mcp`
  (0.2.4) — MCP-сервер с инструментами `component_list` / `component_info` /
  `component_demo`. Внутри у него снимок данных: 99 JSON, по одному на компонент
  (описание по-русски, 2213 пропсов с типами и умолчаниями, демо, changelog), всего 1,6 МБ,
  и `SKILL.md` (~2,4 тыс. слов: импорты, варианты desktop/mobile, темы, палитры).
- **Context7** (`/core-ds/core-components`) индексирует тот же репозиторий — те же README,
  stories и этот же `SKILL.md`. Нового по сравнению с пакетом там нет.

## Решения

### 1. Стиль — данные, а не код

Встроенный стиль — папка `src-tauri/prototype-styles/<id>/`, ресурс бандла:

- `style.md` — твой промпт, почти как есть (правки — в п. 4);
- `components/<name>.md` — справка по компоненту (п. 3);
- `lib/` — готовые для браузера файлы библиотеки: ESM-модули, CSS, шрифты;
- шапка `style.md` (front matter, как у ранбука): имя для меню, строка-подсказка, что
  дописать в import map и какие `<link>` поставить в `<head>`. Описание не в коде — значит,
  встроенный стиль и стиль пользователя устроены одинаково.

Второй встроенный стиль добавляется ещё одной папкой, без кода. Тот же формат читается и
из папки пользователя — стили расширяют режим Prototype так же, как ранбуки роль
Kubernetes (п. 6).

### 2. Выбор — список Style на вкладке, значение у чата

- Виден только у Prototype, рядом с Role, тем же `Dropdown`. По умолчанию «Без стиля».
- Значение уходит с каждым ходом, как `KubePin`, и хранится в записи чата рядом с `role`.
- **Менять можно в любой момент**, в отличие от роли: со следующего хода модель
  просто получает другой раздел промпта. Уже сделанные страницы остаются как есть — это
  стоит сказать подсказкой у списка.

### 3. Справка по компонентам — снимок из MCP-пакета, по требованию

- **Не Context7 во время работы:** превью и приложение работают без сети, у Context7 нужен
  ключ и запрос на каждый ход, а данные там те же.
- **Не их MCP-сервер:** ему нужны `npx` и сеть, и MCP-инструменты роли Prototype не
  предлагаются. Остаётся запасным путём для Assistant, если когда-нибудь понадобится.
- **Снимок при сборке.** `scripts/build-prototype-libs.ts` (или соседний скрипт) берёт
  `dist/data/*.json` из `@alfalab/core-components-mcp` (devDependency) и пишет компактный
  `components/<name>.md`: описание, пропсы одной строкой каждый (`view: "accent" |
  "primary" | … = "secondary" — Тип кнопки`), один-два коротких демо. Changelog
  выбрасываем. Версия пакета записывается в снимок.
- **В промпт** — только каталог: имя и одна строка на компонент, ~100 строк.
- **Полная справка** — новый инструмент `styleDoc { component }`, как `kubeRunbook`:
  отдаёт `.md` из снимка. Предлагается роли Prototype всегда; без выбранного стиля
  отвечает «стиль не выбран». Это новый инструмент, поэтому он проходит всю таблицу
  мест из AGENTS.md (вариант `ToolName`, разбор, редакция в логе, подпись и иконка).

Вариант без нового инструмента — класть справку в папку чата для `readFile` — отброшен:
папка сохраняется версиями при `present`, справка засоряла бы каждую.

### 4. Библиотеки в превью

- `core-ds.js` (ESM, `react`, `react-dom`, `react/jsx-runtime` — внешние, из того же
  React, что уже в бандле) и `core-ds.css` (стили компонентов, переменные bluetint,
  типографика). В import map: `"@alfalab/core-components": "/lib/core-ds.js"`.
- **Шрифт Onest (лицензия OFL)** — `woff2` 500/600 и `onest.css` с `@font-face` в
  `prototype-libs/`. Твой промпт берёт Onest из Google Fonts, а у превью сети нет. Это
  единственная содержательная правка промпта: «Onest — `<link href="/lib/onest.css">`».
- **Иконки** — lucide, который уже есть, с `strokeWidth={2.2}`: твой промпт описывает
  ровно такие иконки (линейные 24×24, скругления round). `@alfalab/icons-glyph` —
  тысячи иконок и мегабайты; брать, только если нужна именно их графика.
- `MIT` core-components и `OFL` Onest — файлами лицензий рядом, как у campplus.
- **Сколько весит — первое, что меряем** (этап S-1). Если вся библиотека слишком
  тяжела для установщика (сейчас все библиотеки прототипов — 3,4 МБ), собираем
  отобранный список: кнопки, поля, select, чекбокс, переключатель, вкладки, таблица,
  типографика, статусы, плашки, тост, боковая панель, модалка, шаги, суммы, даты, ссылка,
  разделитель, сетка/отступы, лоадеры, поповер, аккордеон — около 40 из 99. Каталог в
  промпте тогда — только собранные.

### 5. Как это читает модель

Раздел стиля дописывается в конец `PROTOTYPE_PROMPT`:

1. **Правила вида** — `style.md`.
2. **Как подключить:** строки import map, `<link>` на `core-ds.css` и `onest.css` и пример
   страницы — шаблон React-страницы из промпта, но с `Button` и `Typography` из core-ds.
3. **Когда что:** компонент core-ds, если такой есть в каталоге; переменные из `style.md`
   — для раскладки и того, чего в библиотеке нет. Tailwind остаётся, но при стиле
   цвета, радиусы и шрифты берутся из переменных, а не из палитры Tailwind.
4. **Каталог компонентов** и правило: «перед первым использованием компонента —
   `styleDoc`».

Для презентации (обычный HTML без React) действуют только `style.md` и шрифт.

**Цена:** твой промпт — ~7 тыс. символов, около 2,5–3 тыс. токенов; каталог — ещё ~1,5–2
тыс. Платит только чат с выбранным стилем; кэш промпта у провайдеров это сглаживает.

### 6. Стили как расширение — по образцу ранбуков

Стиль — папка, а не код, поэтому её можно принести так же, как ранбук или skill. Режим
Prototype расширяется без новой сборки приложения: правила вида, библиотека
компонентов и справка к ней приходят вместе.

**Где лежат.** Встроенные — ресурс бандла (`prototype-styles/`). Свои —
`~/.kibo/prototype-styles/<id>/` в том же формате (п. 1). Список Style собирается как
`runbooks::merged`: свой стиль с id встроенного заменяет его, остальные добавляются.
Папка перечитывается при открытии списка и перед ходом, как папка ранбуков: новый стиль
виден без перезапуска.

**Как превью отдаёт библиотеку стиля.** `artifact://` сейчас отдаёт `/lib/<file>` из
`prototype-libs`. Добавляется `/lib/styles/<id>/<file>` из `lib/` выбранного стиля — с той
же проверкой пути, что у `/lib/` (`prototype_protocol.rs` уже отказывает `../`). Сети
у превью по-прежнему нет: всё, что нужно стилю, лежит в его папке. Экспорт в один HTML
(`prototype_export.rs`) вшивает файлы стиля так же, как библиотеки.

**Библиотека приходит собранной.** На машине пользователя нет ни `node`, ни `bun`, и
приложение npm-пакеты не собирает. Стиль несёт готовые ESM-файлы, где `react`,
`react-dom` и `react/jsx-runtime` — внешние: так компоненты берут тот же React, что и
страница, а с двумя копиями React хуки ломаются. Готовит их скрипт
`scripts/build-prototype-style.ts <npm-пакет> <папка>` — тот же `Bun.build`, что у
core-ds в S-1. Справку `components/*.md` он снимает с данных пакета, если они есть (как у
core-ds MCP), иначе её пишут руками. Без справки стиль тоже работает: остаются правила
`style.md` и библиотека, но нет `styleDoc`.

**Как доставляется.** В каталоге (`docs/32-catalog.md`) — новый вид `prototype-style`:
многофайловый, как skill, ставится в `~/.kibo/prototype-styles/<id>/`. Ограничение на
размер — своё: в стиле есть бандлы JS и шрифты, ему мало того, что достаточно skill.
Можно и вручную — положить папку.

**Доверие — как у ранбуков и skills из каталога.** `style.md` попадает в промпт модели,
поэтому стиль ставят из источника, которому доверяют. JS стиля исполняется только в
превью: в `<iframe sandbox>` без same-origin, без IPC и без сети — с той же изоляцией,
что и код, который пишет сама модель. Приложению он ничего не добавляет.

**Что не делаем.** Не тянем пакеты из npm во время работы и не даём стилю своих
инструментов: `styleDoc` общий и читает `components/` выбранного стиля.

## Открытые вопросы

1. **Менять стиль посреди чата** — предлагаю да (п. 2). Или запереть, как роль?
2. **Вся библиотека или отбор** — решим по замеру в S-1.
3. **Иконки** — lucide с толщиной 2.2 (п. 4) или иконки Альфы?
4. **Мобильные варианты.** Компоненты core-ds бывают desktop и mobile. Предлагаю брать
   responsive-сборку (выбирает по ширине) и не усложнять.
5. **Лимит на размер стиля** в каталоге — сколько допустимо (S-6)?
6. **Где ещё нужен стиль.** Только Prototype или потом и Assistant для схем и
   мини-страниц? Пока только Prototype.
