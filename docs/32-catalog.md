# Каталог: skills, команды, ранбуки, MCP и хуки из общего источника

План, CT-0 и CT-1 сделаны. Пользователь видит на странице Catalog (пункт в боковой панели под Agent и Chat) список того, что выложено в каталоге, и ставит
нужное одной кнопкой. Каталог — публичный git-репозиторий. Приложение читает его по HTTP,
как статические файлы: без `git` на машине, без своего сервера и без авторизации.

Кода в документе нет — только решения.

## Исходная точка

**Это то, что vision §1.4 уже называет точками расширения:** «Не делаем свой язык плагинов.
Точки расширения — MCP и skills-файлы». Каталог не добавляет ни новой точки расширения, ни
формата. Он только доставляет файлы, которые приложение уже умеет читать. Это не
`16-extensions.md`: там модули, собираемые в бинарник, здесь — файлы, которые ставят во время
работы.

**Все пять видов уже лежат на диске в известном формате:**

| Вид | Формат | Куда ставится | Кто читает | Где видно в UI |
|---|---|---|---|---|
| Skill | Папка `<name>/SKILL.md` и файлы рядом | `~/.kibo/skills/<name>/` | `infra/skills_store.rs` | Панель Skills, Settings → Skills |
| Команда | `<name>.md` | `~/.kibo/commands/` | `infra/slash_commands_store.rs` | Меню `/` |
| Ранбук | `<name>.md` | `~/.kibo/runbooks/kubernetes/` | `infra/runbooks_store.rs` | Роль Kubernetes |
| MCP-сервер | Запись `mcpServers` | `~/.kibo/mcp.json` | `infra/mcp_config.rs` | Панель MCP |
| Хук | Фрагмент `hooks` (формат Claude Code) | `~/.kibo/hooks.json` | `infra/hooks.rs` | Панель Hooks |

Skills, команды и ранбуки — отдельные файлы: их установка сводится к копированию. MCP и хуки
живут в общем файле, поэтому их запись вливается в этот файл.

**Что уже есть и пригодится:**
- `infra/http_agent.rs` — `ureq` с корпоративным CA из настроек, так что каталог во внутренней
  сети с собственным сертификатом заработает без доработок;
- `services/text_diff.rs` — дифф для показа обновления;
- `blake3` — хэш содержимого, чтобы заметить локальную правку;
- `Modal` и `Dropdown` — подтверждение и фильтр;
- `mcp_config::change` — правка `mcp.json` из кода (с переформатированием, как у переключателя).

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Где хранится каталог | Публичный git-репозиторий. Авторы работают через PR, ревью — это модерация | Нет сервера, нет аккаунтов. Версия — коммит, история — `git log` |
| Как приложение его получает | HTTP GET по базовому URL: `<base>/index.json`, затем `<base>/<path>` каждого файла. Для GitHub `https://raw.githubusercontent.com/<owner>/<repo>/main/`, для GitLab `https://gitlab.com/<owner>/<repo>/-/raw/main/`, подойдёт и любой статический хостинг | Не нужен `git` на машине (на чистом macOS без Command Line Tools его нет) и новые зависимости: `ureq` уже есть. Скачивается только выбранное, а не весь репозиторий |
| Авторизация | Нет. Каталог публичный | В каталоге нечего прятать: skills и команды — это промпты, а секреты MCP лежат как заглушки `${NAME}` и вводятся при установке. Закрытый каталог — открытый вопрос, внизу |
| Где адрес каталога | Свой каталог приложения зашит: `domain::catalog::DEFAULT_SOURCE` = `https://raw.githubusercontent.com/gribanoveu/kibo-agent-catalog/main/`, он всегда первый и с пометкой Built-in. Остальные — `settings.json` → `catalogSources: ["<base url>", …]`, по умолчанию пусто; два написания одного адреса (`…/main` и `…/main/`) — один источник | Это не секрет, ему место среди обычных настроек. Можно указать несколько источников (общий и командный). Поля для ввода адреса на странице пока нет — до первого, кому нужен второй каталог |
| Индекс | `index.json` в корне репозитория. Собирает CI каталога или пишут руками; в CI каталога есть проверка, что индекс совпадает с папками | Иначе пришлось бы листать дерево — а это GitHub API с лимитом 60 запросов в час без токена и привязка к одному хостингу |
| Установка | Копия файлов на место, которое приложение и так читает. В `~/.kibo/catalog/installed.json` записываются источник, id, вид, `rev` и blake3 установленного содержимого | Ссылка на кэш или чтение прямо из каталога означали бы, что правка в чужом репозитории меняет поведение агента без ведома пользователя. Для хуков и MCP это запуск чужой команды |
| Обновление | Только по кнопке. В индексе `rev` новее записанного — в строке «Update», перед применением показывается дифф | Автообновление по той же причине: чужая правка не должна доезжать сама |
| Локальная правка | Если хэш файлов на диске не совпадает с записанным, перед обновлением предупреждаем, что правка будет перезаписана, и показываем дифф | Пользователь мог подогнать skill под себя |
| Когда читать индекс | При открытии вкладки и по кнопке «Refresh», условным GET с `If-None-Match`. Последний полученный индекс кэшируется в `~/.kibo/catalog/<blake3(base)>.json` вместе с его `ETag` | Правило AGENTS.md: без таймеров. Кэш показывает список и без сети, а ответ `304` (проверено в CT-0) делает обновление почти бесплатным |
| Свежесть | Свежий коммит в каталоге видно не сразу, а через время до `max-age` хостинга (raw GitHub — до 5 минут). Обходить это не нужно | Обойти можно только через SHA последнего коммита, а его без `git` даёт лишь GitHub API: лимит и привязка к GitHub. Для каталога пять минут — не задержка |
| MCP и хуки | Модальное окно со всей командой (`command` + `args`) или `url`, для хуков — событие и `matcher`. Ставится только после явного «Install» | Хук запускается на каждый вызов инструмента без карточки. По этой же причине `infra/hooks.rs` не читает хуки из репозитория |
| Секреты MCP | Значения `${NAME}` в `env` и `headers` — поля формы в том же окне. Введённое пишется только в `mcp.json` (он только для владельца). Пока хоть одно поле пусто, кнопка Install недоступна | Тот же путь, каким секреты попадают туда сейчас; новое хранилище не нужно. `${…}` — соглашение каталога: приложение их не раскрывает, и незаменённая заглушка ушла бы серверу как есть |
| Конфликт имён | Если skill, команда или MCP-сервер с таким именем уже есть и не из этого каталога — установка отказывает с объяснением. Переименования при установке нет | Чужой файл молча не перезаписывается. Переименование ломает ссылки внутри skill'а |
| Где в UI | Страница Catalog в боковой панели (`components/pages.tsx`, `CatalogPage.tsx`, заготовка уже есть): источники, список с фильтром по виду (`Dropdown`), в строке — Install / Update / Remove. Страница занимает всё справа от боковой панели, как режим Chat: без колонки панелей (`dock: false`), без кнопок в заголовке окна и без списка чатов в боковой панели. Установленное видно на самой странице | Каталог — это место, куда приходят выбирать, а не настройка; панели рядом только отвлекают от списка. Если понадобятся, это `dock: true` и `openPane` |

## Формат каталога

```
kibo-catalog/
  index.json
  skills/review/SKILL.md
  skills/review/checklist.md
  commands/changelog.md
  runbooks/kubernetes/tls-cert.md
  mcp/github.json
  hooks/block-force-push.json
```

```json
{
  "version": 1,
  "items": [
    { "id": "review", "kind": "skill", "name": "Code review", "description": "…",
      "rev": "1", "path": "skills/review", "files": ["SKILL.md", "checklist.md"] },
    { "id": "changelog", "kind": "command", "name": "/changelog", "description": "…",
      "rev": "1", "path": "commands/changelog.md" },
    { "id": "tls-cert", "kind": "runbook", "role": "kubernetes", "name": "TLS certificate rejected",
      "description": "…", "rev": "1", "path": "runbooks/kubernetes/tls-cert.md" },
    { "id": "github", "kind": "mcp", "name": "GitHub", "description": "…",
      "rev": "1", "path": "mcp/github.json" },
    { "id": "block-force-push", "kind": "hooks", "name": "Block force push", "description": "…",
      "rev": "1", "path": "hooks/block-force-push.json" }
  ]
}
```

Это содержимое настоящего каталога — [gribanoveu/kibo-agent-catalog](https://github.com/gribanoveu/kibo-agent-catalog),
базовый URL `https://raw.githubusercontent.com/gribanoveu/kibo-agent-catalog/main/`.

- `id` — имя, под которым позиция ставится: папка skill'а, файл команды или ранбука, ключ в
  `mcpServers`. Допустимы только `[a-z0-9-]`.
- `rev` — строка. Сравнивается на равенство, а не на «больше»: если она изменилась, значит,
  есть обновление.
- `files` бывает только у skill'а, пути в нём — относительно `path`. У остальных видов `path`
  указывает на единственный файл.
- `mcp/<id>.json` содержит одну запись `McpServerConfig`, без имени: имя — это `id`.
- `hooks/<id>.json` — объект `{"hooks": {"PreToolUse": [ … ]}}` в формате `hooks.json`.
- `version` — версия формата индекса. Индекс с незнакомой версией приложение не читает и
  объясняет почему, а не гадает.

## Установка и удаление по видам

| Вид | Install | Remove |
|---|---|---|
| Skill | `files` → `~/.kibo/skills/<id>/` | Удаляется папка `<id>` |
| Команда | → `~/.kibo/commands/<id>.md` | Удаляется файл |
| Ранбук | → `~/.kibo/runbooks/<role>/<id>.md`. Неизвестная `role` — позиция не показывается. Имя встроенного ранбука (`crashloop`, `network`…) разрешено, но строка говорит, что он заменит встроенный: свой файл заменяет встроенный по имени (`domain::runbooks`) | Удаляется файл, и снова действует встроенный |
| MCP | Ключ `<id>` добавляется в `mcpServers` с подставленными секретами | Удаляется ключ `<id>` |
| Хуки | Группы добавляются в конец списков своих событий | Удаляются группы, совпадающие с записанными при установке. Отредактированные пользователем группы остаются, и вкладка об этом говорит |

Запись в `mcp.json` и `hooks.json` переформатирует файл, как уже делает переключатель MCP
(`mcp_config::change`). Об этом нужно сказать в окне подтверждения: если файл писали руками,
его раскладка не сохранится.

## Что меняется в приложении

| Где | Что |
|---|---|
| `domain/catalog.rs` | Типы индекса и `installed.json`, разбор с проверками (ниже), расчёт состояния строки: не установлено / установлено / есть обновление / изменено локально / конфликт имени. Без I/O |
| `infra/catalog_http.rs` | GET индекса и файлов через `http_agent`, с лимитами размера. Новый сетевой модуль, поэтому он попадает в `data_policy::NETWORK_ALLOWED` |
| `infra/catalog_store.rs` | Кэш индекса, `installed.json`, запись файлов через `app_dir` |
| `services/catalog.rs` | Install / update / remove: скачать, проверить, положить, записать. Для MCP и хуков — через `mcp_config` и `hooks` |
| `commands/catalog.rs` | `catalog_list`, `catalog_refresh`, `catalog_preview` (дифф и команда для модального окна), `catalog_install`, `catalog_remove`; регистрация в `lib.rs` |
| `domain/settings.rs` | `catalogSources` |
| `src/lib/catalog.ts`, `src/hooks/useCatalog.ts` | Wrapper'ы команд; хук читает список при открытии вкладки и после каждого действия |
| `src/components/CatalogPage.tsx` | Страница (уже есть, пустая): источники, список, фильтр, модальное окно установки |
| `src/components/DataPolicy.tsx`, `docs/08-data-policy.md` | Новая строка «Каталог» |

После установки панели Skills, MCP и Hooks должны показать новую позицию. Если какая-то из них
не перечитывает свой список при показе, это исправляется в ней самой, без нового события:
каталог меняет те же файлы, что меняет и редактор панели.

## Что нельзя потерять

- **Пути из индекса — чужие данные.** `path` и `files` проверяются как относительные: без `..`,
  без абсолютных путей, без пустых сегментов. Итоговый путь обязан лежать внутри целевой папки.
  Иначе `"files": ["../../.zshrc"]` пишет куда угодно. Мутант без этой проверки должен ронять тест.
- **Лимиты.** Индекс — до 1 МБ, файл — до 1 МБ, в skill'е — до 100 файлов. Ответ сверх лимита
  дочитывать не нужно, позиция отказывает.
- **Только `https`.** `http` разрешён только для `localhost`, как предупреждение у MCP. Заголовков
  пользователя в запросе нет, поэтому переадресации разрешены. Если у каталога появится токен
  (открытый вопрос ниже), переадресации выключаются, как в `mcp_http.rs`.
- **Атомарность.** Skill сначала скачивается целиком во временную папку рядом и только потом
  переименовывается на место. Если обрыв случился посреди установки, половина skill'а не
  остаётся.
- **Исполняемых битов нет.** Файлы skill'а пишутся как обычные: скрипт из каталога запускается
  только через `runCommand`, а значит, через карточку подтверждения.
- **Skill — это тоже промпт от чужого.** Он может попросить модель выполнить что угодно.
  Отдельной защиты от этого нет: команды всё равно идут через гейт `runCommand` и
  `command_risk`. В строке позиции показывается источник, чтобы было видно, чей это текст.
- **Политика данных.** Хостинг каталога видит IP и то, какие позиции смотрели и ставили, а
  больше ничего: из рабочей папки ничего не уходит. Это строка в `08-data-policy.md` и на
  экране «Where your data goes»; тест `data_policy` должен упасть, пока строки нет.
- **Мутационная проверка** (`docs/11-mutation-testing.md`): проверка путей, сравнение `rev` и
  хэша, отказ при конфликте имени, удаление только своих групп хуков.

## Что показала проба (CT-0)

2026-10-12, [gribanoveu/kibo-agent-catalog](https://github.com/gribanoveu/kibo-agent-catalog), `curl` с macOS.

- **Индекс и все пять файлов отдаются.** `200`, `text/plain; charset=utf-8`, около 0,4–0,5 с на
  файл. Skill из нескольких файлов — несколько последовательных GET; на десятке файлов это
  секунды, параллелить пока не нужно. Отсутствующий файл — `404`.
- **Кэш.** `cache-control: max-age=300`, Varnish. Изменение индекса после `git push` стало видно
  через 4 мин 48 с. Параметр запроса (`?t=…`) кэш не обходит: это тот же объект.
- **Адрес с SHA коммита** вместо `main` отдал новое содержимое сразу после push.
- **`ETag` есть, `If-None-Match` даёт `304`** — обновление без изменений не скачивает индекс заново.
- **Хук `block-force-push`** проверен на JSON события, как его передаёт `infra/hooks.rs`: `git push -f`
  и `--force` — код 2, `--force-with-lease`, `git push origin main` и ветка с `-f` в имени — 0.
- **`${GITHUB_TOKEN}` в `mcp/github.json`** приложение само не раскрывает (в `mcp_config` и
  `mcp_rmcp` подстановки нет) — отсюда правило «Install недоступен, пока заглушка не заполнена».

## CT-1: как сделано и проверено

2026-10-12. Бэкенд: `domain/catalog.rs` (индекс, проверки путей и записей, адрес источника),
`infra/catalog_http.rs` (условный GET), `infra/catalog_store.rs` (кэш в `~/.kibo/catalog/`),
`services/catalog.rs` (источники, кэш вместо сети при ошибке), команда `catalog_list`. Окно:
`lib/catalog.ts`, `hooks/useCatalog.ts`, `CatalogPage.tsx` — список по видам через `ItemList`,
фильтр `Dropdown`, Refresh, «записей пропущено» под источником.

- **Ошибка в одной записи не прячет остальные:** запись становится строкой в `problems`.
  Индекс не читается целиком только если это не JSON или формат новее (`version` ≠ 1).
- **Без сети или при битом ответе** показывается последняя хорошая копия с пометкой, почему
  новее нет. Битый ответ (`<html>` вместо индекса) копию не затирает, и следующий запрос
  идёт с `ETag` хорошей.
- **Живой тест** `cargo test live_catalog -- --ignored`: настоящий каталог читается
  (5 записей, без проблем), повторный запрос — `304`. GitHub отдаёт слабый `ETag` (`W/"…"`),
  потому что ureq просит gzip, — `304` с ним работает.

**Мутации:** 36, все пойманы. Ломали: `http` на чужой хост и `127.0.0.1` не локальный,
`?`/`#` в адресе, `/` в конце; `..`, `.`, пустой сегмент и лишние символы в пути; любая
версия индекса; дубль между видами; файлы skill'а без проверки, расширение, `files` у не-skill'а,
skill без файлов; любая роль и ранбук без роли; пустые `name` и `rev`; `id` без проверки;
описание без `trim`; `ETag` не отправлен и не прочитан, `304` как ошибка, лимит ×4, `4xx` как
тело; кэш другого источника принят, один файл на все источники; без дедупликации, свой каталог
последним, битый индекс в кэш, время `304` не сохранено, `ETag` копии не послан, Built-in не
отмечен, ничего не сохранено, ошибка сети не показана.

Не поймано сразу: `https_only(false)` — `https`-источник отпускал на `http` по переадресации.
Закрыл тест `an_https_source_is_not_followed_to_plain_http`: TLS-сервер из тестов
`http_agent` (сертификат `testdata/tls/leaf`) отвечает `302` на `http`-адрес, и запрос
обязан упасть; для этого из `fetch_index` выделен `fetch_with` с агентом снаружи.

## Отвергнутые варианты

| Вариант | Почему нет |
|---|---|
| Свой сервер с API | Хостинг, деплой, аптайм и авторизация ради раздачи нескольких десятков файлов. Vision §1.4: облачного бэкенда нет. К тому же сервер видел бы, кто что ставит. Если понадобится, он будет отдавать тот же `index.json`, и клиент не изменится |
| `git clone` каталога | Нужен `git` на машине пользователя. `git2` собран без https (`default-features = false`), а включение https тянет OpenSSL на Linux. Клонируется всё, хотя нужен один skill |
| GitHub REST API (листинг дерева) | 60 запросов в час без токена, привязка к GitHub. Индекс в репозитории решает то же самое одним запросом с любого хостинга |
| Читать skills прямо из кэша каталога | Одна строка в `skills_store::user_dirs()`, но любой коммит в каталоге сразу меняет поведение агента, и никто этого не проверяет |
| Архив на позицию (`.tar.gz`) | Новая зависимость и распаковка с её собственными проблемами с путями. Список файлов в индексе проще и проверяется так же |
| Автообновление | Чужая правка, тем более хука или MCP-команды, не должна применяться без пользователя |

## Открытые вопросы

- Нужен ли источник по умолчанию (официальный каталог Kibo) или список источников пуст, пока
  пользователь не добавит свой?
- Закрытый каталог. Варианты в порядке простоты:
  - внутренняя сеть или VPN — без изменений в клиенте;
  - секретный URL — без изменений в клиенте;
  - токен в заголовке из keychain — переадресации выключаются;
  - вход через OAuth — когда будет сделан `18-mcp-oauth.md`.
  Делать, когда кто-то попросит.
- Проектный каталог: позиции из `.kibo/catalog` открытой папки, под `folder_trust`. Пока не
  нужен: у проекта уже есть свои `.kibo/commands` и skills.
- Официальный MCP Registry как ещё один источник, только для MCP. Нужно, если понадобится поиск
  по публичным серверам, а не только по курируемому списку.
