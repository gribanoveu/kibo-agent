# MCP-серверы по HTTP

> **2026-09-30.** Транспорт и протокол заменены на `rmcp` —
> [22-rmcp-migration.md](22-rmcp-migration.md). Конфигурация (F-7.4e) и интерфейс (F-7.4g)
> в силе; раздел про F-7.4f описывает клиент, которого больше нет.

Рабочий документ фичи F-7.4e…g: MCP-сервер, который не запускается командой, а живёт
по адресу (Streamable HTTP). Решения этапа 7 «Решения по MCP» (`06-port-plan.md`) —
имена, подтверждение, вес, отвал, лог — остаются в силе: меняется только транспорт.

## Что уже есть

- Всё выше транспорта от него не зависит: порт `McpClient` (`domain/mcp.rs`), пул и
  перезапуск (`services/mcp_servers.rs` — `Supervised::live` перезапускает, когда
  `is_alive()` = `false`), имена, подтверждения, вес, лог. Реализация одна —
  `StdioServer` (`infra/mcp_stdio.rs`).
- До F-7.4e HTTP отсекался одной проверкой в `problem()`: есть `url`, нет `command` —
  «HTTP servers are not supported yet»; `url` лежал в `extra`.
- `mergeMcp` во фронтенде сниппеты с `url` уже принимает.

## Главное решение: свой клиент на `ureq`, без `rmcp`

В этапе 7 записано «`rmcp` оправдан, когда дойдём до HTTP». Пересмотрено:

- HTTP-клиент `rmcp` стоит на `reqwest`/`hyper`/`tokio`, а `data_policy`
  (`no_dependency_exists_to_send_data_elsewhere`) запрещает `reqwest` и `hyper` прямо.
- Всё вокруг блокирующее; `ureq` уже в графе, с `http_agent` (корпоративный CA, тело
  не-2xx читается).
- Streamable HTTP — тот же JSON-RPC, где каждое сообщение — отдельный POST. Порядка
  250–300 строк.

## Решения (приняты пользователем 2026-09-25)

- **`http://` не на localhost — предупреждение, не отказ.** Сервер запускается, строка
  во вкладке говорит, что заголовки (токен) уйдут открытым текстом. Локальные адреса —
  `localhost`, `127.*`, `[::1]`.
- **`${ENV}` в `headers` не подставляется.** `mcp.json` уже owner-only и уже держит
  токены в `env`; заголовок с токеном — то же самое.
- **OAuth — позже.** До него `401` — ошибка сервера с пометкой, что нужен OAuth, которого
  ещё нет. Работают серверы с ключом в заголовке.

## Шаги

### F-7.4e — конфигурация (`domain/mcp.rs`)

- `McpServerConfig`: `url: Option<String>`, `headers: BTreeMap<String, String>` — формат
  Claude Code и Cursor (`"type": "http", "url", "headers"`); `type` остаётся в `extra`.
- `problem()`: ровно одно из `command` / `url`; `url` — `http`/`https` с хостом;
  `type: "sse"` отказ с причиной (старый транспорт, ниже).
- `McpServerItem.warning` — `http://` не на localhost. Не мешает запуску.
- `McpServerItem.command` для HTTP-сервера — URL. Заголовки не показываются нигде.
- Пока нет транспорта, корректная HTTP-запись остаётся строкой с причиной «not supported
  yet» — последней проверкой в `problem()`, которую F-7.4f удаляет.

**Сделано (2026-09-25).** Поверх плана: `url` с пробелами по краям отклоняется — транспорт
его не обрезает, значит и проверка не должна; предупреждение во вкладке — `note` строки
(видно в раскрытой), а собственная ошибка процесса (`failed`, `exited`) его перекрывает.
Форма сервера HTTP-запись пока не правит — F-7.4g.

**Мутации: 19, все пойманы** (17 в `domain/mcp.rs`, 2 в `panes.tsx`): оба поля сразу, ни
одного, `url` не проверяется, любая схема, URL без хоста, `type: "sse"`, регистр хоста,
каждый из трёх локальных адресов, предупреждение для `https` и для localhost, предупреждение
не доходит до строки, URL не в строке, `url`/`headers` пишутся в каждую запись, HTTP-запись
запускаема до транспорта; во вкладке — предупреждение не показано и перекрывает ошибку
процесса.

Не пойманы сразу два. «URL без хоста» выжил, потому что тест брал `https:///mcp`, который
`http::Uri` не разбирает вовсе, — закрыт случаем `http://:8080/mcp` (разбирается, хост
пустой). «Схема не приводится к нижнему регистру» — эквивалентный: `http::Uri` сам
приводит `http`/`https`; лишний `to_ascii_lowercase()` удалён.

### F-7.4f — транспорт (`infra/mcp_http.rs` + рефакторинг `mcp_stdio.rs`)

- **`Connection`**: разбор входящего из `read_in_background` вынести в
  `dispatch(message, &pending, send)` (ответ — ждущему, `ping` — ответ, прочие запросы
  сервера — отказ); второй конструктор `with_sender(send, timeout, describe_close)`.
  `initialize`, `request` с таймаутом и отменой, пагинация `tools/list`, `call_tool`,
  `notifications/cancelled` не дублируются. Stdio-тесты проходят без изменений.
- **`HttpServer::start(config, cancelled)`**:
  - каждое исходящее сообщение — POST в своём потоке; `Accept: application/json,
    text/event-stream`, `headers` из конфига, `Mcp-Session-Id` (когда есть),
    `MCP-Protocol-Version` (после рукопожатия);
  - ответ `application/json` → `dispatch`;
  - ответ `text/event-stream` → разбор строк: `data:` склеиваются, пустая строка —
    конец события, каждое событие → `dispatch`; читается до ответа с нашим `id`;
    промежуточный `ping` получает ответ отдельным POST;
  - `202` на уведомление — норма; `Mcp-Session-Id` — из ответа на `initialize`.
- **Ошибки как данные**: `McpError::Http { status, body }` — 401/403/5xx доставляются
  ждущему с началом тела; 401 — с пометкой про OAuth. `404` при живой сессии — сессия
  умерла: соединение закрыто, `is_alive()` = `false`, `Supervised` переинициализирует раз
  за ход. Упавший вызов не повторяется. Не удалось соединиться — тоже закрыто.
- **Отмена и таймаут**: опрос флага из `Connection::request`; поток POST по отмене
  бросается, его ограничивает таймаут агента (`timeout_secs` сервера).
- **`Drop`** — `DELETE` сессии в фоне, без ожидания.
- **`lib.rs`**: в `Start` — `match config.url`: `HttpServer` или `StdioServer`.
- **Тесты** — подменный сервер на `TcpListener` в тестах того же файла: JSON; SSE с
  `ping` до результата; 202 на уведомление; эхо session id и версии; 401 с телом;
  404 → закрыто → перезапуск; отмена шлёт `notifications/cancelled`; таймаут. Затем
  мутации по `11-mutation-testing.md`.

**Сделано (2026-09-25).** Отличия от плана:

- **Политика данных — здесь, а не в F-7.4g**: код, открывающий соединения, падает в
  `data_policy`, пока его нет в `NETWORK_ALLOWED`, а таблица `08-data-policy.md` должна
  назвать выход раньше исключения в тесте.
- **`Inbox` вместо `dispatch`**: `Connection` отдаёт транспорту то, куда класть пришедшее
  (`deliver` — ответ ждущему, ответ на `ping`; `fail` — ошибка одного запроса; `close` —
  конец всего), и берёт функцию отправки (`Outbox`). Stdio — те же читатель и писатель
  поверх, его тесты не менялись.
- **Таймаут самого POST** (`ureq::Error::Timeout`) — ошибка вызова, а не конец сессии:
  медленный сервер ещё жив. Обрыв связи — конец сессии, как 404 при живой сессии.
- **Поток читается до своего ответа и не дальше**: сервер может держать его открытым.
  Запрос сервера с тем же номером, что у нашего, за ответ не принимается — номера у
  сторон свои.
- **`data:` склеиваются без `\n`**: для JSON это то же самое (между токенами разделитель не
  нужен, внутри строки сырой перевод запрещён), и `lines()` сам снимает CRLF.
- Проверено вживую на `https://mcp.context7.com/mcp`: рукопожатие, два инструмента, вызов.

**Мутации: 31, все пойманы** (29 в первом прогоне + 2 после тестов): заголовки (Accept,
Content-Type, из записи, сессия, версия), таймаут POST и его разбор, обрыв связи, запоминание
сессии и версии, статус ошибки, обрезка тела, 404 с сессией и без, любая ошибка при сессии,
202 на запрос, распознавание потока, JSON не на наш запрос, чтение после ответа, запрос
сервера с нашим номером, ответ на `ping`, причина обрыва, закрытие inbox, DELETE без сессии
и без заголовков, `Inbox::fail`, подсказка OAuth на 401.

Не пойманы сразу три. **«Подтверждение рукопожатия уходит в фоне»** — тест сравнивал порядок
прихода, а это гонка; закрыт тестом, где сервер принимает подтверждение 300 мс, и `tools/list`
должен прийти не раньше. **«У POST нет своего таймаута»** — не видно по результату вызова, но
поток и соединение висели бы вечно; закрыт тестом, где сервер держит соединение и отмечает,
что клиент его закрыл. **«CRLF в потоке»** — эквивалентный: `BufRead::lines` снимает `\r\n`
сам, лишний `strip_suffix` удалён.

**Не покрыто тестами:** выбор транспорта по `url` в `lib.rs` — замыкание `Start` без
тестового двойника. Проверено в приложении (2026-09-25): модель вызывает инструменты
HTTP-сервера.

### F-7.4g — UI

- Экран «Where your data goes» (`DataPolicy.tsx`): сервер с `url` — сетевой выход.
- Форма сервера (`ConfigEntryForm`, `configEntries.ts`): URL и заголовки вместо команды.
- Примеры в редакторах MCP и хуков убраны (2026-09-25): узкая колонка прокручивала JSON.
- CSP не меняется: в сеть ходит бэкенд, не окно.

**Сделано (2026-09-25).**

- **Форма**: переключатель «Runs» — «A command» / «At a URL» (`Dropdown`, как событие у
  хука). URL-режим — поля URL и Headers (`Name: value` построчно; значение может содержать
  двоеточие). HTTP-запись открывается в форме как HTTP — до этого форма читала её с пустой
  командой и не давала сохранить.
- **Запись** получает `type: "http"`: Claude Code без него читает запись как команду, Cursor
  его игнорирует. Смена способа запуска убирает поля другого способа (`command`/`args`/`env`
  или `url`/`headers`) и `type: "http"`/`"sse"` у команды — иначе вышла бы запись, которая не
  запускается. `type: "stdio"` и прочие ключи остаются. Схему URL форма не проверяет — это
  делает бэкенд, и строка вкладки говорит почему.
- **Экран политики**: HTTP-сервер назван с хостом — `docs (mcp.example.com)`; подписи
  провайдера и MCP говорят о сети. HTTP-сервер узнаётся по `command` строки, начинающемуся с
  `http(s)://` — бэкенд кладёт туда URL.
- **Пример** — второй сервер, `remote`, с `type`, `url` и `headers`.
- Проверено в превью (Vite): форма в обоих режимах, экран политики.

**Мутации: 18, все пойманы** (15 в `configEntries.ts`, 2 в `DataPolicy.tsx`, 1 в форме):
чтение режима и заголовков, разделители `=` и `:`, строка без имени, обрезка значений и URL,
пустой URL, пустые `headers`, `type: "http"`, остатки прежнего способа, `type` http/sse у
команды, хост и регистр схемы на экране, поля URL в форме. Эквивалентный: проверка режима
перед удалением `type` — URL-режим всё равно пишет свой `type`; проверка удалена. «Поля URL
не показываются» прогон отметил как зависание: тест падает, но Bun долго печатает дамп DOM.

## Отложено сознательно

| Что | Почему потом |
|---|---|
| OAuth 2.1 (PKCE, RFC 9728/8414, динамическая регистрация, loopback-редирект, токены в `secret_store`) — план в [18-mcp-oauth.md](18-mcp-oauth.md) | Отдельная фича со своим сетевым входом (`TcpListener`). Без неё работают серверы с ключом в заголовке; требующие OAuth получают понятный `401` |
| Старый HTTP+SSE (2024-11-05, `GET /sse` → `endpoint`) | Устарел. `type: "sse"` — отказ с причиной; добавлять под конкретный сервер |
| GET-поток уведомлений сервера | Нужен только для `tools/list_changed`, а список инструментов заморожен на ход |
| Возобновление потока (`Last-Event-ID`) | Обрыв посреди вызова — упавший вызов, как у упавшего stdio-сервера |
| Эпоха 2026-07-28 (без рукопожатия, `server/discover`) | Та же точка пересмотра, что в `mcp_stdio.rs`; для HTTP наступит раньше |
