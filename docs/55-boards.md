# Несколько досок: доска агента и до 10 своих

План, не сделано. Сейчас доска в приложении одна, с колонками To do / Doing / Done и архивом.
Здесь Board становится набором досок. **Доска по умолчанию** остаётся как есть: только с ней
работает тул `board`, её колонки фиксированы. Рядом с ней пользователь заводит **до 10 своих
досок** со своими колонками: добавляет, переименовывает, переставляет и удаляет их. Работа
закончена, когда на странице Board есть переключатель досок, своя доска живёт с карточками,
тегами, комментариями и перетаскиванием как доска по умолчанию, а модель о своих досках не
знает и не может их тронуть.

Кода в документе нет — только решения. Ветка и PR — те же, что у панели карточки (#106).

## Что уже есть

- **Домен** — `domain/board.rs`. `Card { id, title, note, due, column, comments, tags }`,
  `column` — enum `Column { Todo, Doing, Done, Archived }`. Один `apply(cards, change)` на всё
  (и для тула, и для страницы). `settle` держит в Done не больше `MAX_DONE` (5) карточек, старшие
  уходят в архив; архив — не больше `MAX_ARCHIVED` (100). Новая карточка встаёт наверх To do.
  Ключи `T1, T2…` выдаются от самого большого номера.
- **Хранилище** — `infra/board_store.rs`, `~/.kibo/board.db`: таблицы `cards` (колонка
  `status` = `todo|doing|done|archived`, `position`), `card_tags`, `card_comments`. Каждое
  изменение — прочитать всё, `apply`, переписать всё одной транзакцией под замком. Наружу —
  порт `TaskBoard { cards(), change() }` и сигнал `board:changed`.
- **Тул модели** — `services/ai_tools/tools/board.rs`: `list / add / move / edit`, колонки в
  схеме — `todo | doing | done`. Текст для модели — `model_text.rs`.
- **Страница** — `BoardPage.tsx`: колонки заданы константой `COLUMNS`, `Order` —
  `Record<OpenColumn, string[]>`, `dropChange` переводит перетаскивание в `move`, фильтр по
  тегам, архив под колонками. Панель — `BoardCardSheet.tsx`, статус берётся из списка `STATUS`.
- **Catalog** — функция `board`, «Delete data» удаляет `board.db` целиком.

## Решения

### 1. Доска по умолчанию — неявная и та же, что сейчас

У неё нет строки в таблице досок: её id (`main`), имя и колонки заданы в коде. Её нельзя
удалить, переименовать или поменять колонки. Архив и правило «в Done не больше пяти» —
только у неё. Существующие карточки после миграции принадлежат ей, ничего не переезжает.

### 2. Модель видит только доску по умолчанию — это гарантирует порт, а не промпт

`TaskBoard` остаётся как есть и по-прежнему означает доску по умолчанию. Тул `board`
получает этот порт и физически не может обратиться к своей доске пользователя. Промпт, схема
тула и `model_text` не меняются, агентский бенч перегонять не нужно. Странице нужны
отдельные методы с id доски (решение 6).

### 3. Колонка карточки — строковый id, а не enum

`Card.column` становится строкой. У доски по умолчанию значения прежние —
`todo / doing / done / archived`, поэтому в базе и в JSON ничего не меняется. У своей доски
id колонок генерируются (`k1, k2…` в пределах доски), а имя хранится отдельно. Enum `Column`
остаётся только на границе тула: модель по-прежнему шлёт `todo|doing|done`, тул переводит это
в id. `settle` и «наверх To do» сравнивают со строковыми константами доски по умолчанию.

### 4. Своя доска — имя и упорядоченный список колонок

`BoardInfo { id, name, columns: [{ id, name }] }`. Новая доска создаётся с колонками
To do / Doing / Done — это обычные свои колонки, их можно переименовать и удалить. Правила
своей доски:
- новая карточка встаёт **наверх первой колонки**;
- архива и лимита Done нет — колонки равноправны;
- `move` в колонку, которой нет на этой доске, отклоняется;
- у доски не меньше 1 колонки и не больше `MAX_COLUMNS` (8);
- имя доски и колонки — не пустое, до 40 символов;
- досок не больше `MAX_BOARDS` (10, без учёта доски по умолчанию);
- лимит `MAX_CARDS` (200) — на каждую доску отдельно.

### 5. Колонку и доску с карточками удалить нельзя

Удаление непустой колонки отклоняется ошибкой «сначала перенесите карточки». Удаление непустой
доски — так же: «сначала уберите карточки». На странице пункт меню неактивен и объясняет почему.
Карточки никогда не пропадают вместе с колонкой или доской, поэтому подтверждение в `Modal`
не нужно: удаляется только пустое.

### 6. Изменения досок — отдельный enum, рядом с `BoardChange`

`BoardsChange`: `CreateBoard { name }`, `RenameBoard { board, name }`,
`DeleteBoard { board }`, `AddColumn { board, name }`, `RenameColumn { board, column, name }`,
`MoveColumn { board, column, index }`, `RemoveColumn { board, column }`. Чистая функция в
домене, как `apply`. `BoardChange` (изменения карточек) не меняется: страница шлёт его вместе с
id доски, а `apply` получает колонки этой доски, чтобы проверять `move` и знать первую колонку.

### 7. Ключи карточек — сквозные по всем доскам (решено)

Номер `T{n}` берётся от максимума по **всем** доскам: ключ однозначно называет карточку, где бы
она ни лежала, и не меняется при будущем переносе между досками. Цена — на доске по умолчанию
номера идут с пропусками (T3, T7…). Модель от этого не страдает: она получает ключи списком.

### 8. Хранилище: две таблицы, у карточки — `board_id`

- `boards (id, position, name)` — только свои доски;
- `board_columns (board_id, id, position, name)`;
- у `cards` — новая колонка `board_id TEXT NOT NULL DEFAULT 'main'`, добавляется тем же
  приёмом, что `add_column` в `chat_store`: существующая база после этого — доска по умолчанию;
- `status` у карточки — id колонки.

Изменение карточек переписывает **одну** доску (`DELETE … WHERE board_id = ?`), а не всю базу:
`ponytail:` из `write` остаётся в силе, но в пределах доски. `DeleteBoard` пустой доски удаляет её
и её колонки одной транзакцией. Импорт `board.json` попадает
в доску по умолчанию, как и сейчас.

### 9. Команды и сигнал

- `boards_list` — доска по умолчанию и свои, с колонками;
- `boards_change(change)`;
- `board_list(board)` и `board_change(board, change)` — получают id доски;
- все `async` через `commands::blocking`, обёртки в `src/lib/board.ts`.

Сигнал остаётся один — `board:changed`. Страница по нему перечитывает и список досок, и
открытую доску. Отдельный канал не нужен: изменение в одной доске стоит лишнего чтения,
не больше.

### 10. Страница: переключатель досок, колонки своей доски

- **Переключатель — ряд вкладок** над фильтром тегов: доска по умолчанию первой, потом свои,
  в конце **+** для новой доски (неактивен на десятой). Вкладки **фиксированной ширины**, длинное
  имя обрезается многоточием с полным именем в подсказке. Если вкладки не помещаются, по краям
  ряда появляются кнопки-иконки **назад / вперёд** (`ChevronLeft` / `ChevronRight`): они сдвигают
  ряд на одну вкладку. Прокрутки колесом или полосой нет. Неактивная кнопка — когда сдвигать
  дальше некуда. Открытая вкладка, если её не видно, прокручивается в поле зрения. У вкладки
  своей доски — `ChatMenu`: Rename и Delete (неактивен у непустой, решение 5). Последняя
  открытая доска запоминается в `localStorage`.
- **Колонки** берутся из `BoardInfo`, а не из константы. `Order` — `Record<string, string[]>`
  по id колонок, `dropChange` и `orderOf` обобщаются.
- **Шапка колонки своей доски** — имя редактируется на месте, `ChatMenu`: Move left / Move
  right / Delete (неактивен у непустой). Справа от последней колонки — «+ Column». **+** для
  новой карточки — у первой колонки.
- **Много колонок** — ряд колонок прокручивается по горизонтали, у колонки минимальная ширина.
- **Панель карточки** — статус в `Dropdown` строится из колонок открытой доски.
- **Фильтр по тегам** — по тегам открытой доски, сбрасывается при смене доски.
- **Архив** — только у доски по умолчанию.

## Слои

| Слой | Что меняется |
|---|---|
| `domain/board.rs` | `Card.column: String`, константы колонок доски по умолчанию, `BoardInfo`, `BoardsChange` и его `apply_boards`, `apply` принимает колонки доски, новые ошибки (`NoColumn`, `ColumnNotEmpty`, `BoardNotEmpty`, `TooManyBoards`, `TooManyColumns`, `EmptyName`, `NameTooLong`, `NoBoard`, `DefaultBoardFixed`) |

| `commands/board.rs`, `lib.rs` | `boards_list`, `boards_change`, у `board_list`/`board_change` — параметр `board` |

## Нарезка

Каждый этап: тесты, мутационная проверка своей логики, `tsc` + `bun test`, `cargo check` +
`cargo test`, отдельный коммит в #106.

- **MB-1. Колонка — строка.** `Card.column: String`, константы доски по умолчанию, `settle` и
  `apply` на строках, тул переводит `Column` в id. Видимых изменений нет, все тесты прежние
  зелёные. Отдельным этапом — чтобы рефакторинг не смешался с новым поведением.
- **MB-2. Домен своих досок.** `BoardInfo`, `BoardsChange`, `apply_boards` со всеми лимитами,
  `apply` с колонками доски (первая колонка, `move` в чужую колонку, лимит на доску), сквозные
  ключи. Только чистые функции и тесты.
- **MB-3. Хранилище.** Миграция `board_id`, таблицы, чтение и запись одной доски, удаление пустой
  доски транзакцией, `TaskBoard` остаётся доской по умолчанию. Тесты: старая база открывается как доска
  по умолчанию, изменение одной доски не трогает другую, тул не видит своих досок.
- **MB-4. Команды и обёртки.** Четыре команды, обёртки, mock в `board.test.tsx` учится доскам.
- **MB-5. Страница: вкладки досок.** Ряд вкладок фиксированной ширины со стрелками назад / вперёд,
  **+** / Rename / Delete (пустой), запоминание в `localStorage`, колонки из `BoardInfo`, обобщённые `Order`/`dropChange`, фильтр
  и архив по доске.
- **MB-6. Страница: колонки своей доски.** Имя на месте, меню колонки (влево/вправо/удалить с
  объяснением), «+ Column», горизонтальная прокрутка, статус в панели из колонок.
- **MB-7. Хвосты.** Описание в Catalog, строка в CHANGELOG, описание PR, проверка в `tauri dev`
  на своей доске и на доске по умолчанию через Assistant.

## Вне плана

- **Перенос карточки между досками** — ключи сквозные (решение 7), поэтому добавить его потом —
  один пункт в меню карточки.
- **Своя доска для модели** (выбрать, с какой доской работает агент) — порт это позволяет, но
  пока модели нужна одна.
- **Порядок досок перетаскиванием**, цвет колонок, WIP-лимиты, архив у своих досок.
- **Префикс ключа по доске** (`KIBO-1`) — решено против, ключи сквозные (решение 7).
