## 1. Список файлов в сводке компакции

**Что у них.** Сводку пишет модель, но список файлов к ней добавляет код, а не модель. Код
идёт по вызовам инструментов в сжимаемой части и раскладывает пути на три множества:
`read`, `written`, `edited`. В итоге получаются два отсортированных списка: изменённые
(`written ∪ edited`) и только прочитанные (`read` минус изменённые). К тексту сводки они
дописываются тегами:

```
<read-files>
src/a.ts
</read-files>

<modified-files>
src/b.ts
</modified-files>
```

Списки копятся от сжатия к сжатию. Предыдущая компакция хранит их в `details`, и
следующая начинает с них, а не с нуля. Тот же механизм работает в сводке ветки (п. 6).
Вызовы, сделанные из скрипта codemode, тоже учитываются: они записаны на результате
скрипта.

Код: `extractFileOpsFromMessage`, `computeFileLists`, `formatFileOperations` в
[`compaction/utils.ts`](https://github.com/earendil-works/pi/blob/0f8740bb65638180403a225ad7ec4d0cc1f8dedf/packages/coding-agent/src/core/compaction/utils.ts),
сборка — `extractFileOperations` в
[`compaction/compaction.ts`](https://github.com/earendil-works/pi/blob/0f8740bb65638180403a225ad7ec4d0cc1f8dedf/packages/coding-agent/src/core/compaction/compaction.ts).

**У нас.** Файлы перечисляет модель: промпт сводки просит «files touched by path and what
changed in them» (`domain/compaction.rs:317`). Слабая модель или длинная история — и файл
выпадает. После второй компакции он выпадает уже навсегда: следующий проход начинает с
текста предыдущей сводки (`SUMMARY_PREFIX`), и что модель в ней не повторила, того больше нет.

**Как сделать.** Чистая функция в `domain/compaction.rs`: по сжимаемым `LlmMessage`
собрать пути из `tool_calls` (`readFile`, `editFile`, `writeFile`, `deleteFile`,
`movePath` с обоими путями). Дописать теги в `summary_message`. Чтобы списки копились без
нового поля в хранилище, достаточно разобрать теги из предыдущего сообщения-сводки, если
оно попало в сжимаемую часть. Удалённый файл стоит выделить отдельно (`<deleted-files>`),
иначе модель будет его искать. Тест: две компакции подряд, и файл из первой сохраняется
во второй, даже если модель о нём не написала.

> **✅ Сделано.** `domain::compaction::with_file_lists`: три блока, `<modified-files>`,
> `<deleted-files>` и `<read-files>`, по вызовам `readFile`, `writeFile`, `editFile`,
> `deleteFile` и `move`. Вызов, который ничего не сделал, не считается: результат
> начинается с `Error: `, `Denied by the user` или `Not run: ` (константы
> `TOOL_*_PREFIX` в `domain/tools.rs`, их же пишет `llm_chat`). Списки предыдущей сводки
> разбираются из её текста, отдельного поля в хранилище нет. Блоки, которые модель
> переписала из прошлой сводки, вырезаются, чтобы не было двух наборов.

## 2. Позиционные аргументы в `/`-командах

**Что у них.** Шаблон команды — Markdown с frontmatter `description` и `argument-hint`, как у
нас. Подстановки:

| Синтаксис | Результат |
|---|---|
| `$1`, `$2`, … | Один аргумент |
| `$@` или `$ARGUMENTS` | Все аргументы через пробел |
| `${1:-default}` | Первый аргумент или значение по умолчанию |
| `${@:-default}` | Все аргументы или значение по умолчанию |
| `${@:N}` | Аргументы, начиная с N |
| `${@:N:L}` | L аргументов, начиная с N |

Аргументы разбираются с кавычками как в shell: `/review "API compatibility"` — это один
аргумент. Результат подстановки повторно не разворачивается: `$1` внутри аргумента
остаётся текстом. Вся подстановка — одна регулярка
`\$\{(\d+|ARGUMENTS|@):-([^}]*)\}|\$\{@:(\d+)(?::(\d+))?\}|\$(ARGUMENTS|@|\d+)`.

Код: `parseCommandArgs`, `substituteArgs` в
[`prompt-templates.ts`](https://github.com/earendil-works/pi/blob/0f8740bb65638180403a225ad7ec4d0cc1f8dedf/packages/coding-agent/src/core/prompt-templates.ts).

**У нас.** Только `$ARGUMENTS`, и подставляется он на фронтенде одной строкой
(`src/lib/slashCommands.ts:61`).

**Как сделать.** Заменить эту строку функцией с той же регуляркой и разбором кавычек, в
том же файле. Бэкенд не трогается. Тест в `src/__tests__/` на каждую строку таблицы и на
кавычки. Синтаксис совместим с Claude Code (`$1`, `$ARGUMENTS`), поэтому чужие команды
продолжают работать.

> **✅ Сделано, но по Claude Code, а не по pi.** Совместить их нельзя: Claude Code считает
> аргументы **с нуля** (`$0` — первый, `$1` — второй), а pi, как bash, с единицы. Ставка
> на то, что команда из `.claude/commands` работает у нас без правок, поэтому синтаксис
> Claude Code (сверено с code.claude.com/docs, раздел о подстановках в skills):
> `$ARGUMENTS`; `$ARGUMENTS[N]` и `$N` с нуля, с кавычками как в shell, а без
> аргумента на этой позиции плейсхолдер остаётся как написан; `$name` из поля
> `arguments` во frontmatter (строка через пробел или список), пустой без аргумента;
> `\$1` — буквальный `$1`. Подстановка в один проход. Если ни один плейсхолдер ничего не
> взял, введённое дописывается в конец как `ARGUMENTS: …`, как у Claude Code (раньше у
> нас это шло просто после пустой строки). bash-форм pi (`${1:-default}`, `${@:N}`)
> нет: Claude Code их не знает, и команда с ними не была бы переносимой.
> `expandTemplate` в `src/lib/slashCommands.ts`, поле `arguments` в
> `domain/slash_commands.rs`.

## 3. Нечёткое совпадение в `editFile`

**Что у них.** Сначала ищется точное совпадение. Если его нет, обе строки нормализуются и
поиск повторяется:
- NFKC;
- пробелы в конце каждой строки убираются;
- «умные» кавычки `‘ ’ ‚ ‛` и `“ ” „ ‟` становятся `'` и `"`;
- тире и дефисы U+2010…U+2015 и минус U+2212 становятся `-`;
- особые пробелы (NBSP, U+2002…U+200A, U+202F, U+205F, U+3000) становятся обычным пробелом.

Замена вычисляется в нормализованном тексте, а записывается хитро: каждая правка
расширяется до затронутых строк, эти строки берутся из нормализованного текста, а все
остальные копируются из оригинала. Так нормализация не расползается по файлу.

Код: `normalizeForFuzzyMatch`, `fuzzyFindText`, `applyReplacementsPreservingUnchangedLines`
в [`tools/edit-diff.ts`](https://github.com/earendil-works/pi/blob/0f8740bb65638180403a225ad7ec4d0cc1f8dedf/packages/coding-agent/src/core/tools/edit-diff.ts).

**У нас.** Только точное совпадение (`exact_match_ranges`, `find_unique` в
`services/ai_tools/tools/edit_file.rs`). При промахе подсказываем ближайшую строку
(`closest_line`), и модель тратит раунд на повтор.

**Как сделать.** Побочный эффект у них есть: в затронутых строках «умные» кавычки
файла молча становятся ASCII. Лучше этого не повторять, а отображать совпадение
обратно на оригинал. Нормализуем построчно, запоминая для каждого символа
нормализованного текста его байт в оригинале. Найденный диапазон переводим в
диапазон оригинала и меняем только его. Правило уникальности остаётся: если после
нормализации совпадений несколько, правка отклоняется, как сейчас. Срабатывание
нечёткого поиска стоит назвать в результате («matched ignoring trailing whitespace»),
чтобы модель знала, что её якорь был неточным. Проверить на `agent_bench`: меньше
ошибок `editFile`.

> **✅ Сделано.** `find_loosely` и `loosened` в `services/ai_tools/tools/edit_file.rs`.
> Если точного совпадения нет, якорь ищется ещё раз без пробелов в конце строк и с
> кавычками, тире и особыми пробелами, приведёнными к ASCII. Найденное место переводится
> обратно в байты оригинала по карте, и заменяется только оно, поэтому типографика и
> хвостовые пробелы остального файла не трогаются. Отличия от pi: нет NFKC (это была бы
> новая зависимость), а пробел в конце последней строки якоря без перевода строки не
> срезается, иначе `x – ` на месте `x - 1` удвоил бы пробел. Правила те же, что у
> точного совпадения: уникальность, целые слова, отказ на смешанных концах строк.
> Заметки «совпало нестрого» в результате нет: модель видит дифф того, что легло на
> диск. На `agent_bench` не прогонялось.

## 4. Объяснение промахов кэша

**Что у них.** После каждого ответа модели сравнивают его `usage` с предыдущим запросом:

- `missedTokens = min(prev.promptTokens, promptTokens) − cacheRead` — то, что уже было в
  прошлом промпте, но не взялось из кэша;
- промах ≤ 1024 токенов — шум границ кэша, не считается;
- если провайдер ни разу не сообщил о кэше, ноль ничего не значит и тоже не считается.
  Но если раньше сообщал, ноль считается полным промахом: так ведут себя провайдеры в
  стиле OpenAI, которые не сообщают о записи в кэш;
- после компакции или сводки ветки сравнение начинается заново: контекст сменился
  законно. Смена модели не исключение, она честно перевыставляет весь промпт.

В чат выводится заметка, если промах ≥ 20 000 токенов или ≥ $0.10:
`Cache miss after 7m idle — 84k tokens re-billed (~$0.25)`, или `after model switch`, или
просто `Cache miss`. Причина указывается только наблюдаемая: пауза дольше TTL (5 минут)
или смена модели. Догадок нет. Сводная строка в `/session` — сумма за сессию.

Код: [`cache-stats.ts`](https://github.com/earendil-works/pi/blob/0f8740bb65638180403a225ad7ec4d0cc1f8dedf/packages/coding-agent/src/core/cache-stats.ts),
вывод — `addCacheMissNotice` в `modes/interactive/interactive-mode.ts`.

**У нас.** `ChatUsage.cached_tokens` есть, и `ContextMeter` показывает долю кэша
последнего запроса. Что промах был и почему, не видно. Цен в долларах у нас нет, поэтому
считать можно только в токенах.

**Как сделать.** Чистая функция в `domain/` по паре «предыдущий запрос, текущий
`ChatUsage`, прошедшее время, сменилась ли модель», возвращающая `Option<CacheMiss>`. Usage
приходит событием `ContextUsage` на каждый раунд. Предыдущий запрос (токены, модель,
время) держит цикл хода. Между ходами его нужно где-то хранить, иначе пауза перед
следующим сообщением, самый частый случай, не увидится. Хватит памяти процесса по
`chatId`: после перезапуска первый запрос и так промах. Компакция сбрасывает
предыдущий запрос. Заметка — новый вариант события хода, строка в чате тише обычного
текста.

> **✅ Сделано, но на фронте, а не в `domain/`.** В бэкенде нет id чата, так что предыдущий
> запрос между ходами держать негде. А состояние редьюсера (`src/lib/chatTurnReducer.ts`)
> и так живёт между ходами одного чата и получает `contextUsage` каждого раунда. `cacheMiss`
> там сравнивает раунд с предыдущим: что было в обоих промптах, минус `cachedTokens`.
> Порог 20 000 токенов, порог шума 1024 не нужен, он ниже. Пауза считается от конца
> прошлого запроса до `roundStarted` текущего, а не до его ответа. Модель передают хуки
> (`useAgentTurn`, `usePlainChat`) из `llm.models.current`. Готовая компакция, rewind и
> открытие другого чата сбрасывают сравнение. Компакция, которая не удалась, не
> сбрасывает. Заметка — обычный блок `notice`:
> `Cache miss after 7 min idle — ~84k tokens of the prompt were sent again at full price`.
> Долларов нет, сводки в `/session` тоже: такой команды у нас нет.

## 5. Доверие к папке

**Что у них.** Пока папке не дали доверие, её ресурсы не загружаются: `.pi/settings.json`,
`.pi/mcp.json`, `.pi/extensions`, `skills`, `prompts`, `themes`, `.pi/SYSTEM.md` и
`APPEND_SYSTEM.md`, а также `.agents/skills` в папке и выше. Пустая папка `.pi` доверия не
требует. `AGENTS.md` и `CLAUDE.md` грузятся всегда: это текст, а не исполняемое, и в
документации прямо сказано, что он всё равно остаётся недоверенным вводом.

Порядок решения: флаг командной строки, затем расширение, затем сохранённое решение для
этой папки **или ближайшей родительской**, затем глобальная настройка
`defaultProjectTrust` (по умолчанию `"ask"`). Решения хранятся в `~/.pi/agent/trust.json`
по канонизированному пути, с блокировкой файла. Без интерактивного окна `"ask"`
означает «не грузить». Команда `/trust` сохраняет решение.

Документация честно пишет, чего доверие **не** даёт: оно не ограничивает инструменты и не
защищает от prompt injection в файлах папки.

Код: [`trust-manager.ts`](https://github.com/earendil-works/pi/blob/0f8740bb65638180403a225ad7ec4d0cc1f8dedf/packages/coding-agent/src/core/trust-manager.ts)
(`hasTrustRequiringProjectResources`, `findNearestTrustEntry`); описание — раздел
«Understand project trust» в
[`docs/security.md`](https://github.com/earendil-works/pi/blob/0f8740bb65638180403a225ad7ec4d0cc1f8dedf/packages/coding-agent/docs/security.md).

**У нас.** Шаг отложен явно: в `infra/hooks.rs` написано, что хуки только глобальные,
потому что хук из репозитория — чужая команда на каждом вызове инструмента, и проектным
хукам нужен шаг «доверять папке». MCP тоже только глобальный (`infra/mcp_config.rs`).
Зато проектные skills (`.claude/skills`, `.agents/skills` от папки до корня репозитория,
`infra/skills_store.rs`) и `.kibo/commands` (`infra/slash_commands_store.rs`) грузятся
без всякой проверки. Это текст для модели, а не исполняемое, но skill может велеть
модели запустить скрипт из своей папки.

**Как сделать.**
- В `domain/` — решение по папке (`Trusted`/`Declined`/`Ask`) и поиск ближайшего
  родителя. Это чистая функция над списком путей.
- В `infra/` — файл `trust.json` в каталоге приложения, владелец-только, как остальное.
- Карточка через `Modal` при открытии папки, у которой есть проектные ресурсы, и
  только тогда. Пустой репозиторий ни о чём не спрашивает.
- До доверия не грузятся проектные skills и команды. После — разрешены проектные
  `hooks.json` и `.mcp.json`. Последние два — отдельный шаг, это новая функциональность,
  а не ограничение.
- В [08-data-policy.md](08-data-policy.md) дописать, что доверие закрывает и чего не
  закрывает, теми же словами, что у них.

## 6. Сводка покинутой ветки

**Что у них.** Сессия хранится деревом. Возврат к раннему сообщению (`/tree`) не стирает
ветку, которую покидают. При переходе pi спрашивает: «No summary», «Summarize» или
«Summarize with custom prompt» (вопрос можно отключить настройкой
`branchSummary.skipPrompt`). Сводка строится от общего предка до конца покидаемой
ветки, в пределах бюджета токенов, по шаблону:

```
## Goal
## Constraints & Preferences
## Progress  (Done / In Progress / Blocked)
## Key Decisions
## Next Steps
```

Плюс списки файлов из п. 1. В новую ветку она вставляется с предисловием «The user
explored a different conversation branch before returning here. Summary of that
exploration:». Запросы на сводку не пишут в кэш промпта: они разовые.

Код: [`compaction/branch-summarization.ts`](https://github.com/earendil-works/pi/blob/0f8740bb65638180403a225ad7ec4d0cc1f8dedf/packages/coding-agent/src/core/compaction/branch-summarization.ts)
(`collectEntriesForBranchSummary`, `BRANCH_SUMMARY_PROMPT`).

**У нас.** Rewind возвращает чат и файлы к моменту до сообщения, и всё, что было после,
пропадает. `/fork` копирует чат целиком. Дерева нет, и для нашего UI оно не нужно.

**Как сделать.** Дерево не строить. Взять одно: на rewind предложить «откатить со
сводкой». Отрезаемый хвост уходит в тот же запрос сводки, что у компакции (с другим
промптом), и результат становится первым сообщением после точки отката, с префиксом,
как `SUMMARY_PREFIX`. Файлы откатываются как сейчас. Сводка говорит модели, что
пробовали и почему не вышло, а не что лежит на диске. Зависит от п. 1 только списками
файлов. Без них сводка тоже работает, но хуже.

## 7. Прогрев кэша

**Что у них.** Перед истечением кэша (на 90% TTL, но не позже чем за 10 секунд) pi
повторяет последний запрос с лимитом вывода в один токен, и кэш живёт дальше. Шлёт,
только если это выгодно:

```
warmCost       = цена(cacheRead промпта + 1 токен вывода)
missCost       = цена(промпт без кэша) − цена(cacheRead промпта)
expectedSavings = p × missCost − warmCost        # прогреваем при ≥ $0.05
```

`p` = 1, пока ход идёт (агент ждёт долгую команду или ответ на карточку), и 0.15 в
простое: так они измерили по своему использованию. Режимы: `off`, `streaming`
(по умолчанию — только во время хода), `idle`. Горизонт: час во время хода, 30 минут в
простое. Прогрев останавливается, если сменились модель или сообщения. Он не делается,
если повтор запроса не попадёт в тот же кэш: у Anthropic с бюджетным thinking бюджет
считается от `max_tokens`, и запрос с одним токеном получит другой ключ кэша. Usage
прогрева идёт в итоги сессии, но не в контекст.

Код: [`cache-warmer.ts`](https://github.com/earendil-works/pi/blob/0f8740bb65638180403a225ad7ec4d0cc1f8dedf/packages/coding-agent/src/core/cache-warmer.ts)
(`getCacheWarmingDelayMs`, `isReplayable`, `evaluate`).

**У нас.** Нет. Имеет смысл только для провайдера с коротким TTL, то есть Anthropic
(5 минут). DeepSeek и большинство OpenAI-совместимых шлюзов кэшируют сами и надолго, им
это не нужно. Цен у нас нет, поэтому `expectedSavings` не посчитать. Остаётся порог в
токенах.

**Как сделать.** Только режим `streaming`, и только на паузе хода: карточка
подтверждения или вопрос MCP. Это единственное место, где у нас заведомо будет
продолжение (`p` = 1), и оно же может длиться дольше 5 минут. Таймер в сервисе хода,
запрос — тот же, что ушёл последним, с `max_tokens: 1`. Отмена — при ответе на карточку.
Включать по провайдеру `anthropic` и промпту больше порога. Делать после п. 4: без
заметок о промахах не проверить, что прогрев что-то дал.

## 8. Codemode

**Что у них.** Инструмент `codemode` принимает JavaScript, который выполняется в QuickJS,
скомпилированном в WebAssembly. Единственная возможность скрипта — вызывать другие
инструменты: `await tools.<name>(args)`. Результаты промежуточных вызовов в контекст
модели не попадают. Попадает только то, что скрипт вывел через `text()` или вернул.
Поэтому модель может отфильтровать 2 МБ вывода MCP или пройти по сотне подов, а в
контекст положить десять строк.

Детали:
- Сеть, таймеры, `require`, `process`, `fetch` отсутствуют. `eval` работает, но только
  внутри той же VM. Есть лимиты памяти и времени. Скрипт, ждущий промис, который никто не
  разрешит, падает сразу.
- Первая строка может быть `// @options: {"max_output_tokens": 2000, "timeout_ms": 30000}`.
  Длинный вывод обрезается посередине, целиком сохраняется во временный файл, и путь к
  нему указывается в результате.
- Описание инструмента — TypeScript-декларации доступных инструментов, сгенерированные из
  JSON Schema, в бюджете 3000 токенов. Остальное скрипт находит сам через
  `searchTools(query)` (BM25), `describeTool(name)`, `describeNamespace(server)`.
- Вложенные вызовы проходят через тот же конвейер инструментов, что и прямые, с хуками.
  Они показываются в UI под родительским вызовом (`parentToolCallId`), и их usage
  суммируется. Вложенный вызов с подтверждением — это тот же гейт.
- `store`/`load` хранят JSON между запусками скрипта в одной сессии.
- У MCP-сервера появляется четвёртый режим видимости, `codemode`: инструменты не
  объявлены модели, они доступны только из скриптов. У них это режим по умолчанию.

Код: [`packages/codemode`](https://github.com/earendil-works/pi/tree/0f8740bb65638180403a225ad7ec4d0cc1f8dedf/packages/codemode)
(README подробный), вложенные вызовы —
[`nested-tool-calls.ts`](https://github.com/earendil-works/pi/blob/0f8740bb65638180403a225ad7ec4d0cc1f8dedf/packages/coding-agent/src/core/nested-tool-calls.ts),
настройки `codemode.mode` и `codemode.inlineBudget` — в `docs/settings.md`.

**У нас.** Нет. Большой вывод сейчас режется по краям и сохраняется в файл (MCP,
`runCommand`), а инструменты kube сжимают вывод сами. Это работает, но модель не может
спросить «только поды с рестартами больше 5» иначе как прочитав всё.

**Как сделать.** Отдельный этап со своим планом. Что решить в нём:
- Движок: `rquickjs` (биндинги QuickJS) или `boa` (чистый Rust). Это первая зависимость с
  интерпретатором, поэтому нужны лимиты памяти и времени и проверка, что скрипт не
  достаёт ничего, кроме переданных функций.
- Гейт: вложенный вызов, требующий подтверждения, ставит на паузу ход посреди скрипта.
  Контрольная точка паузы сейчас этого не умеет. Проще всего на первом шаге разрешить
  из скриптов только инструменты без карточки: чтение, поиск, MCP с `readOnlyHint`,
  kube на чтение.
- Где выигрыш: роль Kubernetes и MCP с большим выводом. Мерить на `kube_bench` и
  `agent_bench` по токенам и раундам, до и после.
