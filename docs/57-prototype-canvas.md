# Prototype 2.0: канвас с фреймами из компонентов

План, предложен 2026-11-14. Превью роли Prototype ([31-prototype-role.md](31-prototype-role.md))
становится канвасом в духе Figma на React Flow: на нём фреймы — слайды презентации, экраны
мобильного приложения или страницы сайта. Модель не пишет HTML: она пишет React-компоненты
и собирает из них фреймы, а страницу вокруг фрейма отдаёт приложение. Модель заводит канвас
нужного вида, добавляет и удаляет фреймы, переходит от одного к другому и правит их,
связывает экраны переходами; у презентации переходы системные — кнопки под слайдом.
Пользователь двигает фреймы, смотрит прототип в режиме просмотра и указывает на элемент в
любом фрейме — модель получает файл и строку. Старые чаты открываются тем же канвасом с
одним фреймом — v2 надмножество v1, а не замена рядом.

Кода в документе нет — только решения.

Чего нет: React Flow (`@xyflow/react` 12.12.1, MIT, тянет `zustand` и `classcat` — это
внутренности библиотеки, не состояние приложения, правило «без глобального стора» не
задевается), перевода JSX на бэкенде, описания канваса на диске, понятия «фрейм»,
переходов между страницами.

## Решения

### 1. Модель пишет компоненты, HTML — приложение

Внутри фрейма — React-компонент, собранный из общих компонентов канваса. Всё, что вокруг
него (`<head>`, import map, Tailwind, тема, отступы под статус-бар, монтирование), отдаёт
протокол; модель эту оболочку не видит и не может сломать.

- **Почему компоненты.** Общая шапка или таб-бар правится один раз и меняется на всех
  экранах, как компонент в Figma, — это и есть единство дизайна между фреймами. Правка
  меньше: экран — десяток строк сборки, а не страница с шаблоном. Ошибки ловятся до показа
  (решение 6), а указка называет файл и строку (решение 8).
- **Отвергнуто: HTML на фрейм**, каждый своей страницей с Babel. Всё переиспользуется из
  v1, но у фреймов нет общего кода — одна и та же шапка переписывается в каждом и
  расходится; каждый фрейм несёт шаблон из промпта и Babel (2,3 МБ) на канвасе из 10–20
  живых фреймов; синтаксическая ошибка видна только красным экраном.
- **Отвергнуто: своя сцена в JSON** (прямоугольники, текст, автолейаут — как в Figma).
  Плюс один: пользователь двигал бы элементы руками. Минусов больше: свой рендерер на
  месяцы работы, никакой интерактивности, а модель рисует абсолютными координатами
  заметно хуже, чем вёрсткой, — дизайн выйдет беднее, чем сейчас.
- **Что теряется.** Простая страница без React — слайд тоже компонент. Свои `<script>` в
  `<head>` — всё через `import`. Это сознательно: оболочка одна на все фреймы.

### 2. Папка канваса

- `canvas.json` — вид канваса (`deck`, `mobile`, `web`) и упорядоченный список фреймов:
  `id` и название (у `mobile` — ещё цвет текста статус-бара). Порядок — порядок слайдов
  и экранов в потоке.
- `frames/<id>.jsx` — экран: `export default` компонента. Путь выводится из `id`, а не
  пишется в канвас: одно поле, в котором нельзя ошибиться.
- `components/*.jsx` — общие компоненты; модули импортируют друг друга относительными
  путями.
- `theme.css` — необязательно: `@theme` Tailwind (цвета, шрифты, радиусы) на весь канвас.
- `assets/` — картинки пользователя, как сейчас.

**Файл, а не набор новых инструментов** (`addFrame`, `removeFrame`…). Каждый инструмент —
восемь мест из таблицы `AGENTS.md`, а модель и так пишет файлы `writeFile`/`editFile`.
Проверка — в `present`; ошибка возвращается модели словами, что поправить. Если модель
станет путаться в файле, добавим один инструмент `canvas` — но не заранее.

- **«Переключиться на фрейм»** — это какой файл модель читает и правит. Канвас подсвечивает
  фрейм, который модель сейчас трогает: путь виден в событии хода.
- **Нет `canvas.json` — канвас из одного фрейма** `web` со страницей последнего `present`,
  показанной как в v1 (HTML и Babel). Так открываются все старые чаты, без миграции; в
  таком чате модель правит HTML, пока пользователь не попросит перевести страницу в
  компоненты.
- **`present` без `path`** показывает канвас целиком; с `id` фрейма — центрирует на нём.

### 3. Где фреймы лежат на канвасе — пользователя, не модели

Координаты, которые пользователь задал перетаскиванием, — в `layout.json` рядом с
`prototype.json`, вне рабочей папки: модель их не видит и, переписывая `canvas.json`
целиком, не затирает. По умолчанию фреймы встают в ряд по порядку (слайды) или сеткой
(экраны); новый фрейм — следом за последним. В версии раскладка не входит: это вид, а не
результат.

Отвергнуто: позиции в `canvas.json`. Тогда модель и пользователь пишут один файл, и
каждое перетаскивание ломает модели следующий `editFile` (`FileChangedSinceRead`).

### 4. Виды канваса и фреймов

| Вид | Размер фрейма | Рамка от приложения | Переходы |
|---|---|---|---|
| `deck` | 1920×1080, масштабируется | Номер слайда; под фреймом ◀ ▶ | Системные: следующий/предыдущий по порядку |
| `mobile` | 390×844 | Статус-бар (время, сеть, батарея) и индикатор Home поверх фрейма | `data-goto` |
| `web` | 1440×900, внутри прокрутка | Строка адреса с названием фрейма | `data-goto` |

- **Статус-бар рисует приложение, а не модель.** Он поверх фрейма, в рамке устройства;
  оболочка задаёт странице `--safe-top`/`--safe-bottom`, промпт говорит отступать на них.
  Так шапка экрана уходит под статус-бар цветом, как на настоящем телефоне, а модель не
  тратит токены и не ошибается в иконках батареи. Отвергнуто: статус-бар компонентом
  модели — каждый канвас рисует его по-своему.
- **Вид — у канваса, выбирает модель** по просьбе пользователя: «презентация» — `deck`,
  «дизайн мобильного приложения» — `mobile`, «сайт» — `web`. Мобильная и веб-версия рядом
  в одном канвасе — вне плана.

### 5. Канвас — React Flow, фреймы не ловят мышь, пока их не «открыли»

Под фреймами — сетка точками (`Background` React Flow); канвас двигается перетаскиванием
за пустое место и зумится колесом и щипком. Фрейм — узел React Flow: рамка устройства,
внутри `PrototypeFrame` в натуральном размере, масштаб — трансформация вьюпорта React
Flow. Переходы — рёбра. Мини-карта и `fitView` — из библиотеки.

- **Двойной клик по фрейму — вход в него.** Снаружи фрейм — картинка: за него тащат
  канвас, его выделяют. Внутри — живая страница: кликать, скроллить, указывать на элемент
  и оставлять комментарий (решение 9). Escape или клик мимо — выход. Так же ведёт себя
  Figma с вложенными прототипами.
- **Почему так, а не просто живые фреймы.** События из фрейма другого origin не
  всплывают в окно, поэтому классы `nopan`/`nowheel` React Flow тут ничего не дают: над
  живым фреймом канвас бы не двигался. Поэтому снаружи поверх фрейма — прозрачная крышка,
  а вход её снимает.
- **Почему React Flow, а не свой pan/zoom.** Свой — сотня строк для трансформации, но
  рёбра между фреймами, мини-карта, выделение и `fitView` — уже тысячи. Библиотека —
  зависимость приложения, не страниц модели; её CSS — базовый (`base.css`), цвета
  подставляются из `tokens.css` через `--xy-*`.
- **Живы только видимые фреймы** (`onlyRenderVisibleElements`); нужна ли при мелком зуме
  карточка вместо страницы — скажет проба CV-0.
- **Место — рядом с чатом, как сейчас**: в просмотрщике (440–1400 px), с той же кнопкой
  «Развернуть» на всё окно. Узкий просмотрщик канвасу не мешает — он зумится; при
  открытии `fitView` показывает все фреймы.

### 6. JSX переводит протокол (`oxc`)

Протокол отдаёт `.jsx` из папки чата уже JavaScript-модулем; браузер грузит модули и их
относительные импорты сам, Babel во фреймах нет.

- **Замер (2026-11-14, отдельный проект, macOS, release, strip).** `oxc` 0.158 с
  `transformer`, `codegen`, `semantic`: бинарник +2,6 МБ (0,34 → 2,98 МБ) — столько же,
  сколько Babel весит в установщике; холодная сборка ~34 с, дальше её держит общий
  target. Перевод экрана в шесть строк — ~14 мкс, поэтому кэша нет: модуль переводится
  при каждом запросе. По умолчанию JSX уходит в `react/jsx-runtime`, который уже в import
  map. Ошибка синтаксиса приходит со смещением в файле.
- **Что можно импортировать.** Относительные пути внутри папки; `react`, `lucide-react`
  и библиотеку выбранного стиля. Остальное — ошибка с перечнем того, что есть.
- **Ошибка перевода** отдаётся модулем, который бросает её текст — «`components/ui.jsx`:12:5
  Unexpected token», — и её ловит тот же сборщик ошибок под превью. Ошибка рендера —
  через `onUncaughtError` в `createRoot` оболочки, туда же.
- **`present` переводит все модули канваса** и возвращает модели все ошибки разом, до
  показа: синтаксис, импорт вне разрешённого, `frames/<id>.jsx` без `export default`.
- **Где живёт.** `infra/jsx_modules.rs`: это обёртка над сторонним парсером, не правило
  домена. Протокол и `present` вызывают её одинаково.
- Отвергнуто: **перевод в браузере** — оболочка переводит Babel'ем все модули, делает
  `blob:`-URL и вставляет import map до первого модуля. Работает без крейта, но Babel
  остаётся в каждом фрейме, каждый фрейм заново переводит все компоненты, а ошибки видны
  только в превью. Отвергнуто: **`swc`** — та же задача, крейты тяжелее.
- **`.tsx`** `oxc` переводит тем же вызовом; не включаем, пока не попросят.

### 7. Переходы — `data-goto` в JSX, рёбра — из дерева разбора

Элемент с `data-goto="<id фрейма>"` ведёт на этот фрейм. Скрипт панели (рядом с указкой
в `PANEL_SCRIPTS`) ловит клик и отправляет панели `goto`; панель проверяет `e.source`,
как сейчас.

- **Рёбра выводятся, а не хранятся.** Тот же разбор, что переводит модуль, собирает его
  `data-goto` со строковым значением и его импорты. Ребро фрейма — его собственные
  `data-goto` и `data-goto` компонентов, которые он импортирует (транзитивно): таб-бар в
  `components/` даёт рёбра каждому экрану, где он стоит. Один источник правды: модель
  меняет кнопку — ребро меняется само. Отвергнуто: список переходов в `canvas.json` — он
  расходится с кодом при первой же правке.
- **Переход на несуществующий фрейм** — ошибка `present` и предупреждение под канвасом.
- **Режим просмотра** (`▶` на панели — с первого фрейма, `▶` в заголовке фрейма — с
  него, на весь экран): один фрейм в рамке устройства по центру, клик по `data-goto`
  меняет фрейм, «Назад» — история, Escape — выход. Для `deck` — слайды на весь экран: ◀ ▶ под слайдом,
  стрелки и пробел; клавиши, нажатые внутри фрейма, его скрипт пересылает панели. У
  `deck` `data-goto` не действует — порядок задаёт канвас.
- Переход из кода (`go("cart")` после отправки формы) — вне плана: рёбра из него не
  вывести, а кнопка с `data-goto` закрывает почти все случаи прототипа.

### 8. Указка называет файл и строку

При переводе для превью элементам разметки (`div`, `button` — не компонентам)
дописывается `data-kibo-src="components/ui.jsx:12:5"`. Указанный элемент приходит
модели с этим местом, id фрейма и HTML, как браузер его нарисовал, — вместо нынешнего
«найди по тексту и классам». Указали внутри компонента — модель видит, что правка
коснётся всех фреймов с ним, и промпт велит сказать это пользователю. В экспорт атрибут
не попадает. Ошибки страницы приходят с названием фрейма. «Восстановить версию» и откат
к сообщению работают без изменений: снимок — вся папка.

### 9. Что пользователь делает на канвасе руками

Двигает канвас и фреймы, входит во фрейм, запускает фрейм на весь экран (решение 7) и
комментирует. Удалять, дублировать и переименовать фреймы — через модель: так канвас
пишет один автор, и модели не нужна строка «канвас изменён».

**Комментарий — указка с текстом.** Внутри фрейма указка выделяет элемент; клик
открывает рядом с ним поле, Enter ставит на элементе метку с номером и кладёт
комментарий вложением в поле ввода чата. Комментариев может быть несколько — на разных
элементах и фреймах; отправляются одним сообщением, каждый с фреймом, местом в коде
(решение 8) и HTML элемента. После отправки метки уходят: ответ модели — новая версия, а
не тред. Нынешнее «одно указанное вложение» становится списком, `pointNote` — заметкой
на каждый.

Отвергнуто: комментарии, которые живут на канвасе тредами, как в Figma. Это хранилище,
статусы и «решено» — ради того, на что здесь отвечает модель следующим ходом.

### 10. Как канвас открывается: режим и кнопка

- **Модель включает режим сама**, когда понимает, что нужен прототип, и сама выбирает вид
  канваса (решение 4) — механизм [35-loadable-modes.md](35-loadable-modes.md). Канвас от
  него не зависит: до 35 он работает в роли Prototype, после — в режиме, без изменений.
- **Кнопка под полем ввода остаётся** и открывает и закрывает панель, как сейчас. Её
  название — «Canvas» вместо «Preview»: панель теперь не одна страница.

### 11. Экспорт — один HTML без Babel

Модули модели встраиваются так же, как библиотеки сейчас: каждый — `data:`-URL в import
map под своим полным адресом, поэтому относительные импорты между ними работают без
переписывания.

- **Фрейм** — одна страница, как «Сохранить как…» сейчас, только легче: Babel не нужен.
- **Презентация** — одна страница со всеми слайдами-компонентами и тем же управлением,
  что в режиме просмотра.
- **Прототип `mobile`/`web`** — одна страница с плеером: фреймы — компоненты, переход по
  `data-goto` — смена показанного. Отвергнуто: zip папки — без приложения его нечем
  открыть.

## Слои

- `domain/prototype.rs` — `Canvas` (вид, фреймы), его проверка с ошибками для модели,
  правила импорта, рёбра по собранным `data-goto` и импортам, раскладка по умолчанию.
  Чистое, тестируется без диска и без парсера.
- `infra/jsx_modules.rs` — `oxc`: перевод модуля, его импорты и `data-goto`,
  `data-kibo-src`, ошибка со строкой и столбцом.
- `infra/prototype_store.rs` — чтение `canvas.json` и `layout.json`, запись раскладки.
- `infra/prototype_protocol.rs` — оболочка фрейма, `.jsx` как JS, модуль-ошибка;
  `PANEL_SCRIPTS`: `goto`, клавиши презентации, `--safe-*`.
- `services/ai_tools/tools/present.rs` — проверка канваса и всех модулей, `path`
  необязателен.
- `infra/prototype_export.rs` — модули в import map, плеер и презентация в одной странице.
- `commands/prototype.rs` — `prototype_canvas` (фреймы, рёбра, раскладка, ошибки),
  `prototype_layout_save`; оба `async` через `commands::blocking`. Нового канала событий
  нет: `chat:turn-event` уже говорит, что файл изменился.
- Фронт: `src/lib/prototype.ts` (обёртки), `usePrototypeCanvas` (свой хук, не в
  `App.tsx`), `PrototypeCanvas.tsx` + `.css`, `CanvasFrame.tsx` + `.css` (рамки устройств,
  крышка), `CanvasPlayer.tsx` (просмотр). Клавиши — в `shortcuts.ts`.
- Промпт роли — вместо шаблонов страниц: папка канваса, виды, правила импорта,
  `data-goto`, `--safe-*`, «общее — в компонент», один пример экрана из компонентов.
- `Cargo.toml` — `oxc` (`transformer`, `codegen`, `semantic`); `package.json` —
  `@xyflow/react`.

## Нарезка

Каждый этап — отдельный коммит с тестами и мутационной проверкой
([11-mutation-testing.md](11-mutation-testing.md)).

**CV-0. Проба — без кода приложения.** Цена `oxc` уже замерена (решение 6). В собранном
приложении на macOS: 12 фреймов из заранее переведённых модулей на React Flow — время до
отрисовки всех, память процесса WebKit, плавность пана и зума; чёткость фрейма при зуме
2× (WebKit может растрировать iframe под трансформацией размыто) и координаты указки при
масштабе; Tailwind v4 в браузере берёт `@theme` из `<style type="text/tailwindcss">`
под CSP превью; модули с `Origin: null` импортируют друг друга по относительным путям.
Ответ решает, нужна ли карточка вместо страницы при мелком зуме.

**CV-1. Канвас в домене.** `Canvas`, проверка, правила импорта, рёбра (транзитивно через
импорты), раскладка по умолчанию, канвас v1 из манифеста. Тесты: каждая ошибка проверки,
дубль id, id не годный для имени файла, импорт вне разрешённого, цикл импортов, ребро на
несуществующий фрейм, чат без `canvas.json`.

**CV-2. Модули.** `infra/jsx_modules.rs` на `oxc`: перевод, импорты, `data-goto`,
`data-kibo-src`, ошибка со строкой и столбцом. Тесты: JSX уходит в `react/jsx-runtime`,
`data-goto` только со строковым значением, атрибут источника у элементов разметки и не у
компонентов, позиция ошибки.

**CV-3. Протокол.** Оболочка фрейма для папки и для версии, `.jsx` как JS с правильным
MIME, модуль-ошибка, `PANEL_SCRIPTS` в оболочке. Тесты: оболочка импортирует фрейм по его
id, `..` и симлинк наружу — 404 и для `.jsx`, CSP оболочки тот же, что у страницы v1.

**CV-4. `present` и команды.** Проверка канваса и всех модулей в `present`, `path`
необязателен; `prototype_canvas`, `prototype_layout_save`, обёртки. Тесты: `present`
отказывает со всеми ошибками разом, раскладка не попадает в версию, чат v1 показывается
как раньше.

**CV-5. Канвас в панели.** React Flow, сетка, пан перетаскиванием, вход во фрейм
двойным кликом и выход, рамки трёх видов, статус-бар, перетаскивание фреймов с
сохранением, подсветка фрейма в работе, перезагрузка фреймов, которые импортируют
изменённый модуль, кнопка «Canvas». Тесты `bun test`: хук канваса, вход и выход.

**CV-6. Переходы и просмотр.** `goto` в `PANEL_SCRIPTS`, рёбра, плеер для `mobile`/`web`
на весь экран — с первого фрейма или с выбранного.

**CV-7. Презентация.** Слайды, системные ◀ ▶, полный экран с выбранного слайда, клавиши
из фрейма.

**CV-8. Указка и комментарии.** Место элемента в сообщении модели, пометка «элемент
внутри общего компонента», комментарии метками и списком вложений. Тесты: заметка на
каждый комментарий, метки уходят после отправки.

**CV-9. Промпт.** Раздел о канвасе вместо шаблонов страниц; проверка руками на двух моделях
(бенча прототипов нет): «презентация на 6 слайдов», «мобильное приложение доставки из 4
экранов с переходами», «лендинг», и продолжение чата v1.

**CV-10. Экспорт.** Фрейм, презентация и прототип с плеером — одной страницей без Babel.

**CV-11. Документы.** `docs/README.md`, `CHANGELOG.md`, строка в
[31-prototype-role.md](31-prototype-role.md) о том, что превью заменено канвасом, строка в
[37-prototype-styles.md](37-prototype-styles.md) — стиль подключается импортом.

## Вне плана

- Правка элементов руками (двигать кнопку, менять текст на канвасе) — это сцена из
  решения 1, отвергнутая; вернёмся, если просьбы «поправить руками» станут частыми, и
  тогда скорее через «указал → модель поправила», чем через свой редактор.
- Переход из кода (`go()`), `.tsx`, общее состояние между фреймами в режиме просмотра.
- PDF/PPTX презентации, анимации переходов между экранами, варианты компонентов как в Figma.
- Несколько канвасов (страниц) в одном чате.
